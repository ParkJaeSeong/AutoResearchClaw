# Pilot 통합 개발 목록과 순서

2026-09-18. 상태: 개발 범위·의존성 정리. 코드 실행용 세부 계획이나 모든 정책의 승인 완료를 뜻하지 않는다. 각 묶음 착수 시 해당 설계에 맞춘 파일·테스트 단위 구현 계획을 작성한다. 기존 코드·운영·실제 연구 상태는 이번 문서 작성으로 변경하지 않는다.

## 목표와 기준

Pilot은 도메인 전문가를 조정해 근거를 검토하고 현재 승인된 마일스톤의 다음 행동과 이유를 기록한다. 자료 탐색·확보는 Pilot, 이미지 해석을 포함한 변환은 Documents, 자료 관계·지식 분석·보관은 Atlas, 최종 문서 구성·표현은 Presentation이 담당한다. 실행 계층·장비 제어는 별도이며 이번 개발에 포함하지 않는다.

## 보존·재사용 범위

기존 .atlas-link/.document-handoff 원장, import 수신·개별 검토, 프로젝트/작업 기록, UI를 재사용한다. 기존 자료와 연구 판단은 삭제·이동·재생성하지 않는다. 현재 구현 여부는 각 작업 착수 시 확인하고 중복 모듈을 만들지 않는다. 기존 모델 실행부의 codex-cli-default-unverified 기록은 확인되지 않은 실제 모델을 의미하며 구성 가능한 모델 표준 완료로 보지 않는다.

## A. 공통 요청·결과 수신 — Pilot, 최우선

- [ ] A1 기존 ask 연결: job-71f93df47d324b48을 재제출하지 않고 관찰→QA 원형 검증→수신 대기함으로 연결. 유효 QA 없음/partial/실패 진단을 구분한다.
- [ ] A2 요청 원장: 프로젝트·마일스톤·단계 종류·작업·시도·질문 revision·요청 역할·회차·반환 작업·정책·공개 범위를 고정. 실제 외부 payload/hash도 별도 보존한다.
- [ ] A3 서비스 어댑터: A1 허용 context 5개 키와 import 자체 schema만 전송. service별 key/receipt/fingerprint/auth/instance를 검증한다. 새 API를 가정하지 않는다.
- [ ] A4 수신 복구: consumer별 이벤트 중앙 저장 후 프로젝트 분배, cursor/ACK 복구, ask polling, dispatch/interrupted/고아 상태 표시. 송수신 유실로 새 실행을 만들지 않는다.
- [ ] A5 원형 보존: QA/page/source의 버전·해시·읽은 범위 검증. page409/잘린 chunk/그림 부재를 최신본이나 확인했다는 문장으로 대체하지 않는다.

완료 기준: 기존 계약만으로 요청→불변 결과→정확한 프로젝트 대기함까지 복구 가능. Atlas B1~B3 해당 실패 시험 통과. 외부 호출이 필요한 검증 전에는 저장 응답·격리 fixture로 확인한다.

## B. 작업 반환·전문가 검토·자율 진행 — Pilot

- [ ] B1 역할 반환: PID 대신 work/role/round/input revision으로 재개. 실제 입력 제공 기록과 수신 확인을 구분. 없어진 역할은 조정자 재배정 기록 필요.
- [ ] B2 독립 검토: 고정 공통 입력→독립 의견→상호 검토→조정 판단. 독립 회차에는 공유 ask/위키를 통한 비공개 의견 노출을 막는다. 새 근거는 새 revision으로 편입한다.
- [ ] B3 다음 작업: 개별 문서 검토→Atlas 통합 질의→종합 토론→가설·계획 수정. 부족 원인에 따라 기존 자료 전달/추가 질의/변환 보완/외부 탐색으로 되돌린다. 본문·보충자료를 독립 연구 두 건으로 세지 않는다.
- [ ] B4 실행 경계: 로컬 중지와 원격 취소를 분리. 공개 A1 취소 미지원, import 취소는 Documents 취소 아님. 작업 완료 직전 revision/generation을 대조해 늦은 채택을 막는다.
- [ ] B5 마일스톤 종료: 필수 근거·검토·채택 기준으로 완료. 불필요한 대기는 이유를 남겨 제외. 사용자 정지는 신규 실행 전체를 막고 개별 자원 제약은 해당 작업만 대기. 종료 후 늦은 결과는 보존하되 다음 마일스톤을 실행하지 않는다.

완료 기준: A 결과를 원래 역할에 전달하고 승인 범위의 후속 작업을 자동 진행. 동일 결과 중복 채택 없음. Atlas B4/B5·dependency·M1 경계 시험 통과. 고정 토론 횟수·임의 시간 제한을 완료 기준으로 삼지 않는다.

## C. 모델·추론 실행 설정 — Pilot, SSO 기준 적용

- [ ] C1 프로필 사본: 실행 방식(CLI/API), 실행 위치, 모델 연결, 인증 참조, 옵션, 버전, 기능 테스트 결과를 Pilot에 보관. 공통 관리 화면이 꺼져도 앱 사본으로 동작. 비밀 값은 프로필/로그와 분리.
- [ ] C2 작업 배정: 앱 기본과 기능별 선택을 구현. 개별 작업 지정은 Pilot 확장 제안으로 정책 확정 후 적용. 페르소나와 모델을 분리한다.
- [ ] C3 지원 옵션: 프로필별 지원되는 추론 옵션·출력량·도구/이미지 기능을 검증. 추론 강도와 답변 분량 구분. 제공자 간 추론 수준이 같다고 가정하지 않는다.
- [ ] C4 실행 고정: 시작 시 설정 snapshot 저장, 요청값/실제 확인값/미확인 구분. CLI 전역 설정을 덮어쓰지 않는다. 변경은 다음 작업부터 적용.
- [ ] C5 실패·삭제: 실패 시 다른 모델 자동 전환 금지. 사용 중 프로필 삭제 영향 표시, 과거 이력 보존, 다음 작업의 삭제 프로필 사용 금지. 미지원 옵션을 조용히 무시하지 않는다.

완료 기준: 서로 다른 두 작업에 서로 다른 지원 설정을 적용하고 기록으로 확인. 실행 중 프로필 변경·삭제·자격 증명 오류·미지원 옵션 시험. 실제 선택할 모델 목록과 자동 선택 권한은 사용자 정책 결정 필요. 모든 제공자 어댑터를 한 번에 구현하지 않는다.

## D. 단계별 산출물 표준 — Pilot, Presentation 소비자 검토 필요

- [ ] D1 공통 schema: schema_version, 프로젝트/마일스톤/단계/작업/수행 순서, 입력 refs, 목적, 요약, 주장·근거·조건·한계, 검토/채택 상태, 다음 작업, 실행 설정 refs를 정의.
- [ ] D2 단계 확장: 탐색(검색/선정/확보), 분석(일치/충돌/공백), 가설(경쟁 설명/반증), 설계(변수/측정/분석/제약)를 유형별 추가. 탐색 초안에 최종 설계 항목을 강제하지 않는다.
- [ ] D3 저장·표시: 버전 있는 JSON 기준 기록에서 Markdown 생성. 단계 종류와 수행 순서 분리, 재수행은 새 버전/작업 기록. 변경 이유·이전 버전·원자료/대화 참조 보존.
- [ ] D4 검수: 초안/검토/채택을 분리. 출처 내용·Atlas 해석·Pilot 가설·실측·합성·가상 구분. 중요한 채택에 필요한 근거만 차단 조건으로 삼고 비핵심 메타데이터 누락은 경고.

완료 기준: 서로 다른 세 단계 산출물을 동일 renderer로 읽고 과거 버전을 재현. 보고서용 주장에서 출처 위치까지 추적 가능. 기존 기록은 원형 유지, 변환본임을 표시하고 미확인 메타데이터를 발명하지 않는다.

## E. Atlas 질의 후 위키 반영 — 공동 계약 후 Atlas/Pilot 분담

- [ ] E1 계약: readonly ask 유지, 명시 복합 operation/capability·쓰기 권한·정규화 요청·단계 결과·원형 회수/보관을 합의. 명칭은 미확정.
- [ ] E2 Atlas: 이번 QA 후보만 처리, QA→update 영속 연결, 답변 입력 페이지 원형 고정·회수, 쓰기 직전 hash 비교, 후보별 부분 성공·변경 이력·색인 상태·실패 단계 재개.
- [ ] E3 Pilot: 한 요청의 answer/knowledge 복수 결과 수신. 전달키에 단계·결과 hash/revision·대상 입력 포함. 반영 결과만으로 과학 토론 재생성 금지.
- [ ] E4 공동 검증: 답변 후 페이지 변경409, 중간 종료, partial, 위키/색인 실패, 중복 요청, 비공개 가설 노출 방지. 현재 import 이벤트로 가장하지 않고 초기 job polling 사용.

완료 기준: 답변과 근거를 보존한 채 해당 QA 지식만 갱신하고 실패 부분만 복구. capability 없는 서버에서는 비활성. 기존 A/B 개발의 선행 조건이 아니다. 지식 자동 반영 정책 3개 결정 필요.

## F. Presentation 보고서 전달 — 계약 공동 검토 후 구현

- [ ] F1 소비자 계약: 목적(논문/보고서/계획서), 독자, 선택 마일스톤/버전, 서식, 주장·근거·표/그림 refs, 사용권/제한 중 확인된 정보를 정의. Presentation의 현재 API/MCP 존재를 가정하지 않는다.
- [ ] F2 고정 패키지: 채택 산출물과 명시한 미확인/한계를 manifest+hash+읽기용 요약으로 내보낸다. 보고서에 필요한 파일을 제공하고 개발자 로컬 경로만 전달하지 않는다. 비밀·비공개 대화는 기본 제외.
- [ ] F3 반환: 보고서와 사용한 패키지 버전을 연결. 내용 공백/근거 부족은 Pilot 보완 요청으로 반환. Presentation이 가설을 사실로 승격하거나 채택 판단을 변경하지 않는다.

완료 기준: 동일 패키지로 보고서를 만들고 주요 주장→Pilot 산출물→근거 추적 가능. 내용 개정 시 새 패키지로 구분. 파일 인계부터 검증하고 실제 지원 인터페이스 확인 후 자동화한다.

## G. UI — 기존 화면 안에서 점진 적용

- [ ] G1 요청 흐름: 요청자·질문→외부 처리→수신→담당 검토→다음 작업 표시. 원격 취소와 후속 실행 중지 구분.
- [ ] G2 설정: 앱 기본/기능별/개별 지정 출처, 실행 시 모델·추론, 최근 연결 테스트와 미확인 표시.
- [ ] G3 산출물: 요약·결론 우선, 근거/대화/도구/버전은 펼침. 단계와 수행 순서, 되돌아간 이유를 표시.
- [ ] G4 위키·보고서: 답변/위키 저장/색인/연구 완료 분리. 보고서에 전달할 버전·범위와 생성 결과 표시.

완료 기준: 기존 프로젝트 선택·입력 상태 보존, 전체 폭·메뉴 접힘·모바일 넘침·밝고 어두운 모드 검수. docs/ui 기준 준수. 새 상위 탭과 박스를 무작정 늘리지 않는다.

## 권장 의존 순서와 검증 지점

1. A + 최소 G1: 기존 답변 수신 연결. 기존 job 재접수 없음.
2. C와 D의 최소 schema/정책 확정: 모델 설정·산출물 규격을 B 실행 기록에 연결.
3. B + G2/G3: 단일 자료→통합 질의→토론→다음 작업을 격리 입력으로 검증한 뒤 실제 연구에 적용.
4. E: 정책·공동 계약 확정 후 Atlas 구현과 Pilot 단계 결과 수신을 연결. A/B와 별도 진행 가능.
5. F + G4: Presentation 소비자 계약과 마일스톤 결과 패키지 확인.
6. 종단 검증: 중단·재시작·partial·모델 설정 변경·근거 부족 재탐색·M1 종료·보고서 추적성을 확인. 테스트 성공은 실제 M1 완료를 뜻하지 않는다.
