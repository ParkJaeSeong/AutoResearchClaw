# M1 실행 현황

M1 전체 완료 전이다. 현재 A 묶음(01~04)을 개발·검증 중이다.

| 작업 | 상태 | 확인할 결과 |
|---|---|---|
| 01 기준선·정책 | 검사 진행 중 | 기존 주요 검사 166개 통과, 전체 검사의 실패 원인 확인 중 |
| 02 결정 과정 UI | 완료 · 독립 검토 통과 | 아래 로컬 시안에서 가설 수정·대안 보류·근거 탐색 |
| 03 실제 호스트 연결 | 실행 확인·원문 보존 | 세 역할의 최초 제출 및 동일 문맥 후속 응답 |
| 04 그래프·역할 계약 | 구현·검사 중 | 열 개 작업의 페르소나·권한·복귀 경로 |
| 05~20 | 미착수 | 자료 저장, 협의 엔진, 반복, 실제 UI 연결, 인계·통합 검증 |

[최신 로컬 UI 시안](http://127.0.0.1:51633/researchclaw/codex/m1_ui/) — 로컬 서버가 실행 중일 때 열린다. 화면 대화는 명시적으로 표시된 예시다.

[실제 세 에이전트 검증 기록](2026-09-08-m1-host-verification.md) — 합성 자료를 사용한 실제 호스트 통신 결과. UI 시안 대화와 별개이며 M1 완료나 실제 연구 결과가 아니다.

개발 위치: `.worktrees/m1-research-graph`, 브랜치 `feature/m1-research-graph`. 원래 main의 기존 프로젝트는 수정하지 않는다.

지금 사용자가 확인할 핵심: H1 수정 결정에서 처음 주장·쟁점·응답·수정안을 추적할 수 있는가? H2 보류 이유가 구분되는가? 실제 세 역할의 발언이 기대한 검토 방식인가?
