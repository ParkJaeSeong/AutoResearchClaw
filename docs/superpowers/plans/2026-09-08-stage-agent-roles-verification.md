## 구현한 범위

1~15단계의 역할·책임·질문·판단 기준·권한 제한을 조회한다.

```sh
researchclaw-codex roles describe --stage 7 --json
```

프로젝트 경로가 필요하지 않으며 프로젝트를 열거나 상태·승인·증거를 변경하지 않는다. 반환은 `schema_version: 1`, `protocol_version: 1`, `activation: guidance_only`다. 0·16·23·음수·비숫자 등 미지원 입력은 stderr와 exit2로 거부한다.

54개 논리적 역할에 108개의 단계별 질문을 제공한다. 역할 수는 동시 실행 수가 아니다. 조회 자체는 에이전트를 실행하지 않는다.

- 판단 단계: 분야, 방법론, 비판·재현성, 비투표 조정자.
- 수집·추출·자원·실행 지원 단계: 작업자와 독립 확인자.
- 10·13단계: 구현 담당을 추가하고 평가·승인과 분리.

## 리뷰로 보완한 내용

첫 리뷰에서 단계 번호만 바꾼 공통 질문과, 다른 역할의 단어로 통과할 수 있던 합산 검사를 발견했다. 모든 역할의 질문을 단계별로 보완하고 역할별 검사를 추가했다. 보완 전 해당 검사는 22 failed/101 passed, 보완 후 123 passed였다. 재검토에서 두 지적 모두 해소됐으며 최종 리뷰에도 미해결 지적은 없다.

CLI 도입 전에는 정상 사용 사례17개가 실패했고, 연결 후 전체 관련 검사290개가 통과했다. 누락된 참고 문서·링크도 먼저 실패를 확인한 뒤 추가했다.

## 검증 방식에 대한 결정

**Ruling:** 계획의 문서 문구 일치 검사는 실제 에이전트의 참고 문서 조회·해석 확인으로 대체했다. 문구 존재만으로 지침 사용을 입증할 수 없기 때문이다. 파일 링크와 설치 데이터 포함 여부는 기능 검사로 유지했다.

새 지침을 읽기 전 독립 에이전트는 프로젝트 없는 역할 질문 조회 명령을 찾지 못했다. 수정 후 별도의 에이전트는 조회 명령을 찾고, 안내와 실제 검토 완료를 구분하며 10단계 자기 승인 금지 및 13·14·15단계의 서로 다른 협의 규칙을 설명했다.

이는 한정된 참고 문서 사용 확인이다. 모든 상황에서의 준수나 연구 품질을 증명하지 않으며, 놓친 모호성이 있으면 추가 지침 검증·수정이 필요하다. 질문 키워드 검사 역시 내용 품질 평가를 대체하지 않는다.

## 변경하지 않은 것과 다음 단위

기존 TaskPacket·ProjectState·등록·승인·복구·불변 증거 형식은 변경하지 않았다. 13단계 최소2개 일치 권고, 14단계 분석 종합, 15단계 세 최종 권고 일치 규칙을 유지했다. 외부 LLM API·키·제공자 설정·별도 모델 프로세스를 추가하지 않았다.

A는 역할 안내의 기반이다. 실제7~9단계 협의 제출·공개·응답·종합과 진행 조건 연결은 다음 B 단위이며, 독립 상세 설계가 필요하다. 기존 프로젝트 재실험·강제 이전·16단계는 구현하지 않았다.

이 기록 시점에 main 병합·GitHub 푸시·실사용 설치 갱신은 하지 않았다. 개발 브랜치와 임시 설치 환경은 보존했다.
