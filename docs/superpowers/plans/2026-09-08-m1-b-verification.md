# M1 B — 실행·검증 기록

## Task05 — 신규 프로젝트와 불변 저장

상태: **Task05 완료 · 독립 검토 승인**. 구현 `fe23532`, 검토 보완 `0486946`, 보고서 `45afdf9`. 최종 코드의 별도 프로세스 수용 확인도 통과했다.

사용자가 확인할 결과는 신규 M1 프로젝트를 생성하고 다른 프로세스로 다시 조회해도 동일한 상태가 나오는 것이다. 자료나 결정의 새 버전을 저장해도 이전 버전은 보존되어야 한다.

| 확인 항목 | 기대 동작 | 결과 |
|---|---|---|
| 신규 초기화·다시 열기 | 최초 설정과 같은 HEAD를 읽음 | 별도 CLI 프로세스 확인 통과 |
| 조회 무변경 | 조회 전후 파일 내용·수정 시간이 같음 | 내용·mtime·mode 대조 통과 |
| 기존 프로젝트 분리 | 기존 state.json을 보존하고 M1 초기화 거부 | 공개 CLI에서 양방향 충돌 거부·원본 보존 통과 |
| 명령 재시도 | 같은 명령·같은 내용은 원래 결과, 다른 내용은 충돌 | 원래 HEAD 재시도 수용 확인·내용 충돌 단위 검사 통과 |
| 동시 수정 | 같은 이전 HEAD를 바꾸려는 다른 쓰기는 하나만 성공 | 별도 프로세스 동시 쓰기·동시 초기화 검사 통과 |
| 저장 중 중단 | HEAD는 완전한 이전 또는 새 커밋만 가리킴 | 파일시스템 오류 주입·동기화 실패 재시도 검사 통과 |
| 손상·경로 문제 | 손상된 기록을 복구·정상화하지 않고 오류 표시 | 손상된 HEAD·이력·객체, 심볼릭 링크 거부 검사 통과 |

이 단계는 저장 기반이다. 에이전트 협의, 문헌 승인, 작업 패킷 등록, 실제 기록 UI 연결은 후속 작업이며 여기서 완료로 표시하지 않는다. 실행 확인용 자료는 합성 자료로 구분한다.

기존 전체 회귀 기준선은 Task01에서 SSL 대기로 중단되었다. 이 작업에서는 영향받는 기존 프로젝트·상태·CLI 검사와 신규 저장 검사를 실행하며 전체 회귀 완료와 구분한다.

### 직접 확인하는 명령

개발 작업 공간 `.worktrees/m1-research-graph`에서 **새 경로**를 대상으로 실행한다.

```sh
.venv/bin/researchclaw-codex m1 init ./m1-storage-demo --topic "M1 저장 검사용 합성 프로젝트" --content-origin synthetic --max-returns 2 --json
.venv/bin/researchclaw-codex m1 status ./m1-storage-demo --json
```

`status`는 조회만 수행한다. `m1 resume`이나 노드 등록은 Task06의 범위이며 현재 이 확인 절차에 포함하지 않는다.

별도 프로세스 확인에서는 자료 한 개와 합성 이벤트를 추가한 뒤 명령을 재시도했다. 새 HEAD가 만들어지고, 같은 명령의 재시도 결과가 일치하며, 이전 커밋의 파일 내용과 수정 시간이 보존됨을 확인했다. 이는 저장 API의 확인이며 실제 에이전트 협의 기록이 아니다.

### 검사 결과와 한계

- 최종 신규 검사: `test_store.py`, `test_project.py`, `test_m1_cli.py` — **66 passed**, 0 failed/skipped, 0.74초.
- 기존 회귀: 기존 `test_project.py`, `test_state.py`, `test_cli.py` — **155 passed**. 당시 신규 60개를 포함한 실행은 215 passed/87.17초였다. 이후 M1 동기화 재시도 수정은 신규 검사로 다시 확인했다.
- 최종 수용 확인: 다른 CLI 프로세스의 재조회, 조회 전후 내용·mtime·mode, 객체·이벤트 추가, 옛 HEAD를 사용한 동일 명령 재시도, 이전 커밋 보존, 신규/기존 프로젝트 충돌 거부 양방향 모두 통과.
- 컴파일·공백 오류 검사는 통과했다. Ruff는 설치되어 있지 않아 실행하지 못했다.
- 실제 전원 차단을 실험한 것은 아니다. 파일시스템 오류 주입과 프로세스 동시 실행을 검사했다. 실패 뒤 남는 미발행 파일의 정리, 대규모 이력 성능 최적화, 악의적인 파일 소유자에 대한 완전한 방어는 이번 범위에 포함하지 않는다.

### 독립 검토 보완

초기화의 마지막 디렉터리 동기화가 실패한 뒤 새 명령이 성공을 반환할 수 있는 문제를 독립 검토에서 재현했다. 새 커밋도 저장소의 상위 디렉터리 동기화를 확인한 뒤 성공하도록 수정했다. 실패 지속·동일 명령 재시도·오류 해소 후 성공·더 최신 HEAD 보존을 검사했고, 재검토에서 명세와 품질 모두 승인되었다.

최종 별도 프로세스 확인용 프로젝트는 합성 자료다. 이전 커밋과 새 커밋이 모두 보존되었고, 오류나 성공을 실제 연구 승인으로 사용하지 않았다. 이 단계에서 M1 전체 실행이나 UI 실제 기록 연결을 완료했다고 주장하지 않는다.
