# M1 C — 가설과 실제 협의 검증

사용자 요청에 따라 Task09~12를 순서대로 개발·검토한다. 발언은 실제 배정된 호스트 에이전트에게 받고, 입력 자료는 합성 검사 자료로 표시한다. 앞 단계 협의는 test checkpoint에서 시작하므로 전체 M1 연구 수행으로 보고하지 않는다.

| 작업 | 확인할 결과 | 상태 |
|---|---|---|
| 09 가설 모델 | 근거·반증 조건·수정 이유·작성자와 버전 | 완료 · 독립 검토 승인 |
| 10 최초 제출 | 세 역할의 같은 입력, 전체 제출 뒤 공개 | 완료 · 독립 검토 승인 |
| 11 응답·최종 입장 | 쟁점별 응답과 의견 변화, 미해소 반대 | 완료 · 독립 검토 승인 |
| 12 결정 | 최종 입장과 일치하는 선택·수정·유보 이유 | 완료 · 독립 검토 승인 |

검증 사례는 전체 집계 개선과 조건 간 집단 구성 차이를 가정한다. 하위 집단별 효과·표본 수·불확실성이 없다는 한계를 유지한다. 조정자는 초안을 작성할 수 있지만 세 역할의 지적·응답·최종 입장을 대신 작성하지 않는다.

## Task09 가설 기록

구현 `93a5f03`, 명세·품질 독립 검토 승인. 가설 하나와 정성적 예측을 허용하며, 불명 근거·반증 조건 누락·변경 이유 없는 개정은 거부한다. 가설 JSON은 이전 버전을 그대로 포함하고 새 revision을 추가한다. 작성자 ID는 선언이며 실제 독립 실행 인증과 구분한다.

검사: `.venv/bin/python -m pytest tests/codex_native/m1 tests/codex_native/test_hypothesis_generation.py -q` — **245 passed**, 12.50초, 신규 41개 포함. 초기 실패 34개·통과 1개를 확인했고, 최종 컴파일·공백 검사도 통과했다. 전체 기존 회귀 검사는 아니다.

조정자의 별도 수용 확인: 최종 코드에서 단일 정성 가설·공백 0개를 공개 prepare/register로 등록하고 검토 대기 및 동일 명령 재시도를 확인했다. 실제 호스트 검증용 합성 H1r1도 등록했으며, 아직 세 역할의 연구 심사를 받은 상태는 아니다.

## Task10 독립 최초 제출

구현 `e513bfc`, 명세·품질 독립 검토 승인. 공개 가설 등록 뒤 별도 review 회차를 만들고 세 판단 역할의 초기 의견을 모은다. 필수 세 제출 전에는 다른 역할의 초기 원문을 공개하지 않는다. 실패 역할의 교체도 기존 제출과 실패 이유를 보존한다.

검사: `.venv/bin/python -m pytest tests/codex_native/m1 tests/codex_native/test_task_packets.py tests/codex_native/test_deliberation.py -q` — **325 passed**, 36.53초, 실패·건너뜀 없음. 초기 기능 부재와 CLI/재개/중첩 응답의 비공개 원문 노출을 실패 검사로 확인한 뒤 보완했다. 컴파일·공백 검사 통과.

실제 호스트 역할 세 개의 최초 의견을 새 엔진에 등록했다. 첫 두 제출 뒤 세 번째 역할 패킷은 여전히 비공개였고, 마지막 제출 뒤 세 역할 모두 같은 전체 스냅샷을 받는 것을 확인했다. 각 역할은 집계→하위 집단 일반화와 판정 기준의 문제를 각각 제기했다. 원문은 [실제 등록 발언 기록](../acceptance/m1-live-ui-2026-09-09/transcript.json)에 보존한다.

자료는 합성이며 에이전트 발언은 실제 호스트 반환값이다. 엔진의 배정 출처는 declared_only이고, 실제 호스트 호출 관측은 별도 기록한다. 도구 반환 task ID만 관측했으며 실행 서명·신원 인증을 제공받은 것은 아니다.

## Task11 쟁점·응답·최종 입장

구현 `fee0fcb`, 입력 검증 보완 `82fd0ca`, 독립 검토 승인. 세 역할이 한 차례씩 응답한 뒤 최종 입장을 등록한다. 모든 쟁점에 대한 처리 이유와 연결 응답을 남기며, 최초 쟁점은 제기자의 확인이 있어야 해소되고 응답 중 새 쟁점은 다른 역할의 확인도 필요하다. 기존 배정·초기 원문은 바꾸지 않는다.

검사: `.venv/bin/python -m pytest tests/codex_native/m1 tests/codex_native/test_task_packets.py tests/codex_native/test_deliberation.py -q` — **348 passed**, 63.41초. 최종 쟁점·협의 집중 검사는 60 passed였다. 초기 기능 부재 14개 실패·37개 통과와 추가 잘못된 입력 실패를 확인한 뒤 보완했다. 컴파일·공백 검사 통과.

실제 세 역할의 응답과 최종 입장을 등록했다. 모두 revise를 권고했다. M1의 질문 명료화와 M2 상세 설계의 요구를 구분하는 데 의견이 모였지만, 동결된 H1 수정이나 새로운 자료가 없으므로 차단 문제를 해소했다고 판단하지 않았다. 원문과 변화 이유는 위 실제 등록 발언 기록에 추가했다. 최종 코드의 별도 CLI 재시도는 원래 결과를 반환하면서 최신 HEAD를 보존했다.

독립 검토에서 새 쟁점 배열의 비객체 원소가 안정된 검증 오류 대신 AttributeError를 내는 문제를 발견했다. null·문자열·배열과 공개 CLI 실패 검사 4개를 먼저 확인하고 수정했다. 영향 범위 재검사 **17 passed, 10 deselected**, HEAD 보존과 CLI exit 2를 확인했으며 재검토에서 남은 지적은 없다.

## Task12 실제 결정 등록

실제 세 역할의 동결된 최종 입장과 여섯 미해소 쟁점을 그대로 연결해 `decision-live-r1`을 공개 API에 등록했다. ready=false, 다음 행동은 return, 목적지는 hypothesize다. 선택 가설 없음·차단 쟁점·역할 반대가 이유 코드로 남는다. 가설이나 역할 의견을 바꾸어 인계 가능 결과를 만들지 않았다. 구현 `6172229`, 재시도 비교 보완 `30413b3`의 독립 검토 승인을 받았다. 최종 코드의 별도 CLI 재시도는 원래 영수증과 동일했고 HEAD도 보존했다.

Task12 검사: `.venv/bin/python -m pytest tests/codex_native/m1 tests/codex_native/test_task_packets.py tests/codex_native/test_deliberation.py tests/codex_native/test_research_decision.py -q` — **469 passed**, 254.16초, 실패·건너뜀 없음. 결정 신규 43개와 UI 서버 독립 부분 7개를 포함한다. 초기 기능 부재 검사 41개 실패 후 집중 41개 통과, 추가 경계 검사 2개를 최종 묶음에서 확인했다. 컴파일·공백 검사 통과. 전체 기존 회귀 검사는 아니다.

재검토 보완: JSON 숫자와 불리언을 같은 재시도 입력으로 취급하던 공통 비교를 정규 JSON 바이트 비교로 바꿨다. 실패 검사 3개 후 관련 재시도 **13 passed, 149 deselected**. 최종 코드에서 실제 결정 CLI 재시도도 같은 영수증과 HEAD 보존을 확인했다.
