# M1 D — 복귀와 실제 기록 UI

사용자가 승인한 Task16 UI 연결까지 진행 중이다. 이 문서에는 완료한 검사와 아직 확인하지 않은 항목을 구분해 기록한다. 전체 M1 통합·설계 인계는 Task17 이후다.

| 작업 | 상태 | 확인할 결과 |
|---|---|---|
| 13 복귀 계획 | 완료 · 독립 검토 승인 | 복귀 대상·이유·재사용·재검토·승인 영향 |
| 14 새 회차 | 구현·검증 중 | 이전 가설 보존, 새 개정·예산·재시도 |
| 15 기록 조회 | 대기 | 현재·과거 HEAD에서 공개된 등록 기록만 조회 |
| 16 UI 연결 | 독립 부분 구현 중 | 실제 결정·발언·근거·가설 비교와 자동 갱신 |

UI와 로컬 서버의 독립 부분을 먼저 준비했다. 변경된 HEAD에서만 화면을 갱신하고 선택한 노드·결정을 유지한다. 연결이 끊기면 마지막 기록과 갱신 시각을 표시한다. 실제 조회 형식 연결과 브라우저 수용 검사는 아직 남아 있다.

부분 검사: Node 14개 통과(기존 8개, polling 4개, 선택 유지 2개), HTTP 서버 7개 통과. HTTP 검사는 후속 build_view를 임시 대체한 독립 검사이므로 실제 기록 UI 연결 완료를 뜻하지 않는다. 전체 기존 회귀 검사도 아니다.

실제 협의 사례는 합성 자료를 입력으로 한 세 호스트 역할의 발언이다. 조정자가 대신 작성한 대화가 아니지만 엔진의 배정 출처는 declared_only다. 실제 호스트 호출 관측과 엔진 등록 검증을 구분한다. 최초 의견·응답·최종 판단·복귀 결정은 [등록 발언 기록](../acceptance/m1-live-ui-2026-09-09/transcript.json)에 보존한다.

## Task13 실제 복귀 계획

`decision-live-r1`과 실제 여섯 쟁점으로 hypothesize 복귀 계획을 계산했다. 이전 가설 작성·검토 회차 2개가 영향 범위이며 수집·추출·종합을 포함한 앞선 회차 7개는 재사용 가능하다. 앞선 일부 회차는 명시된 합성 test checkpoint다. 자료 집합을 바꾸지 않으므로 문헌 승인과 바인딩을 유지한다. 계획 계산 전후 전체 프로젝트 파일 바이트·mtime·mode가 동일했다. 아직 복귀 적용이나 가설 개정을 수행한 것은 아니다.

Task13 구현 `33b06f6`, 범위 판정 보완 `8433dde`·`d5d7a78`, 독립 검토 승인. 초기 31개 실패 후 31개 통과, 복귀·M1 CLI·패킷 CLI·문헌 승인 관련 검사 **59 passed**, 19.56초. 최종 보완 관련 검사는 **11 passed, 28 deselected**, 5.41초. 범위가 명확한 가설 문구 수정은 허용하고, 내용 없는 시작·전체 워크플로 초기화는 거부한다. 별도 CLI도 같은 계획을 반환했고 보완 코드에서도 실제 계획이 동일했다. 컴파일·공백 검사 통과.
