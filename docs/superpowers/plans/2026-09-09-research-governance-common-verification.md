# 공통 기반 A06–A09 검증 기록

상태: 완료 · 공통 기반 A01–A09의 개별 작업 구현·독립 검토 완료. 사용자 우선순위에 따라 UI보다 공통 기반을 먼저 완성한다.

| 작업 | 확인할 동작 | 상태 |
|---|---|---|
| A06 | 입장 변경 사유·정확한 근거·작성자의 요약 확인 | 완료 · 093fe68 · 9개 검사 · 독립 검토 통과 |
| A07 | 마일스톤별 차단과 미해결 질문 인계 | 완료 · 0d1be24 · 35개 검사 · 독립 검토 통과 |
| A08 | 변경된 자료의 후손만 재검토, 무관한 승인 재사용 | 완료 · ae15e0c · 35개 검사 · 독립 검토 통과 |
| A09 | 반복·예산·입력 부족을 구분한 다음 작업 판정 | 완료 · 916c5ce · 24개 검사 · 독립 검토 통과 |

실제 M1 역할 실행·UI·실험 수행과 별개인 공통 정책 구현이다. 입력 생성·승인 권한을 임의로 대체하지 않는다.

## 구현 및 검토 결과

- A06: `validate_position_change`, `validate_rationale_links`와 읽기 전용 `commands.read_policy_snapshot` 추가. 같은 쟁점·작성자의 정확한 이전 입장, 변경 사유·근거, 주장·판정·문장에 대한 원작성자의 확인을 검사한다. 중복 주장으로 확인을 우회하는 경로와 잘못된 세션 입력을 보완했다.
- A07: `assess_gate`는 필수 독립 역할·제출·출처·현재 승인·차단 범위를 검사한다. 검증된 원래 이벤트에서 상태를 계산한다. M1 경험적 질문은 정확한 M2 수신 수락이 있으면 미해결로 인계 가능하고 M2 무결성 차단은 남는다. 조정자의 인계 선택과 무관하게 범위 없는 반대를 보정 요청하고, 잘못된 선행 컬렉션은 진행 불가로 반환한다.
- A08: `plan_revalidation`은 정확한 과거 버전의 의존 그래프에서 변경 대상과 후손만 계산한다. 순환·불명·모호한 참조를 거부하며, 승인 적용 범위의 직접 영향도 반영한다. 현재 유효하며 영향 밖인 자료·승인만 재사용한다. 이벤트는 아직 저장하지 않은 계획으로 반환한다.
- A09: `assess_next_work`는 ID·담당·HEAD 이름 변경만으로 같은 작업을 재시도하지 못하게 한다. 반환·실행·비용 예산은 독립적이며 비용 unknown은0이 아니다. 정확한 승인과 연결된 수정은 한 번만 사용 가능하고 과거 실패·불충분 상태를 보존한다. 버전 타입·역사적 수정 참조·중복 근거 우회도 보완했다.

각 작업은 합성 fixture에서 공개 함수와 검증된 저장 snapshot을 사용했다. 초기 기능 부재 RED 및 검토 발견 사례 RED를 확인한 뒤 GREEN을 기록했다. 최종 집중 검사는 A06 9개, A07 35개, A08 35개, A09 24개다. 각 작업의 독립 검토와 수정 재검토 통과; 마지막 검토는 공통 조회·승인·참조 연결도 확인했다. 남은 지적 없음.

최종 영향 범위 명령:

```text
.venv/bin/python -m pytest tests/codex_native/research_graph -q
310 passed in 14.15s
```

기존 실제 M1 프로젝트85개 파일과 가져온 프로젝트76개 파일의 SHA256·mtime·HEAD를 작업 전후 대조해 불변을 확인했다. 저장소 전체 테스트 통과를 주장하지 않으며 이번 공통 정책 영향 범위를 검사했다.
