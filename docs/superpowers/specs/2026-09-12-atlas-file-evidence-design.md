# Atlas 답변 파일을 Pilot 연구에 연결하기

상태: 대화에서 파일 기반 연계 방향 합의. 상세 설계 검토용. 코드 구현 전.

## 사용자 경험과 완료 목표

사용자가 Atlas에 질문해 저장한 QA Markdown 파일을 Pilot에서 선택한다. Pilot이 질문·답변·출처와 미확인 내용을 미리 보여준다. 가져오기를 실행하면 현재 연구 프로젝트의 변경 불가능한 근거 버전으로 보존한다. 같은 근거를 사용한 가설 검토·실제 에이전트 대화·조정자 결론으로 이동할 수 있다. 추가 조사가 필요하면 Atlas에 전달할 질문을 작성해 복사할 수 있다.

첫 검증 사례는 qa-abbasi-process-direction-20260912-001이다. 제공된 답변을 원문 직접 확인이나 독립 과학 검증으로 표시하지 않는다. 기능 시험과 실제 연구 실행을 구분한다.

## 책임과 범위

- Atlas: 자료 탐색·확보·추출·위키 축적·질답 작성.
- Pilot: 외부 답변의 보존, 사용 범위 판단, 가설 교차 검토, 실험 설계와 결정 기록.
- 사용자: Atlas에 질문하고 답변 파일을 전달. 이후 허용된 검토는 매 라운드 승인 없이 진행.
- 이번 전달 수단은 파일이다. Atlas API/MCP, 자동 조사 요청 전송, 폴더 감시, Atlas 원본 수정은 포함하지 않는다.
- PDF 재수집·변환과 과거24개 선정 자료의 재승인을 이번 기능의 조건으로 요구하지 않는다.

## 입력과 버전

현재 Atlas schema_version=1 QA Markdown을 첫 지원 형식으로 한다. YAML frontmatter의 id·question·answer·consulted_pages·candidates를 해석하고 원본 바이트를 함께 보존한다. 안전한 YAML 로더와 중복 키 검사, 지원 버전·필수 필드 타입 검사를 사용한다. 구분자는 독립된 `---` 행으로 처리한다. 답변 안의 표 구분선을 frontmatter 끝으로 해석하지 않는다.

일반 Markdown이나 PDF는 이번 수신 형식이 아니다. 지원하지 않는 파일에는 필요한 Atlas QA 파일 형식을 안내한다. 후보·출처 정보가 없는 경우 빈 목록/미제공으로 표시하며 만들어 넣지 않는다. 구조가 잘못된 필드와 단순 미제공을 구분한다.

Pilot 프로젝트는 가져오는 현재 프로젝트에서 지정한다. Atlas project가 null이어도 허용하고 두 프로젝트 식별자를 혼동하지 않는다. Atlas QA ID와 전체 파일 해시를 저장한다. 같은 프로젝트·같은 ID·같은 해시는 기존 버전을 반환하고, 같은 ID·다른 해시는 이전 버전을 연결한 새 버전으로 보존한다. 동일 내용이 다른 ID로 왔다면 중복 가능성을 표시하며 별개 논문 근거 수로 합산하지 않는다.

원문 ID·버전·locator·해시와 consulted page 해시는 Atlas의 선언으로 보존한다. 이번 가져오기는 원문 PDF를 열거나 해시를 별도 대조하지 않는다. 질문·답변·후보 원문을 보존하고 산문을 임의로 잘라 저자 주장/Atlas 판단으로 자동 확정하지 않는다. 구조화되지 않은 구분은 원응답에서 확인할 수 있게 표시한다.

## 저장과 근거 사용 판단

새 외부 근거 기록은 기존 research_graph의 object 저장·트랜잭션·expected HEAD 검사를 사용한다. 마크다운 원본과 정규화된 외부 근거 레코드를 저장하며, 변경은 새 버전으로만 남긴다. 공개 mutation dispatcher를 거치고 state 파일 직접 수정은 금지한다.

별도 사용 판단에는 대상 근거 버전, 관련 연구 질문 참조, 허용 용도, 보류 용도, 한계, 작성 주체와 판단 이유를 둔다. 상태는 미검토/사용/범위를 정해 사용/보류/제외로 구분한다. 가져오기와 사용 판단은 서로 다른 사건이다.

Atlas 추가 후보는 위키 반영 전 상태를 유지한다. 그 상태가 답변 전체의 무조건 사용 금지나 위키 반영 완료를 뜻하지 않는다. 근거 부족으로 미정인 항목은 결정과 영향을 받는 작업에 연결한다.

## 가설·실제 토론·결정 연결

현재 node-neutral council의 initial/response/final 공개 순서를 재사용한다. 외부 근거 검토의 입력 묶음에는 연구 질문, 가설·대안 설명, 사용 판단과 정확한 근거 버전을 연결한다. 일반 명칭의 외부 근거 검토 문맥으로 준비하며 기존 M1 hypothesize 노드가 완료됐다고 표시하지 않는다.

호스트 실행은 기존 실행 경로와 저장·재개 절차를 재사용한다. 실제 응답이 도착해야 제출하며, 호스트를 실행하지 않은 기능 테스트는 가상 응답임을 표시한다. 팀장은 미해결 이견·반박·판단 변경과 다음 질문을 연결한 별도 결론을 남긴다. 결론은 근거 버전과 실제 제출 참조를 고정한다.

이미 파일로 존재하는 이전9개 발언은 과거 외부 검토 기록으로 표시할 수 있지만 현재 native council의 새 발언으로 재제출하지 않는다. 새 실제 협의는 구현 후 연결 또는 판단에 새 검토 사유가 있을 때 실행한다. 표시를 채우기 위한 동일 협의 재실행을 하지 않는다.

추가 질문 초안은 결정 ID·부족한 근거·답이 바꿀 판단·요청 범위를 가진다. 복사/다운로드만 제공하고 Atlas 전송 완료 상태를 만들지 않는다.

## 새 답변과 이전 결정

새 파일을 가져와도 진행 중인 회차의 입력이나 과거 결론을 바꾸지 않는다. 같은 QA의 새 버전이 생기면 이전 버전을 사용한 결정에 새 답변이 있음을 표시한다. 변경 내용을 검토한 뒤 새 회차를 시작하거나 기존 판단을 유지한 이유를 새 기록으로 남긴다. 다른 QA ID 간 동일성은 추측해 자동 연결하지 않는다.

## 화면과 파일 입력

기존 연구 화면의 자료 카드·판단 카드·대화 영역을 재사용한다. 별도 연구 대시보드를 만들지 않는다. 기본 흐름은 다음과 같다.

1. ‘Atlas 답변 가져오기’에서 로컬 파일 선택.
2. 질문·답변 요약이 아닌 실제 답변의 접힌 본문, 출처 수, 미제공 항목, 기존 버전 여부 미리보기.
3. ‘이 연구에 가져오기’ 실행 후 ‘가져옴 · 검토 전’ 표시.
4. 사용 판단·관련 질문·결정과 실제 대화로 이동.
5. ‘Atlas에 물어볼 질문’에서 초안 복사.

원본 해시·내부 ID는 상세 정보에 둔다. ‘Atlas에서 전달된 답변’, ‘위키에 반영할 후보 포함’, ‘이전 답변으로 내린 판단’처럼 사람이 이해할 문구를 쓴다. 등록·검토·단계 완료를 같은 성공 배지로 합치지 않는다. 자료/결정이 없으면 없는 상태를 설명하며 가짜 대화나 실행 버튼을 만들지 않는다.

현재 viewer는 GET만 지원한다. 파일 입력은 same-origin의 제한된 JSON POST로 새로 제공한다. 브라우저가 선택한 파일 바이트를 전달하고 서버가 재검사한다. 서버의 임의 로컬 경로를 받아 읽지 않는다. CLI는 사용자가 명시한 QA 경로를 읽어 같은 정규화·등록 기능을 호출한다. 문서 안의 링크를 자동 열거나 실행하지 않는다. 웹 화면에서는 본문을 안전한 텍스트로 렌더링하고 로컬 절대 경로는 서버 파일 접근 링크로 노출하지 않는다.

파일 전송 상한은 QA 한 파일 10 MiB로 두며 초과 시 등록 전 명시적으로 실패하고 기존 상태를 유지한다. 이는 연구 시간·문헌 수 제한이 아니라 이 입력 기능의 요청 크기 제한이다. 기존 origin/Host 검증과 HEAD 충돌 검사를 유지한다. 미리보기 후 파일이 달라지는 것을 막기 위해 등록은 미리 본 동일 바이트와 해시를 사용한다.

## 기존 단계 정책과의 관계

이번 외부 근거·사용 판단·검토·결정은 정식 저장 기록으로 남기되 기존 collect/extract를 수행한 것으로 위장하지 않는다. 기존 corpus 승인·이슈 상태를 변경하지 않으며 M1 자동 통과를 구현하지 않는다.

현재 M1 종합 완료 조건이 자체 수집·추출 참조만 받는 문제는 후속 정책 변경으로 분리한다. 외부 근거로 무엇을 충족할 수 있는지와 필요한 검토 조건을 별도 설계해 적용해야 한다. 화면은 외부 검토가 진행됐다는 사실과 M1 정식 완료가 남았다는 사실을 함께 보여준다.

## 작게 나눈 개발 단위

| 순서 | 결과물 | 독립 확인 기준 |
| --- | --- | --- |
| A1 파일 읽기 | QA 해석·검증·원본 해시·미리보기 | 실제 사례 해석, 잘못된 YAML/버전/답변 필드 거절, 표 구분선 처리 |
| A2 근거 등록 | 외부 근거 불변 저장·중복/새 버전·CLI 입력 | 재등록 멱등성, 이전 버전 보존, 프로젝트 구분, 실패 시 HEAD 유지 |
| A3 사용·결정 연결 | 질문 참조·허용/보류 용도·검토 입력·결정 관계 | 다른 프로젝트/없는 참조 거절, 동일 버전 고정, 기존 council 공개 규칙 유지 |
| A4 화면 연결 | 파일 선택·미리보기·등록·자료→결정→대화 탐색 | 실제 서버, 잘못된 파일, HEAD 충돌, 빈 상태, 3개 화면 폭·키보드 동작 |
| A5 질문·갱신 | 추가 질문 복사, 새 답변 버전 표시·재검토 관계 | 전송을 주장하지 않음, 진행 중 입력/과거 결론 보존, 변경 영향 추적 |

첫 시연은 A1–A4로 이번 QA 한 건을 가져오고 연결된 검토 기록을 확인하는 것이다. A5는 같은 형식의 후속 파일로 갱신 흐름을 확인한다. 문서 개수·토론 횟수를 연구 효과 입증으로 삼지 않는다.

## 구현 위치와 검증

- researchclaw/codex: 새 atlas_intake.py에서 파일 입출력·정규화, research_cli.py의 입력 명령, research_viewer.py의 좁은 POST 경로.
- researchclaw/core/research_graph: 새 external_evidence.py의 순수 등록/판단 정책, commands.py의 등록·hydration, views.py의 근거·결정 projection.
- councils.py: 기존 공개 정책 재사용. 외부 문맥에서 불필요한 수정 없이 동작하는지 회귀 검사.
- research_ui: 외부 근거 입력·상세 모듈을 작게 추가하고 app/detail/trace의 기존 탐색에 연결. 공통 CSS 토큰 사용.
- tests/codex_native/research_graph: 파서·외부 근거·참조·버전·council·viewer 검사. 실제 과학적 근거를 새로 검증한 것으로 표시하지 않는 상태 검사 포함.
- docs/ui/README.md, components.md, review.md의 카드·문구·화면 규칙 준수.

완료 검증은 같은 파일 두 번 가져오기, 같은 ID 수정본, 깨진 입력, 출처 미제공, Atlas project null, 프로젝트 다른 참조, 새 버전 이후 과거 결정 조회를 포함한다. 기존 연구 상태가 자동 완료되지 않는지 확인한다. 정적 파일 변경·자동 검사·서버 반영·브라우저 확인 결과는 나누어 보고한다.
