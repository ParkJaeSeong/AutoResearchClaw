# Atlas 질의와 위키 축적 — 공동 논의

2026-09-18. 상태: Atlas 회신 확인·Pilot 검토 반영. 공동 권고안이며 정책·계약 세부 사항은 미확정이다. 구현 완료가 아니다.

## 사용자와 확정한 방향

Atlas는 위키 검색 후 부족하면 보유 문헌을 확인하고, 새로 확인한 지식을 위키에 반영한다. 위키 반영은 답변 생성과 별도 단계지만 매번 사용자에게 다시 요청하도록 하지 않는다. 외부 수집은 Pilot 담당. Pilot은 해당 마일스톤 끝까지 승인 범위에서 자동 실행한다.

## Pilot의 인터페이스 제안

기존 readonly ask를 조용히 쓰기 작업으로 바꾸지 않는다. 기존 서비스를 유지하고 명시적으로 선택한 지식 축적형 질의 operation/capability를 추가하는 쪽을 우선 검토한다. 실제 endpoint·operation 이름은 Atlas와 합의 전이다.

공통 요청 봉투는 Pilot 작업·요청자·반환 작업을 보존한다. Atlas에는 서비스가 지원하는 추적 필드와 project, 질문, input refs, 위키 반영 범위를 전달한다. HTTP/MCP에서 동일한 요청 의미·멱등성·권한·오류를 유지한다.

결과는 답변 참조와 위키 반영 결과를 분리한다. 답변 원형은 생성 당시 버전으로 불변 보존한다. 위키 변경은 대상 page의 이전/새 해시, 변경 이유, 근거 source/version/위치, 작업 참조를 보존한다. 질문 답변의 근거 참조가 나중에 변경된 페이지로 조용히 바뀌면 안 된다.

상태는 answer 준비와 knowledge 반영을 별도 축으로 둔다. knowledge는 반영 불필요/반영 완료/충돌로 보류/실패 등을 구분한다. 답변 수신 ACK가 위키 반영 성공을 의미하지 않게 한다. 위키 반영 실패 복구는 기존 답변을 재생성하거나 재질의하지 않고 해당 작업부터 재개한다.

실행은 요청 멱등키+내용 fingerprint, 변경 전 hash 비교, 원자적 변경 또는 변경 원장에 의한 복구를 요구한다. 같은 결과가 두 번 반영되지 않아야 한다. 성공 증거는 요청 접수가 아니라 변경된 페이지 참조와 검증 결과다.

## Atlas 공동 검토 반영

기존 readonly ask 유지와 명시 복합 operation을 양쪽에서 권고한다. 명칭·capability·endpoint는 후속 계약에서 확정한다. 이번 QA의 후보 ID만 처리하며 전역 pending ingest로 대신하지 않는다. QA 준비와 후속 위키 작업을 영속 연결해 중간 종료를 복구한다.

자동 갱신 후 QA 당시 페이지 hash 조회가 409가 될 수 있다. 복합 작업에 한정해 **답변 입력 페이지 원형을 고정하고 회수할 경로**가 필수다. 범용 과거 snapshot API까지 요구하지 않는다. 회수 크기·보관 조건은 계약에서 정한다.

초기 관찰은 복합 job polling으로 한다. Documents import 이벤트/ACK를 ask에 재사용하지 않는다. 앞 절의 ACK 설명은 향후 이벤트 도입 시의 의미다. 답변·위키 반영·색인 상태와 후보별 부분 성공을 구분하고 실패 단계만 재개한다.

현재 client_context는 pilot_project_id/question_id/issue_id/round_id/binding_ref만 허용한다. 공통 봉투는 Pilot 원장에 보관하고 허용 참조만 매핑한다. 질문에 쓴 source 목록은 강제 필터가 아니다. 엄격한 자료 범위는 별도 검증·계약이 필요하다. import 인증과 A1 인증을 분리하고 쓰기 권한을 명시한다. project는 현재 보안 경계가 아니므로 비공개 독립 의견을 공유 위키에 노출하지 않는다.

## 사용자 정책 — 세 가지 공동 권고, 미확정

1. 자동 반영 내용: 원문에서 확인한 보고·조건·한계를 자동 반영하고 Atlas 비교 해석도 해석임을 표시해 프로젝트 영역에 보존한다. Pilot 가설은 Pilot에 유지한다. 대안은 Atlas 해석을 후보로만 남기는 것으로 재사용이 늦어진다.
2. 공용 범위: 문헌 자체의 출처별 요약은 공용 재사용하고 프로젝트 특화 해석의 공용 개념·종합 페이지 승격은 별도 정책으로 둔다. 모두 프로젝트에만 두면 중복, 모두 공용화하면 범위 밖 일반화 위험이 있다.
3. 반영 실패 시 진행: 답변과 근거 원형이 검증·보존됐으면 Pilot 검토를 계속한다. 필수 근거·무결성 문제는 영향받는 작업만 대기한다. 모든 반영을 기다리면 색인 장애까지 연구 전체를 막는다.

상충하는 근거는 조건별 병기하고 정정 이력을 남긴다. 저자 보고·Atlas 해석·Pilot 가설을 구분한다. 출처·중복 방지·실패 보존·비공개 보호는 선택 옵션이 아니다. 정상 단계마다 사람 확인을 추가하지 않는다.
