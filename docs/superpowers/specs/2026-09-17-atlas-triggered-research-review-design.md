# Atlas 결과 도착에 따른 Pilot 연구 검토

2026-09-17 · 사용자와 설계 논의 중. 합의와 제안을 구분한 초안이며 구현 명세 확정·자동 실행 활성화 문서가 아니다.

## 합의한 목적과 책임

Pilot은 도메인 전문가를 조정하여 연구 질문, 근거의 충분성, 가설·실험 설계, 다음 작업을 판단한다. Atlas는 지식 보관·검색·분석과 보유/확인 범위, 근거 공백·충돌, 후속 자료 후보를 제공한다. Atlas의 후보 제안은 검증된 외부 근거가 아니다. 외부 검색·확보와 분석 의뢰는 Pilot이 담당한다. Documents는 이미지 해석을 포함한 문서 변환을 담당한다.

이번 범위는 Atlas 완료에서 Pilot 검토를 시작하는 연결이다. 본문·그림의 분할 전달이나 새로운 문서 전송 계약은 도입하지 않는다. 문서 처리 시간 개선은 Documents에서 별도로 다룬다.

## 합의한 연구 흐름

1. 프로젝트의 요청에 대응하는 Atlas 결과가 도착한다.
2. Pilot이 자료 보유·읽은 범위·미확인을 대조한다.
3. 한 편마다 개별 검토 토론을 수행한다. 무엇을 뒷받침하고 어디까지 사용할 수 있는지 잠정 판단을 저장한다.
4. 이번 판단에 필요한 자료 묶음의 준비 상태를 확인한다.
5. Pilot이 준비된 근거 범위와 질문을 정해 Atlas에 통합 질의를 보낸다. Atlas의 통합 답변·출처·읽은 범위를 고정하고 요청 범위와 대조한 뒤 전문가 종합 토론을 한다. 개별 결과는 재사용하되 Atlas의 자료 연결·정리를 Pilot이 중복 수행하지 않는다.
6. 조정자가 판단 이유와 다음 작업을 기록한다. 가설 작성, 집중 검토, 자료 보완 등으로 이어진다.

‘모든 자료’는 세상의 모든 문헌이 아니라 이번 판단을 위해 정한 자료 묶음이다. 자료를 더 요청할 때 이전 묶음과 판단 이력을 지우지 않는다. 묶음 정의·수정 권한 및 종합 시작 조건의 세부 규칙은 아래 결정 항목이다.

부족한 근거는 원인에 따라 다르게 보완한다.

| 상태 | 다음 작업 |
| --- | --- |
| Pilot 보유, Atlas 미보유 | 기존 자료 전달 |
| Atlas 보유, 필요한 해석 부족 | 추가 분석 요청 |
| 변환 실패·읽을 수 없는 내용 | Documents 보완 요청 |
| 현재 자료로 답할 수 없음 | 외부 탐색·수집 |

보완 후에는 영향받는 쟁점부터 재검토한다. 임의의 토론 횟수를 채우거나 같은 근거로 반복하지 않는다.

## 검토 역할에 대한 제안

자료 수신·식별자 대조·정해진 전달은 프로그램 또는 조정자가 처리한다. 근거 충분성, 충돌 해석, 가설·설계·방향 결정은 전문가 교차 검토 대상으로 둔다.

기본 검토 역할은 도메인 전문가, 방법론 검토자, 비판 검토자다. 조정자는 결론과 후속 작업을 정리한다. 역할별 목적과 공통 입력을 고정하고 독립 첫 의견 → 상호 검토 → 조정자 판단 순서로 진행한다. 독립 원문 검증 여부는 실제 제공·도구 접근 범위로 표현한다.

공통 입력에는 현재 질문과 버전, 검토 목적, 이전 판단, 새 결과의 버전/해시, 원문 위치, Atlas 해석, 미독 범위, 변경 사항을 포함한다. 개별 토론 결과는 해당 자료의 잠정 판단이며 종합 결론이나 M1 완료가 아니다.

## 로컬 실행 연결에 대한 제안

Atlas가 Pilot 파일을 직접 편집하지 않는다. 기존 완료 이벤트를 로컬 관찰기가 받아 프로젝트 작업 목록을 갱신하고 결과 검토를 실행하도록 제안한다.

현재 구현은 결과 검증·영속 저장·이벤트 ACK까지다. 연구 검토 작업 생성·실행기 연결·서비스 자동 기동은 후속 개발 범위다. ACK는 수신 확인이며 연구 검토 완료가 아니다.

체크리스트 항목은 프로젝트/질문 버전, 작업 ID, 기다리는 요청/결과, 사용할 자료, 실행할 일, 완료 기준, 상태와 산출물 참조를 가진다. UI의 체크리스트는 영속 작업 기록의 표시이며 독립된 두 번째 상태 저장소로 만들지 않는다.

제안하는 실행 보호:

- 이벤트 ID와 결과 버전으로 중복 검토 등록을 방지한다. 프로세스 장애를 포함한 ‘정확히 한 번 실행’을 단순 주장하지 않고 영속 대기열·실행 점유·복구로 중복 결과 채택을 방지한다.
- 결과 저장과 검토 대기열 등록 사이에 종료되어도 저장 결과에서 미등록 작업을 복구한다. 기존에 ACK된 결과도 검토 등록 여부를 대조할 수 있어야 한다.
- Pilot이 실행 중이면 작업을 저장해 기다린다. 꺼진 동안 도착한 작업은 다음 실행 시 복구한다. OS 자동 기동은 별도 결정한다.
- 질문 변경 시 이전 결과는 보존하고 현재 질문과의 관련성을 확인한다.
- 부분 완료는 사용 범위 검토 대상으로 취급한다. 실패 알림으로 과학적 검토를 완료하지 않는다.
- Atlas 완료, 결과 수신, 검토 대기, 검토 중, 검토 완료, 실행 실패를 구분한다.

## 아직 결정할 사항

1. 개별 토론이 종합 전 가설·추가 수집을 어디까지 실행할 수 있는가?
2. 이번 자료 묶음의 구성과 필수/선택 구분을 누가 정하며, 실패·부분 결과를 포함한 종합 시작 조건은 무엇인가?
3. 로컬 실행기가 어떤 Pilot 실행 환경을 시작할 것인가? 기존 대화에 알림 전달과 별도 작업 실행의 차이, 프로젝트별 동시 실행 범위가 필요하다.
4. 개발 중 사람 검토는 어느 판단에서 멈추며, 프로젝트 설정으로 어떻게 켜고 끌 것인가?

한 번에 하나씩 사용자와 결정하고 최종 명세에 반영한다. 이 초안 작성으로 위 제안을 확정하거나 실제 연구·원격 작업을 시작하지 않는다.

## Atlas 공동 검토 반영 — 2026-09-17

Atlas 검토: `/Users/jspark/orca/projects/ResearchAtlas/docs/integrations/documents-atlas/pilot-review-trigger-review-2026-09-17.md`。 기본 방향 수용. 아래 기술 경계는 Pilot 초안에 반영하며, 뒤의 운영 정책 권고는 사용자 미확정 상태로 유지한다.

### 기존 계약을 사용하는 입력 확보

- import/events 인증과 A1 page/source/search/ask 인증은 별도 연결로 유지한다. 양쪽 info의 Atlas instance가 같아야 한다. 도구 이름의 존재를 실행 권한으로 간주하지 않는다.
- 이벤트의 result_ref는 import 결과 record의 canonical JSON 해시와 대조하고, 원래 요청 payload와 합쳐 프로젝트/질문 맥락을 복구한다.
- 검토 전에 참조된 페이지를 expected_sha256 및 include_raw로 받아 전체 원형을 Pilot에 보존한다. 현재 과거 page hash 조회 API가 없으므로 409 changed_page가 나오고 로컬 보존본도 없으면 입력 고정을 보류한다. 최신 페이지로 대체하지 않는다. 새 분석/복구 작업은 별도로 기록한다.
- ACK된 이벤트도 재조회 가능하다. 이벤트 중복은 event ID, 검토 작업 중복은 Atlas instance/import/result hash + Pilot 질문 revision + 검토 목적/정책 revision으로 구분한다. 새 질문의 재검토는 별도 작업이다.
- 일반 ask는 import 완료 이벤트의 대상이 아니다. ask는 기존 job 조회로 관찰하고 QA 원형을 보존한다. ask 결과는 위키 갱신 완료를 뜻하지 않는다.

### 검토 가능한 결과와 사용할 수 없는 추정

completed/partial 결과에서도 실제 고정 입력을 확보한 경우에만 과학적 개별 검토를 등록한다. failed의 진단 result_ref, cancelled, needs_attention은 복구/공백 처리로 연결한다.

partial 원인은 과학적 근거 공백, Documents 변환 문제, Atlas 구조/색인 문제로 나눠 보존한다. 전체 자료실 structure_check_failed를 특정 논문 부정확성으로 확대하지 않고 검색 색인 current를 과학적 타당성으로 해석하지 않는다. Atlas의 그림 대조 기록과 Pilot 전문가의 직접 그림 확인은 구분한다.

현재 source XML 조회만으로 변환 그림 원형 전체를 받을 수 없다. extraction_refs.path는 다운로드 API가 아니다. 질문별 typed coverage와 그림 artifact 조회는 미구현이며 ‘자료 보유/미독 목록’의 완전한 자동 판정을 가정하지 않는다. 검색 미발견은 자료 미보유의 증명이 아니다.

추가 해석은 필요한 경우 기존 A1 ask로 요청한다. 질문에 지정한 source 집합은 강제 필터가 아니므로 반환 근거의 범위를 Pilot이 검토한다. 범위 밖 근거는 공통 입력에 조용히 섞지 않고 별도 후보로 남긴다. analyze/계약형 ingest가 구현된 것으로 간주하지 않는다.

### 버전과 자료 묶음

원문 source/version/hash, Documents task/result revision/manifest hash, Atlas import/result/page hash, 추가 QA 원형 hash, Pilot 질문/공통 입력/검토/묶음/결정 revision을 구분한다. 기존 terminal import 재개를 새 분석으로 사용하지 않는다.

묶음의 목적·필수/선택 자료·고정 결과 집합·준비 조건은 Pilot이 관리한다. Atlas bundle/ready API는 추가하지 않는다. 변경은 새 묶음 revision으로 기록한다. 새 결과의 영향은 기존 판단 유지/보완/제한/철회의 이유로 남긴다.

### 사용자 결정 전 권고

Atlas도 개별 전문가의 보완 제안을 조정자가 모아 중복·우선순위를 정하는 방식을 권고했다. 필수 쟁점별 근거와 개별 검토 결과로 묶음 준비를 판단하되, 핵심 근거가 없는 결론은 채택하지 않는다. 미충족 상태로 종합할 경우 공백 정리인지 제한된 결론인지 목적과 영향을 명시한다.

기존 council 실행기 재사용 및 프로젝트별 판단 쓰기 직렬화를 우선 검토한다. 기존 대화 터미널에 텍스트를 넣는 방식을 영속 실행 계약으로 삼지 않는다. 실제 실행기 적합성은 구현 계획 전 코드 확인이 필요하다. OS 자동 시작과 개발 중 사람 검토 위치는 아직 결정하지 않았다.

### 추가 수락 기준

서로 다른 instance의 인증, 페이지 409/해시 불일치, 실패 진단만 있는 결과, ACK된 과거 결과의 미등록 복구, 새 질문에 대한 같은 자료 재검토, 묶음 변경, 범위 밖 ask 근거를 확인한다. 모델 호출 중단 후 재실행 가능성과 판단 중복 채택 방지를 구분한다.

이번 반영은 문서 수정만이며 코드·운영·실제 연구 상태 변경과 재접수를 하지 않았다.

## 2026-09-18 사용자 합의: 통합 질의 후 종합 토론

흐름: 필요한 자료 준비 → Pilot의 통합 질의 → Atlas의 근거 연결·정리 → Pilot 전문가 종합 토론 → 조정자의 다음 작업 결정.

본문·보충자료·데이터가 동일 연구에 속한다는 문서 관계와 통합 해석은 Atlas 책임이다. Pilot이 정하는 묶음은 연구 질문에 답할 비교 범위이며 여러 논문을 포함할 수도 있다. 동일 연구 본문과 보충자료를 서로 독립적인 실증 근거 두 건으로 세지 않는다.

통합 질의는 검토 질문·고정 source/version/import/result 참조·이전 개별 검토의 공백을 전달한다. 답변은 자료별 새 근거, 기존 해석을 유지/보완/수정하는 내용, 충돌, 미확인, 출처 위치를 구분한다. Atlas는 자료 연결과 해석을 담당하고 Pilot은 설명 타당성·가설·설계·다음 행동을 판단한다.

현재 구현은 기존 A1 ask를 사용한다. 지정 source 집합은 강제 필터가 아니므로 범위 밖 근거를 별도로 표시하도록 요청하고 수신 후 확인한다. 일반 ask는 import 이벤트가 아닌 job 상태로 관찰한다. 결과 수신을 종합 토론 자동 실행이나 연구 채택으로 간주하지 않는다. 자동 종합 연결은 후속 구현이며 이번 승인 범위는 설계 저장과 실제 통합 질의 1건이다.

## 2026-09-18 후속 상세 설계

[공통 요청·응답과 마일스톤 자율 실행](2026-09-18-pilot-service-request-design.md)이 최신 실행 범위다. 사용자는 자동 실행을 현재 마일스톤 끝까지로 지정했다. 기존 제안의 ‘가설 채택·추가 작업마다 사람 확인’은 기본값으로 채택하지 않는다. 실제 권한·자원 경계와 마일스톤 완료 근거는 유지한다.
