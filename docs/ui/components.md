# 화면·컴포넌트 규칙

[공통 UI 기준](README.md)을 구체적인 화면 요소로 옮기는 문서다.

## 공통 요소

| 요소 | 기본으로 보여줄 것 | 펼쳐서 보여줄 것 |
| --- | --- | --- |
| 진행 요약 | 현재 작업, 실제 실행 여부, 최근 판단, 다음 행동 | 실행·갱신 시각과 상세 이력 |
| 판단 카드 | 무엇을 결정했는지, 이유, 남은 조건 | 관련 대화·근거·이전 판단 |
| 자료 카드 | 제목, 자료 종류, 읽은 범위, 이 연구에 필요한 이유 | URL/DOI, 버전, 원문 위치, 관찰·해석, 사용 판단 |
| 문제 카드 | 쉬운 질문, 영향받는 작업, 현재 처리, 다음 확인 | 담당·근거·변경 이력·내부 ID |
| 실험 카드 | 검증 질문, 실행 상태, 결과 요약·한계 | 설계·조건·원자료·실패·비용 |
| 인계 카드 | 넘기는 내용, 남은 질문, 수신 상태 | 승인 범위·입력 버전·세부 기록 |

같은 사실의 기준 데이터는 하나로 유지한다. 요약을 따로 저장할 때는 대상 기록과 버전을 연결하고, 원기록 변경 시 요약이 이전 버전임을 표시한다. 누락값은 0이나 성공으로 채우지 않는다.

## 에이전트 대화

사용자는 채팅의 양보다 의견 차이와 결정 이유를 보고 싶어 한다.

- 회차 머리말: 검토 질문과 “각자 검토 / 서로 의견 검토 / 최종 판단” 중 현재 단계.
- 발언 카드: 역할 이름 → 판단 → 이유 → 다른 의견에 대한 답 → 다음 할 일.
- 상대 의견에 대한 답은 가능한 경우 해당 발언으로 이동하는 링크를 둔다.
- 회차 요약: 공통 판단, 남은 이견, 바뀐 의견과 이유, 다음 행동. 동의 여부로 사실 검증 완료를 추정하지 않는다.
- 독립 의견은 모두 제출된 뒤 공개한다. 대기 화면에서 미공개 발언의 내용·요약을 노출하지 않는다.
- 요약·쉬운 해설에는 작성 주체와 대상 회차를 표시한다. 원문을 확인할 수 있어야 하고, 원래 발언을 덮어쓰지 않는다.
- 기존 발언을 임의로 잘라 결론이 달라지게 하지 않는다. 긴 발언도 핵심 조건은 쉽게 찾을 수 있게 한다.

향후 발언 작성은 [에이전트 작성 가이드](../research/guides/research-agents.md)를 따른다. UI가 난해한 프롬프트 출력을 매번 임의 번역하는 구조로 해결하지 않는다.

## 화면 크기와 시각 규격

아래 값은 새 작업에서 사용할 프로젝트 기본값이다. 현재 CSS가 모두 이 값으로 정리됐다는 뜻은 아니다.

| 항목 | 기본값 |
| --- | --- |
| 내용 최대 폭 | 1400px, 가운데 정렬 |
| 바깥 여백 | 데스크톱 24px, 작은 화면 16px |
| 여백 단위 | 4 / 8 / 12 / 16 / 24 / 32px |
| 본문 | 16px, 줄 높이 1.7; 장문은 약 65–80자 폭 |
| 보조 문구 | 14px; 핵심 상태를 작은 각주로 숨기지 않음 |
| 제목 | 화면 28–32px, 영역 20–24px, 카드 16–18px |
| 카드 | 내부 여백 20–24px, 반경 12px; 중첩 카드는 최소화 |
| 조작 요소 | 최소 높이 44px; 키보드 초점 명확히 표시 |
| 큰 화면 | 작업 탐색 280–320px + 본문 가변 폭 |
| 좁은 화면 | 768px 이하에서는 한 열; 작업 탐색 → 선택 내용 순서 |

본문은 한글 단어 단위로 줄을 바꾸고 URL·긴 식별자는 넘치지 않게 줄바꿈한다. 페이지가 기본 스크롤을 담당한다. 목록 내부 스크롤이 꼭 필요하면 영역과 제목을 명확히 하고 긴 본문에 이중 스크롤을 만들지 않는다.

색상은 기존 `--bg`, `--card`, `--ink`, `--muted`, `--line`, `--accent`, `--soft`, `--warn`, `--warn-bg` 변수를 공통 사용한다. 성공·선택·경고의 의미를 혼용하지 않는다. 상태는 색상과 글자를 함께 사용하고 밝은·어두운 화면 모두에서 읽을 수 있게 한다.

동일 요소는 공통 스타일을 수정한다. 파일 끝에 같은 선택자를 반복해서 덮어쓰지 않는다. 좁은 화면에서는 정보 중요도를 유지하며 열 배치만 바꾼다.

## 상호작용

- 긴 목록은 검색·필터·접기를 제공하되 최근 판단과 중요한 차단 조건은 기본으로 보인다.
- 자동 갱신은 선택한 단계·회차·펼침·검색·스크롤·키보드 초점을 유지한다.
- 연결이 끊기면 마지막 정상 자료와 그 시점을 보존한다. 오래된 자료를 현재 실행 결과처럼 표시하지 않는다.
- 비어 있는 경우를 구분한다: 아직 없음 / 검색 결과 없음 / 불러오기 실패 / 공개 대기.
- 동작하지 않는 버튼은 만들지 않는다. 조회 전용 화면에는 “실험 시작” 같은 실행 버튼을 놓지 않는다.
- 실행·승인 기능을 추가할 때는 대상·효과·필요한 조건을 보여주고 권한은 서버에서도 확인한다.
- 제목 계층, 버튼·탭·목록의 의미, 초점 표시를 유지한다. 키보드만으로 탐색·펼침·탭 이동이 가능해야 한다.
