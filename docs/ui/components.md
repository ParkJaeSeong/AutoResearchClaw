# 화면·컴포넌트 규칙

[공통 UI 기준](README.md)을 구체적인 화면 요소로 옮기는 문서다.

문장만 나열한 기준·조건·사유는 불릿 목록으로 표시한다. 항목별 배경·테두리·둥근 박스를 넣지 않는다. 여러 필드로 구성된 자료 기록은 별도 구조를 유지한다.

## 프로젝트와 단계 탐색

- 왼쪽 메뉴 맨 위에서 프로젝트를 선택하거나 만든다. 선택한 프로젝트 이름을 표시하고 연구 주제는 본문에서 확인한다.
- 프로젝트 아래에 M1·M2·M3를 구분한다. M1의 단계 묶음은 연구 내용을 찾는 메뉴다. 단계 번호를 실제 실행 순서나 완료율로 사용하지 않는다.
- 단계 묶음 이름을 누르면 해당 수행 기록을 보여준다. 같은 기능의 ‘단계의 수행 기록’ 버튼을 하위 메뉴에 반복하지 않는다. 펼쳐진 묶음은 다시 눌러 접을 수 있다.
- 단계의 기록과 실제 수행 회차를 구분한다. 같은 단계로 돌아간 회차는 그 단계에서 함께 볼 수 있고, 전체 수행 이력에서는 원래 시작 순서를 유지한다.
- 아직 실행 기능이 없는 마일스톤은 범위와 지원 상태만 안내한다. 다른 마일스톤의 기록을 대신 보여주거나 완료 상태를 추정하지 않는다.
- 프로젝트 자료는 해당 프로젝트의 공개 자료 폴더에서 조회한다. 다른 프로젝트의 목록·필터·미작성 입력을 가져오지 않는다.
- 프로젝트·마일스톤·단계 탐색에도 공통 사이드바 접기와 모바일 메뉴 규격을 유지한다. 메뉴를 접으면 본문은 확보한 폭을 사용한다.

## 공통 요소

| 요소 | 기본으로 보여줄 것 | 펼쳐서 보여줄 것 |
| --- | --- | --- |
| 진행 요약 | 현재 작업, 실제 실행 여부, 최근 판단, 다음 행동 | 실행·갱신 시각과 상세 이력 |
| 판단 카드 | 무엇을 결정했는지, 이유, 남은 조건 | 관련 대화·근거·이전 판단 |
| 자료 카드 | 제목, 자료 종류, 읽은 범위, 이 연구에 필요한 이유 | URL/DOI, 버전, 원문 위치, 관찰·해석, 사용 판단 |
| 문제 카드 | 쉬운 질문, 영향받는 작업, 현재 처리, 다음 확인 | 담당·근거·변경 이력·내부 ID |
| 실험 카드 | 검증 질문, 실행 상태, 결과 요약·한계 | 설계·조건·원자료·실패·비용 |
| 인계 카드 | 넘기는 내용, 남은 질문, 수신 상태 | 승인 범위·입력 버전·세부 기록 |

같은 사실의 기준 데이터는 하나로 유지한다. 요약을 따로 저장할 때는 대상 기록과 버전을 연결하고, 원기록 변경 시 요약이 이전 버전임을 표시한다. 누락값은 0이나 성공으로 채우지 않는다.

## 후보 자료 목록

- 후보 자료는 제목 중심의 접힌 행으로 표시한다. 기본 행에는 제목·기록된 확인 범위·원문 링크를 두고, 개별 자료를 펼치면 DOI·자료 유형 등 상세 정보를 확인한다. 필드마다 큰 카드를 만들지 않는다.
- 제목·DOI·arXiv ID 검색으로 목록을 좁히고 전체/검색 결과 수를 표시한다. 같은 기록의 갱신에서는 검색어·펼침 상태를 유지한다. 자료를 임의로 합치거나 삭제하지 않는다.
- 확인 범위의 코드는 해당 목록에서만 원문/초록/서지 정보/접근 불가로 표시한다. 저장된 범위라는 의미를 유지하며 새로 검증했다고 표현하지 않는다. 내부 ID·검색 ID·누락값을 포함한 원형은 ‘저장된 자료 정보’에 보존한다.

## 단계별 확인할 문제

- 문제 목록과 ‘이 단계 / 전체’ 필터는 왼쪽 작업 지도 아래가 아니라 ‘확인할 문제’ 탭의 본문 폭 전체를 사용한다. 목록 내부에 높이 제한과 별도 스크롤을 두지 않는다.
- 각 문제는 기본 접힘이며 질문·상태·관련 단계를 표시한다. 클릭 또는 Enter/Space로 근거·해결 기준·변경 이력을 펼친다. 여러 항목을 동시에 펼칠 수 있고 같은 목록의 기록 갱신 때 펼침 상태를 유지한다.
- 펼친 본문에서 질문·현재 상태·관련 단계 헤더를 반복하지 않는다. 해결 기준부터 표시하고, 내부 ID·분류·중요도 코드는 접힌 원문 정보에 보존한다. 제기된 단계가 표시되면 ‘이 단계에서 제기됨’을 다시 덧붙이지 않는다.
- 작업 지도에서 단계를 선택하면 그 단계와 연결된 문제만 기본으로 표시한다. 문제 상세도 같은 목록 안에서 선택한다. 다른 단계의 문제를 그대로 남기지 않는다.
- 연결은 제기된 단계(`origin`), 명시된 검토 대상(`target_refs`), 현재 진행 조건(`effective_blocking_scope`)으로 판단한다. 본문 단어로 관계를 추측하지 않는다. 빈 현재 진행 조건을 과거 조건으로 되돌리지 않는다.
- 제기된 단계와 선택 단계에 미치는 영향을 구분해서 표시한다. 하나의 문제가 여러 단계에 연결되면 각 목록에 나타날 수 있다. 해결 여부는 기록된 상태로 별도 표시한다.
- ‘전체’에서 단계 연결이 없는 문제를 포함한 프로젝트 전체 기록을 확인한다. 작업 지도에서 다른 단계를 선택하면 ‘이 단계’로 돌아간다. 같은 단계의 자동 기록 갱신은 유효한 문제 선택과 범위를 유지한다.
- 목록이 비었을 때는 ‘연결된 문제 기록이 없습니다’라고 안내한다. 해당 단계가 검증됐거나 문제가 모두 해결됐다고 표현하지 않는다. 이 목록은 선택한 기록 시점의 단계 단위이며, 선택한 수행 회차만의 목록은 아니다.

## 에이전트 대화

사용자는 채팅의 양보다 의견 차이와 결정 이유를 보고 싶어 한다.

- 회차 탐색: “처음 의견 / 서로의 의견 검토 / 최종 판단” 탭과 각 제출 수를 표시한다. 한 번에 선택한 회차만 보이며 최초 선택은 처음 의견이다.
- 발언 카드는 기본 접힘이다. 역할과 원문 첫 문단의 앞부분(최대 180자·화면 두 줄)을 미리 보여주고 누르면 원문 전체와 근거를 펼친다. 미리보기를 생성 요약이나 최종 결론으로 표시하지 않는다. 작업 회차에 기록한 에이전트 발언도 같은 접기 방식을 사용한다.
- 회차 탭은 방향키·Home·End, 발언 펼치기는 Enter·Space로 조작한다. 기록 갱신으로 같은 대화를 다시 그릴 때 회차 선택·펼침·초점을 복원한다. 브라우저 페이지를 완전히 다시 여는 경우까지 저장하는 기능은 아니다.
- 상대 의견에 대한 답은 가능한 경우 해당 발언으로 이동하는 링크를 둔다.
- 회차 요약: 공통 판단, 남은 이견, 바뀐 의견과 이유, 다음 행동. 동의 여부로 사실 검증 완료를 추정하지 않는다.
- 독립 의견은 모두 제출된 뒤 공개한다. 대기 화면에서 미공개 발언의 내용·요약을 노출하지 않는다.
- 요약·쉬운 해설에는 작성 주체와 대상 회차를 표시한다. 원문을 확인할 수 있어야 하고, 원래 발언을 덮어쓰지 않는다.
- 대화 본문은 800px 상한 없이 발언 카드의 안쪽 폭 전체를 사용한다(사용자 요청). 단어 단위 줄바꿈과 긴 식별자 넘침 방지는 유지한다.
- 기존 발언을 임의로 잘라 결론이 달라지게 하지 않는다. 긴 발언도 핵심 조건은 쉽게 찾을 수 있게 한다.

향후 발언 작성은 [에이전트 작성 가이드](../research/guides/research-agents.md)를 따른다. UI가 난해한 프롬프트 출력을 매번 임의 번역하는 구조로 해결하지 않는다.

아래 값은 [공통 디자인 표준 적용표](visual-design.md)에 따른 현재 연구 UI 기본값이다.

| 항목 | 기본값 |
| --- | --- |
| 작업 영역 폭 | 가용 폭 전체, 상위·중첩 작업 컨테이너의 고정 최대 폭 금지(v0.4.1). 2026-09-14 현재 연구 UI 적용 |
| 바깥 여백 | 넓은 화면 40px, 중간 24px, 작은 화면 16px |
| 여백 단위 | 4 / 8 / 12 / 16 / 24 / 32 / 48px |
| 본문 | 16px, 줄 높이 1.6; 본문은 카드 안쪽 전체 폭 |
| 보조 문구 | 14px; 핵심 상태를 작은 각주로 숨기지 않음 |
| 제목 | 화면 28px, 영역 20px, 카드 16–18px |
| 카드 | 내부 여백 24px(작은 화면 16px), 반경 12px; 중첩 카드는 최소화 |
| 조작 요소 | 높이 40px(작은 화면 44px); 파란색 키보드 초점 표시 |
| 큰 화면 | 서비스 사이드바 280px(1024–1199px: 240px); 작업 지도·상세는 1400px부터 240px + 가변 폭 |
| 좁은 화면 | 1024px 미만 서비스 탐색 접기; 연구 영역별 탭, 작업 지도·상세 한 열 |

연구 판단·대화·Atlas 답변·자료 탐색 설명을 포함한 본문에 고정 최대 폭을 두지 않는다. 카드 안쪽 여백을 제외한 전체 폭을 사용한다.

본문은 한글 단어 단위로 줄을 바꾸고 URL·긴 식별자는 넘치지 않게 줄바꿈한다. 페이지가 기본 스크롤을 담당한다. 목록 내부 스크롤이 꼭 필요하면 영역과 제목을 명확히 하고 긴 본문에 이중 스크롤을 만들지 않는다.

색상은 기존 `--bg`, `--card`, `--ink`, `--muted`, `--line`, `--accent`, `--soft`, `--warn`, `--warn-bg` 변수를 공통 사용한다. 성공·선택·경고의 의미를 혼용하지 않는다. 상태는 색상과 글자를 함께 사용하고 밝은·어두운 화면 모두에서 읽을 수 있게 한다.

동일 요소는 공통 스타일을 수정한다. 파일 끝에 같은 선택자를 반복해서 덮어쓰지 않는다. 좁은 화면에서는 정보 중요도를 유지하며 열 배치만 바꾼다.

## 상호작용

- 긴 목록은 검색·필터·접기를 제공하되 최근 판단과 중요한 차단 조건은 기본으로 보인다.
- 자동 갱신은 선택한 단계·회차·펼침·검색·스크롤·키보드 초점을 유지한다.
- 연결이 끊기면 마지막 정상 자료와 그 시점을 보존한다. 오래된 자료를 현재 실행 결과처럼 표시하지 않는다.
- 비어 있는 경우를 구분한다: 아직 없음 / 검색 결과 없음 / 불러오기 실패 / 공개 대기.
- 동작하지 않는 버튼은 만들지 않는다. 조회 전용 화면에는 “실험 시작” 같은 실행 버튼을 놓지 않는다.
- 실행·승인 기능을 추가할 때는 대상·효과·필요한 조건을 보여주고 권한은 서버에서도 확인한다.
- 제목 계층, 버튼·탭·목록의 의미, 초점 표시를 유지한다. 키보드만으로 탐색·펼침·탭 이동이 가능해야 한다.

## 작업 회차 카드 · 첫 구현

연구 과정 상단에 시작 순서가 고정된 회차 목록을 둔다. 최근 시작한 회차가 위에 있다. 단계는 카드의 분류로 표시하고 번호를 단계 진척률처럼 사용하지 않는다. 펼친 내부는 요약 → 진행 과정 → 산출물 순서다.

작업 종료·실패와 개발 검토 대기·수정 요청을 따로 표시한다. 기존 단계 지도는 아래에 유지한다. 회차가 없는 기존 프로젝트에서 과거 실행을 새 회차로 만들어 표시하지 않는다. 실제 실행 여부와 원문 도구 결과의 자동 추적은 별도 연결 대상이다.

접힌 회차 카드는 넓은 화면에서 펼침 표시·단계·제목·상태를 한 줄에 배치한다. 내부 여백은 상하 8px·좌우 16px, 제목 16px, 조작 영역 최소 44px로 한다. 767px 이하에서는 제목·상태를 다음 줄로 내려 긴 제목과 검토 상태를 자르지 않는다.

공통 패널은 기본 내부 여백 16px, 영역 사이 간격 16px을 사용한다. 접힌 상세는 위 여백 8px·내부 위 여백 4px으로 구분한다. 진행 조건은 별도 제목·설명·펼침 행을 쌓지 않고 한 개의 펼침 요약에 조건과 안내를 표시한다. 진행을 막는 조건은 접혀 있어도 보이며 원래 이유·필수 행동은 펼쳐 확인한다. 표시할 조건이 없으면 빈 안내 패널을 만들지 않는다.

개발 검토 폼은 종료된 회차의 요약 다음에 둔다. 의견 입력과 계속 진행/수정 요청 두 행동을 제공하고 입력 중 내용은 회차별로 유지한다. 전송 불확실 시 원래 요청만 다시 확인하며, 과거 기록에서는 입력·제출·재확인을 막는다. 저장과 화면 갱신 결과를 구분한다. 버튼은 후속 흐름에 대한 검토이며 실행 버튼이 아니다.

후속 작업 계획은 근거가 된 회차의 개발 검토 아래 접힌 항목으로 둔다. 별도 수행 회차 번호를 붙이지 않고 계획됨·실행 전 또는 선행 작업 확인 필요를 표시한다. 사용자 수정 의견은 목적에 그대로 보존한다. 실제 실행 카드와 혼동되는 실행 중 배지를 사용하지 않는다.

## 메뉴 기준 갱신 · v0.4.2

데스크톱 버튼은 제품 행 오른쪽, 접힘 시 제품 아이콘 아래 20px에 배치한다. PanelLeftClose/Open 및 접근성·저장·모바일 동작의 구현과 검수는 [적용 기록](presentation-v042-sidebar-2026-09-14.md)을 따른다.

## 작업 회차의 진행 요약 · 2026-09-17

회차를 펼치면 목적 → 결과 요약 → 다음 행동 → 선택 이유 → 남은 문제 순서로 표시한다. 대화·도구 사용·이전 작업과 산출물은 각각 기본 접힘으로 두고 원문을 보존한다. 개발 검토는 결론이 있고 review_required가 참이며 review_status가 pending인 경우에만 사용자 확인 필요로 안내한다.

검사 결과의 목표 표시는 진행 가능 / 보완하며 진행 / 해당 판단 보류다. 실제 검사 범위·결과 기록이 연결될 때만 표시한다. 기존 개발 검토 허용이나 실행 종료를 검사 통과로 변환하지 않는다. 보완 담당과 실제 실행 근거가 없으면 에이전트 보완 중으로 추정하지 않으며, 일반적인 미해결 문제를 사용자 확인 요청으로 바꾸지 않는다. 담당·검사 결과의 구조화 연결은 후속 개발이다.

## 자료 처리 현황 · 2026-09-17

‘자료와 근거’ 상단에서 Documents→Atlas 인계 기록을 제목 중심의 접힌 행으로 표시한다. 제목/DOI/목적 검색과 전체·처리 중·확인 필요·정리 완료 필터를 제공한다. 펼친 내용은 목적→다음 행동→접수/정리/사용 검토 상태→원문 주소→접힌 접수 식별자 순서다. 정리 완료를 연구 사용 채택으로 표시하지 않는다.

프로젝트의 `.document-handoff/journal.sqlite3`를 읽기 전용 API로 조회하며 파일이 없으면 생성하지 않는다. 빈 상태와 읽기 실패를 구분하고 조회 실패 시 마지막 화면을 유지한다. 60초 UI 조회는 Pilot 로컬 기록 확인이며 Atlas 원격 이벤트 조회기가 아니다. 과거 HEAD에서는 최신 처리 목록을 숨긴다. 원문 주소는 HTTP(S)만 허용한다. 실제 접수/업로드·결과 원문 조회는 후속 어댑터 연결 대상이며 작동하지 않는 버튼은 두지 않는다.
