## 2. 필수 방향과 Pilot 배치 권고

### 공통 방향

- 좌측: 원본 기관 로고 → 제품 심볼·Pilot → 현재 연구·전환 → 서비스 탐색 → 하단 화면 모드.
- 우측: 현재 위치 → 연구 제목·필요한 주요 행동 → 현재 작업·판단 요약 → 연구 내부 탐색 → 선택 영역 본문.
- 기관·제품을 별도 전폭 상단 헤더에 반복하지 않습니다.
- 사이드바는 서비스 범위, 본문 탐색은 선택 연구 범위입니다. 연구 미선택 시 선택·생성 화면을 보여주고 전용 탭을 기본적으로 숨깁니다.
- 현재 상태는 의미와 문구를 함께 표시하며 연결됨을 연구 실행·단계 완료의 의미로 사용하지 않습니다.

### research view 권고

현재 작업·실제 실행 여부·최근 판단과 한계·다음 행동을 짧은 요약으로 먼저 유지합니다. Atlas 대형 목록·질답·연결 상세가 이 요약과 단계 탐색 위에 계속 쌓이지 않게 합니다.

연구 내부 탐색은 `연구 진행 / 자료·Atlas / 산출물` 같은 역할 분리를 권고합니다. 이는 기능을 새로 만들라는 요구가 아니며 실제 존재하는 기능에 맞춰 이름과 수를 조정하세요. Atlas와 관련된 판단의 중요한 한계는 해당 판단 가까이에 남기고, 전체 자료·질답·연결 상세를 별도 영역으로 옮깁니다.

`연구 진행`에서는 현재 작업을 바로 선택할 수 있게 하고 Pilot 기존의 `내용 / 에이전트 대화 / 확인할 문제 / 근거 / 승인·인계` 계약을 유지합니다. 긴 그래프와 전체 단계를 먼저 통과해야 대화에 도달하는 구조를 피하고, 요약의 `대화 보기`가 현재 선택 작업·회차의 대화로 직접 이어지게 합니다. 작업 선택은 중간 폭에서 드롭다운·접이식 목록으로 줄여, 280px 서비스 탐색 옆에 또 하나의 고정 288px 열을 무조건 두지 않습니다.

자동 갱신·탭 전환·모드 전환 뒤에도 선택 작업·회차·펼침·검색·스크롤·초점을 보존하세요. 대화 영역을 매번 다시 마운트하여 읽던 위치를 잃지 않도록 확인합니다. 과거 회차·미공개 독립 의견·원문과 쉬운 해설의 구분은 기존 계약대로 유지합니다.

| 항목 | 기준 |

## 5. Pilot 파비콘 권고

**제안한 흰색 방향 나침반을 권고합니다.** 자료 탐색과 연구 방향을 잡는 Pilot의 역할에 맞고, 기존 표·문서·체크·그래프 심볼과 구별할 수 있습니다.

- 고정 배경 `#007F70`, 흰 심볼 `#FFFFFF` 두 색만 사용.
- 32 × 32 도면, 배경 반경 8, 심볼 최대 22 × 22 및 사방 최소 5 여백.
- 한 방향을 읽을 수 있는 단순한 바늘·방향 실루엣. 북쪽 글자, 미세 눈금, 여러 바늘, 민트 장식은 제외.
- 선형이면 2.5–3 두께. 중앙 음각은 배경 녹색으로 표현 가능.
- 파비콘과 사이드바 Pilot 제품 아이콘에 같은 심볼 사용.
- 시스템이 어두워져도 배경을 밝은 녹색으로 바꾸지 않음. 기관 CI는 별도로 유지.
- SVG 원본 및 필요 시 ICO 16·32·48px를 생성하고 실제 탭에서 식별성을 확인.

Presentation 공통 폴더와 Pilot 작업 사본의 favicon·pilot SVG 파일명 조사에서는 전달할 Pilot 전용 원본을 찾지 못했습니다. 따라서 이 인계는 심볼 방향과 제작 규격의 권고이며 완성 SVG 전달이나 시각 검수 완료를 뜻하지 않습니다. Pilot 담당자가 기존 아이콘 체계를 활용해 제작하고, 라이브러리 심볼을 쓴다면 그 출처·라이선스도 프로젝트 방식대로 보존하세요.

## 6. 화면 모드 필수 계약

기본은 시스템 설정입니다. 수동 옵션을 제공하면 `시스템 설정 / 밝게 / 어둡게`를 사이드바 하단에 둡니다. 시스템 설정 선택값을 현재 표시 중인 light/dark로 덮어 저장하지 않고 OS 변경을 새로고침 없이 반영합니다. 수동 선택 중에는 OS 변경이 이를 덮어쓰지 않습니다.

공통 모드 가이드의 전체 역할표를 사용하세요. 특히 밝은 화면 버튼 `#007F70`+흰 글자, 어두운 화면 버튼 `#58D5BD`+`#10271F` 글자, 어두운 링크 `#74DECA`, 포커스 `#73C9FF`를 구분합니다. 기존 하나의 accent가 링크·버튼 배경·버튼 글자 역할을 모두 맡았다면 역할별로 분리하세요.

팝오버·입력·차트·툴팁·코드 영역도 같은 모드를 따라야 합니다. 원문 이미지·PDF·기관 CI는 반전하지 않습니다. 저장 실패·초기 진입·페이지 전환에서 입력을 잃거나 화면이 번쩍이지 않는지 확인하세요. 인쇄·보고서 출력은 화면 모드와 독립적으로 밝은 출력 기준을 유지합니다.

## 7. 완료 확인과 인계 범위

Pilot 담당자가 실제 제공 중인 research view에서 다음을 확인하세요.

1. 처음 진입했을 때 현재 작업·실제 실행 여부·최근 판단·다음 행동·대화 진입을 찾을 수 있음.
2. Atlas 자료가 길거나 비어 있거나 연결 실패해도 단계·대화 탐색이 밀려 사라지지 않음.
3. 연결·실행·의견·정식 단계 완료, Atlas 원문 확인과 Pilot 직접 확인을 구분함.
4. 판단에서 해당 대화·출처로 이동하고 원래 작업·회차로 돌아올 수 있음.
5. 자동 갱신·모드 전환·탭 전환 후 입력·선택·펼침·읽던 위치 유지.
6. 320·390·768·1280·1440px, 200% 확대, 두 모드, 키보드에서 겹침·가로 넘침·가려진 탐색 확인.
7. 실제 서버의 로고·WOFF2·파비콘 로딩, 배포 라이선스 동봉, 최신 탭 아이콘 확인.

코드·자동 검사·실제 서버·브라우저 검수 결과를 구분해 기록하고, 기존 U1–U7의 미완료 기능을 스타일 변경 완료로 처리하지 마세요. 별도 승인 질문을 반복하기 위한 단계는 추가하지 않습니다.
