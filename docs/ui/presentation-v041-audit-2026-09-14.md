## 후속 적용 단위

1. 전체 폭: 외곽·탭·목록·상세·검토 폼의 상한을 정리한다. 긴 문단에만 읽기 폭을 남긴다. 표는 내부 스크롤, flex/grid 자식은 min-width:0을 확인한다.
2. 메뉴: 기존 모바일 모달과 데스크톱 접힘 선택을 분리한다. 펼침/접힘 저장, 아이콘 이름·설명, 하단 설정 접근, 포커스 이동, Escape 및 화면 경계 전환을 검수한다. 메뉴 전환이 연구 API를 호출하지 않게 한다.
3. 상태 보존: 현재 탭·선택 작업·필터·질문 초안·검토 초안·펼친 대화·스크롤·과거 기록 선택을 유지한다. 실제로 없는 차트 확대 기능을 검수 통과로 세지 않는다.

## 수락 검수표

- 밝게/어둡게 × 1280/1920/2560px × 데스크톱 메뉴 펼침/접힘. 다섯 연구 영역의 제목·탭·본문·중첩 작업 패널 실측과 캡처를 남긴다.
- 320/390/768px에서 페이지 가로 넘침 없음. 넓은 표·탭의 내부 스크롤과 모바일 탐색 접근 확인.
- 접기 전후 선택·필터·입력·스크롤·대화 상태 보존, 포커스 복귀, 설정 저장 실패와 재진입 확인.
- 사용 중인 표·차트·대조 패널과 원문 비율을 각각 확인. 해당 기능이 없으면 해당 없음으로 기록.
- 실제 연구 쓰기를 차단한 브라우저로 확인하고 정적 제공 코드·검사 데이터 HEAD·뷰포트·측정값을 증거에 남긴다. 이번 기준 인계로 연구 회차나 M1 상태를 바꾸지 않는다.

## 전체 폭·모바일 넘침 수정 완료 — 2026-09-14

`styles.css`에서 page-tools/research-view 1280px, project-header 960px, episode-review와 decision-limits 작업 영역의 800px 상한을 제거했다. Atlas 답변은 실제 p.prose이므로 개별 문단의 800px 읽기 폭을 유지했다. 메뉴 동작·원문 이미지·데이터·API는 수정하지 않았다.

모바일 넘침 원인은 Atlas 답변 제목 h4의 긴 경로와 해시였다. 좁은 제목 상자 밖으로 이어지는 텍스트에 overflow-wrap:anywhere를 적용했다. 320px에서 document.scrollWidth가 635px에서 320px로 줄었고 탭의 내부 스크롤만 남았다. 페이지 overflow를 숨겨 해결한 것이 아니다.

검증:

- 두 모드 × 320/390/768/1280/1920/2560px × 5개 영역 60조건: 가로 넘침 0. 1920px 본문 1560px, 2560px 본문 2200px; 펼친 메뉴와 여백을 제외한 공간을 채운다.
- 같은 브라우저에서 탭·모드·크기를 바꿔도 Atlas 질문 초안 보존. 기존 상태/탐색 브라우저 검사 60항목 통과(초안·펼친 대화·새 스냅샷·모바일 포커스·모드 전환 등). 회차 UI 단위 검사 13개 통과.
- 실제 8771 서버가 제공하는 CSS를 사용하고 API view는 읽기 전용 고정 응답으로 검수. 브라우저 쓰기 요청 0. 캡처의 넓어진 패널을 직접 확인했다. 사용자 브라우저는 새로고침해야 기존 CSS 캐시가 갱신될 수 있다.
- 증거: `output/evaluations/pilot-ui-full-width/measurements.json`, `light-1920-after.png`, `dark-1920-after.png`, `state-regression/verification.json`.
- 재실행: `PLAYWRIGHT_MODULE=/path/to/playwright PILOT_UI_VIEW=/path/to/view.json node scripts/ui/check_full_width.cjs`.

남은 차이: 데스크톱 접기/펼치기·64px 레일·저장 복원·접힘 상태 검수, 중간 화면 메뉴 경계, 차트 조작/원문 비율에 대한 별도 검수. 이번 변경은 전체 폭과 재현된 넘침 수정 단위의 완료이며 v0.4.1 전체 적용 완료가 아니다.
