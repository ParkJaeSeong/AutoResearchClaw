# UI 검수와 적용 목록

## UI 변경의 완료 기준

다음 사용자 시나리오와 변경에 관련된 자동 검사를 확인한다. 통과하지 못한 항목은 결과 보고에서 구분한다.

- 처음 보는 사람이 현재 작업·실행 여부·다음 행동을 첫 요약에서 찾는다.
- 판단 하나에서 해당 에이전트 의견과 근거로 이동하고 돌아올 수 있다.
- 의견이 바뀌었다면 이전 의견과 변경 이유를 찾는다.
- 자료만 찾은 상태와 읽고 검토한 상태를 구분한다.
- 미해결 문제 때문에 무엇을 보류하며 무엇은 계속할 수 있는지 이해한다.
- 되돌아간 작업의 이유와 실제 이력을 확인한다.
- 새로고침과 자동 갱신 후 선택·검색·펼침·읽던 위치가 유지된다.
- 과거 회차를 볼 때 최신 요약이 그 회차의 결론으로 오인되지 않는다.
- 1440px·768px·390px 폭, 밝은·어두운 화면, 긴 제목·본문에서 겹침·가로 넘침을 확인한다.
- 키보드로 주요 탐색과 대화·근거 확인이 가능하다.
- 빈 자료·연결 실패·미공개 의견이 서로 다른 안내로 표시된다.
- 실제 실행 서버가 수정된 파일과 데이터를 제공하는지 확인한다. 브라우저 확인을 못 했다면 완료 보고에 명시한다.

문구·스타일 수정은 관련 기존 테스트와 시각 확인을 사용한다. 새 상호작용이나 상태 규칙에는 필요한 회귀 검사를 추가한다. 문구 문자열 검사만으로 사용성을 검증했다고 하지 않는다.

## 현재 UI와 기준의 차이 — 2026-09-11

아래는 코드와 최근 수정 기록 기준이다. 이번 가이드 작성에서 화면을 다시 구현하거나 전 시나리오를 검증하지 않았다.

| 순서 | 남은 작업 | 완료 증거 |
| --- | --- | --- |
| U1 | 연결 상태와 실제 에이전트 실행 상태를 분리하고 현재 작업·다음 행동을 한 요약으로 정리 | 실행 중·대기·연결 끊김을 서로 구분하는 화면 |
| U2 | 별도 탐색 자료와 정식 단계 기록의 연결을 표시 | 자료는 있는데 “작업 없음”으로만 보이는 혼란 해소; 연결 근거 확인 |
| U3 | 공통 문구·상태 이름을 한곳에서 관리 | 원시 상태 코드가 기본 화면에 노출되지 않고 같은 상태는 같은 표현 사용 |
| U4 | 대화의 쉬운 해설을 대상 회차·원발언에 연결 | 과거 기록과 최신 해설의 혼용 방지, 원문 이동 |
| U5 | 실제 되돌림과 판단 변경을 작업 지도·목록에서 추적 | 근거 부족으로 돌아간 이유와 이후 판단 확인 |
| U6 | 누적 CSS 덮어쓰기를 공통 규격으로 통합 | 세 화면 폭·두 테마에서 관련 화면 확인 |
| U7 | 결론 버전별 피드백 접수·영향 판단·반영 이력과 자율 진행을 연결 | 무응답에도 허용 작업 진행; 피드백으로 바뀐 결론과 이유 추적 |

U1–U7은 작업 순서이며 제품의 연구 단계 번호가 아니다. 각 작업은 공통 기준을 적용하고 확인한 뒤 다음으로 넘어간다. 급한 화면 수정이 있어도 이 목록과 관계를 남긴다.
