# UI 검수와 적용 목록

## 2026-09-15 재검토 진행 기준 표시

준비와 인계의 작업 기록·예산 아래에 실제 재검토 횟수와 “횟수로 제한하지 않습니다. 부족한 근거와 다음 행동을 기준으로 판단합니다.”를 표시한다. 기존 회차와 한도 이력은 보존한다. 정책·반복 검사 오류는 필요한 다음 행동으로 안내한다. 새 레이아웃이나 실행 버튼을 추가하지 않았다. UI 기존 검사 22개와 운영 8771의 008 회차·정책 표시·최신 HEAD 일치를 확인했다. 브라우저 오류·검수 쓰기는 0건이며, 화면·검증 기록은 `.superpowers/research/2026-09-10-polymer-sdl/return-policy-20260915/`에 있다.

## UI 변경의 완료 기준

다음 사용자 시나리오와 변경에 관련된 자동 검사를 확인한다. 통과하지 못한 항목은 결과 보고에서 구분한다.

- 처음 보는 사람이 현재 작업·실행 여부·다음 행동을 첫 요약에서 찾는다.
- 판단 하나에서 해당 에이전트 의견과 근거로 이동하고 돌아올 수 있다.
- 의견이 바뀌었다면 이전 의견과 변경 이유를 찾는다.
- 자료만 찾은 상태와 읽고 검토한 상태를 구분한다.
- 미해결 문제 때문에 무엇을 보류하며 무엇은 계속할 수 있는지 이해한다.
- 되돌아간 작업의 이유와 실제 이력을 확인한다.
- 새로고침과 자동 갱신 후 선택·검색·펼침·읽던 위치가 유지된다.
- 과거 회차를 볼 때 최신 요약이 그 회차의 결론으로 오인되지 않는다.
- 1440px·768px·390px 폭, 밝은·어두운 화면, 긴 제목·본문에서 겹침·가로 넘침을 확인한다.
- 키보드로 주요 탐색과 대화·근거 확인이 가능하다.
- 빈 자료·연결 실패·미공개 의견이 서로 다른 안내로 표시된다.
- 실제 실행 서버가 수정된 파일과 데이터를 제공하는지 확인한다. 브라우저 확인을 못 했다면 완료 보고에 명시한다.

문구·스타일 수정은 관련 기존 테스트와 시각 확인을 사용한다. 새 상호작용이나 상태 규칙에는 필요한 회귀 검사를 추가한다. 문구 문자열 검사만으로 사용성을 검증했다고 하지 않는다.

## 현재 UI와 기준의 차이 — 2026-09-11

아래는 코드와 최근 수정 기록 기준이다. 이번 가이드 작성에서 화면을 다시 구현하거나 전 시나리오를 검증하지 않았다.

| 순서 | 남은 작업 | 완료 증거 |
| --- | --- | --- |
| U1 | 연결 상태와 실제 에이전트 실행 상태를 분리하고 현재 작업·다음 행동을 한 요약으로 정리 | 실행 중·대기·연결 끊김을 서로 구분하는 화면 |
| U2 | 별도 탐색 자료와 정식 단계 기록의 연결을 표시 | 자료는 있는데 “작업 없음”으로만 보이는 혼란 해소; 연결 근거 확인 |
| U3 | 공통 문구·상태 이름을 한곳에서 관리 | 원시 상태 코드가 기본 화면에 노출되지 않고 같은 상태는 같은 표현 사용 |

| U5 | 실제 되돌림과 판단 변경을 작업 지도·목록에서 추적 | 근거 부족으로 돌아간 이유와 이후 판단 확인 |

U1–U7은 작업 순서이며 제품의 연구 단계 번호가 아니다. 각 작업은 공통 기준을 적용하고 확인한 뒤 다음으로 넘어간다. 급한 화면 수정이 있어도 이 목록과 관계를 남긴다.

## 2026-09-13 Presentation 공통 UI 적용

사용자 문제는 기능이 추가될 때마다 자료·연결 섹션이 앞에 쌓이고, 제품 사이의 디자인이 달라지는 것이었다. Presentation 담당에게 최신 표준·기관 로고·라이선스 포함 웹폰트를 받고, 현재 `research view` 전체를 공통 사이드바와 다섯 연구 영역으로 정리했다. [디자인 인계와 독립 검토](presentation-handoff-2026-09-13.md), [최신 적용표](visual-design.md)에 기준·예외·코드 위치를 기록했다.

검토자가 지적한 실행 상태 분리와 모바일 대화 접근을 반영했다. 실시간 관측 데이터가 없는 상태를 연결됨에서 추정하지 않고 명시했다. 모바일은 반복 머리말을 줄이고 판단 제목 아래에 기록·대화 링크를 둔다. 탭이 넘치면 좌우 이동 안내를 표시한다.

검수 결과:

- UI 단위 검사 36개: 기존 기록·원문 안전 표시·독립 공개·과거 시점·파일/질문 입력·불확실한 접수 재시도와 결정 연결 보존.
- Python 서버/Atlas 연결 검사 20개: 정적 제공·허용 경로·연결 동작 회귀.
- 브라우저 검증 60항목: 다섯 영역 전환, 질문 초안·열린 대화 유지, 판단→대화→뒤로 가기, 새 스냅샷 갱신, 탭 키보드 탐색, 시스템/수동 모드·잘못된 저장값, 작은 화면 탐색·Escape·초점 순환/복귀·배경 제한, 정적 자산/글꼴 로딩.
- 밝게·어둡게 각각 320·390·768·1280·1440px, 각 영역에서 페이지 가로 넘침 없음. `CSS zoom: 2` 배치 점검도 통과했다. 이는 브라우저 메뉴의 실제 200% 확대 검수와 구분한다.
- 실제 연구 서버 `http://127.0.0.1:8771/`를 새 정적 경로로 다시 실행하고 Orca 내장 브라우저에서 새 화면·실제 판단을 확인했다. UI 콘솔 오류 없음. 실제 연구를 쓰는 POST 없이 검수했다.
- 연구 HEAD는 디자인 변경 전후 동일하다. M1 단계·연구 판단·Atlas 자료실은 이 작업에서 변경하지 않았다.

Presentation 최종 이미지 재검토에서 남은 필수 수정 없음으로 확인했다. 결과 파일은 `output/evaluations/pilot-ui-design/verification.json` 및 같은 폴더의 화면 이미지다.

재실행: `PLAYWRIGHT_MODULE=/path/to/playwright PILOT_UI_VIEW=/path/to/read-only-view.json node scripts/ui/check_research_design.cjs`. URL 기본값은 8771이며 `PILOT_UI_URL`로 지정한다. API GET의 고정 자료를 사용하고 모든 POST를 차단한다. 스크린샷·검증 결과는 `PILOT_UI_OUTPUT`(기본 `/tmp/pilot-ui-design`)에 기록한다.

U6의 공통 스타일을 v0.3으로 갱신하고, U1의 상태 구분·첫 요약과 U4의 대화 접근을 개선했다. 실시간 실행 관측, 새 피드백 기능, M2/M3 기능 전체나 U1–U7 전체 완료를 뜻하지 않는다. 기존 단일 ROOT 제품의 연구 선택/생성 기능은 이번에 추가하지 않았으며 비동작 메뉴를 만들지 않았다. 별도 구형 `m1_ui`는 적용 대상이 아니다.

## 2026-09-13 세 스킬을 적용한 UI 문구 정리

`ux-writing`, `humanizer`, `humanize-korean`으로 현재 연구 UI와 이전 M1 UI의 제목·상태·설명·오류 안내를 검토했다. 서버가 제공하는 문헌 탐색 안내도 함께 수정했다. 연구 원문과 실제 발언은 표시 그대로 보존했다.

- 내부 용어를 사용자의 행동으로 풀었다. 예: 개정 선택 → 기록 버전, 현재 인계 게이트 → M2로 넘기기 위한 조건.
- 단계 진행 코드의 의미를 먼저 설명하고 원래 코드·조치 정보는 펼침 영역에 보존했다. 알 수 없는 조건은 임의로 번역하지 않았다.
- 질문 전송과 불확실한 접수 확인의 버튼 이름을 상태에 맞게 구분했다. 같은 요청 키로 재확인하는 동작은 유지했다.
- UI 검사 54개, 서버·화면 데이터 검사 22개 통과. 질문 초안·원문 표시·미공개 의견·과거 기록의 저장 제한·재시도 요청 동일성을 확인했다.
- 변경 대조 및 의미 보존 점검: `_workspace/2026-09-13-001/changes.json`, `copy-audit.json`, `final.md`.

한국어 윤문 스킬의 문체 진단은 편집 참고로만 사용했다. 원문 보존, 부정·불확실성·행동의 의미는 직접 대조했으며 AI 판별 정확도나 사용자 이해도 향상을 수치로 주장하지 않는다. 스킬에 언급된 `verify_change_rate.py`가 설치 묶음에 없어 정적 한국어 문자열의 어절 차이를 로컬에서 계산했다.

최종 화면 검수에서도 브라우저 60항목을 통과했다. 밝게·어둡게 320–1440px에서 가로 넘침이 없었고, 실제 8771 화면을 새로 고친 뒤 콘솔 오류가 없었다. 검사 중 연구 쓰기 요청은 없었으며 연구 HEAD `f085ff7e3fcb8c4ae2bf2e3f4df96483b3abfe3cdb9c26f0fa40be8368e6f529`가 유지됐다. 브라우저 검증 결과는 `output/evaluations/pilot-ui-copy/verification.json`에 보관했다.

## 2026-09-13 작업 회차 첫 구현

- 단계와 시작 순서를 분리한 카드, 요약·진행 과정·산출물, 별도 개발 검토 상태를 연구 과정에 연결했다.
- 합성 프로젝트에서 실제 HTTP/브라우저 10개 검사 통과: 세 카드 순서, 펼침, 키보드 작동, 1440·768·390px 및 밝게·어둡게. 페이지 오류와 브라우저 쓰기 요청은 0건.
- 신규 회차 Python 18개, 기존 viewer/views/CLI 15개, UI/Atlas/discovery Node 40개 통과. 새 상태 running의 라벨 불일치를 독립 검토에서 발견해 회귀 검사 후 수정했다.
- 화면 증거: `output/evaluations/work-episodes/`. 실제 연구 HEAD는 서버 갱신 전후 동일하다. UI 조회 서버 8771에 새 정적 파일을 반영했다.
- 현재 화면은 명시적으로 등록한 공개 보고를 보여준다. 자동 실행 연결·브라우저 검토 제출·상세 지연 조회·새 작업 알림·Markdown 출판은 아직 미구현이다. 전체 UI 재설계나 로딩 성능 개선 완료가 아니다.

- 실제 프로젝트 `/api/view` 단일 조회는 17.108초, 2,149,186바이트였다. 초기 응답을 요약으로 줄이고 상세를 분리하는 후속 성능 작업이 필요하다. 단일 측정이며 원인 분석·개선 완료는 아니다.
