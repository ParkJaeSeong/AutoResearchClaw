## Critical actual-path findings

1. **Gate wrapping can erase failure semantics.** Input-not-found returns early (`executor.py:615`–627), but executor exceptions, missing outputs, and PRM rejection first become FAILED (`executor.py:670`, 680, 753). The later gate branch has no `result.status == DONE` guard: with auto-approval off, it replaces any result with BLOCKED_APPROVAL and decision `block`, retaining only the error/artifacts (`executor.py:772`–788). This can also overwrite a stage implementation's PAUSED result. Runner stops BLOCKED_APPROVAL only when `stop_on_gate=True` (`runner.py:845`); its default is False (`runner.py:440`). Therefore the default direct runner, or HITL CLI path, can continue after a substantive gate failure. Normal semi-auto CLI sets stop=True, full-auto sets auto-approve=True (`cli.py:210`–220); HITL explicitly selects auto=False, stop=False (`cli.py:319`–322). This is a conditional control-flow defect, not a claim every CLI run bypasses gates.
2. **Transition-table behavior is not orchestration behavior.** `stages.py:252` defines transitions, gate rollback mappings are at 118–123, and retry/status transitions at 189–203. Production search finds only `executor.py:652` calling `advance`, for START, discarding its output. Actual runner stops on REJECTED (`runner.py:837`–843); it does not call the helper's REJECT rollback. Actual APPROVE hook returns the previous result unchanged (`executor.py:383`–384), so BLOCKED_APPROVAL need not become DONE. `max_retries`, DoD, and error codes are contract fields (`contracts.py:18`–25), not generic runner enforcement. Failure simply stops (`runner.py:821`–825). Stage-specific internal retries exist separately.
3. **Post-hook state and persisted state can disagree.** `decision.json` and `stage_health.json` are written before post-stage HITL (`executor.py:799`–819). REJECT, ABORT, SKIP, or collaboration can alter the returned result afterward (`executor.py:386`–428), without that wrapper rewriting metadata. Human EDIT returns without output revalidation (`executor.py:396`–398). Pre-stage SKIP returns DONE before directory creation/input/output validation or metadata (`executor.py:231`–237, 605–610), and the runner can checkpoint it (`runner.py:660`). These are trace/validation gaps even where skipping is intentionally authorized.
4. **Caps can force scientific continuation.** Pivot/refine cap is hard-coded to 2 (`stages.py:134`). Consecutive empty metrics force continuation (`runner.py:707`–716). At cap, failed `_check_experiment_quality` only writes `quality_warning.txt`; paper writing continues (`runner.py:779`–813). Stage-15 result remains its original pivot/refine decision; no durable explicit forced-proceed decision replaces it. Agent-mode requirements have a separate one-retry cap (`stage_impls/_analysis.py:828`): a repeated reject becomes proceed with a persisted adverse verdict (`_analysis.py:1097`–1135). These policies conflict with treating unmet prerequisites as unsatisfied, and should not be copied as Pilot return policy.
5. **Resume is positional, not artifact-validating.** Checkpoint stores stage number/name/run ID/time and optional HITL state (`runner.py:78`–104), with atomic replacement. `read_checkpoint` simply returns the following enum stage (`runner.py:126`–143), without artifact hashes, outputs, approvals, config version, or pending rollback validation. Last-stage completion and missing/invalid checkpoint both yield None; `resume_from_checkpoint` then defaults to stage 1 (`runner.py:146`–151), as does CLI `--resume` when no next stage is returned (`cli.py:329`–346). A completed run can therefore restart.
6. **Rollback crash window and input selection threaten correctness.** DONE stage 15 is checkpointed before rollback decision handling (`runner.py:660`, 699). A crash after this checkpoint but before recursive progress resumes at stage 16, potentially skipping the requested pivot; moving stage directories makes this worse. `_read_prior_artifact` scans *all* stage directories, including later stages and snapshots, and does not check stage status or producer/run lineage (`_helpers.py:398`–422). Empty input files and empty input directories satisfy presence checks. Version sorting uses negative version under reverse sorting, so when live output is absent, `_v1` wins over `_v2`; it is not latest-version fallback. Re-entry can consume stale downstream or failed-stage artifacts.
7. **Execution bounds are incompletely preserved.** `to_stage` is checked after checkpoint and before stage-14 diagnosis/repair, heartbeat, or stage-15 pivot handling (`runner.py:663`–697). A partial run ending at stage 14 skips that repair hook; ending at stage 15 skips requested rollback. Recursive pivot execution does not forward `to_stage` (`runner.py:762`–773), so a caller's later stop boundary can be exceeded. No ordered from/to range validation appears in this runner.

## Missing observability modules / API mismatch

Repository file inventory (`rg --files researchclaw`) found no `researchclaw/pipeline/event_log.py`, `researchclaw/cost_tracker.py`, `researchclaw/pipeline/experiment_spec.py`, or `researchclaw/pipeline/pitfall_detector.py`. Runner references all four (`runner.py:463`, 510, 554/564, 584), catching exceptions and continuing (`469`, 515, 559/578, 598). Therefore those advertised hooks are not functioning from this checked-out package as written. External import-path augmentation was not tested.

`ExperimentMemory` exists, but constructor requires `store, retriever, embed_fn` (`memory/experiment_memory.py:24`–29), while runner passes `store_dir=` (`runner.py:477`). Initialization fails and is swallowed. The runner further expects `ExperimentOutcome`/`record_outcome` (`runner.py:604`, 611), which are absent in the inspected module. Existing separate memory APIs must not be confused with this disconnected runner hook. Even if wired, its current payload uses zero defaults and generic topic/config (`runner.py:606`–620), not complete experimental provenance.

## Trace preservation risks

- `decision.json`, stage-health, pipeline summary, checkpoint, decision-history, and iteration context use current paths; most overwrite and are not append-only (`_helpers.py:326`, `executor.py:812`, `runner.py:71`, 1575–1592, 1624). Atomic checkpoint protects torn replacement, not history.
- Automatic rollback snapshots only target through stage 15 (`runner.py:1298`–1303). Existing same-number snapshot is deleted (`1307`–1308). Paper reruns 16 onward are not versioned by iterative wrapper (`1707`–1715). Manual re-entry also lacks generic snapshot invocation.
- Best-result promotion copies analysis/metrics/figure plans and replaces chart directory (`runner.py:1455`–1472), useful for paper consistency but current paths are mutable and original per-attempt relationships require preservation separately.
- Heartbeat writes only after DONE (`runner.py:695`–697), so it is stage completion telemetry, not continuous liveness during long stages. `to_stage` exits before it.
- Generic end event, if module supplied, labels all non-DONE statuses STAGE_FAIL (`runner.py:542`). Missing module means no such event ledger at all in this tree.

## Reuse recommendation for Pilot comparison

Reuse the separation of declared inputs/outputs, preflight and postflight hooks, explicit PAUSED/FAILED outcomes, atomic durable recovery metadata, per-attempt evidence preservation, targeted domain validators, repair context, and independently recorded review verdicts. Preserve these capabilities when replacing the 23-stage flow; the count/order itself need not survive.

Do not inherit failure→approval status conversion, forced scientific proceed on cap, unsigned filename-based prior-artifact selection, implicit restart of completed runs, post-hook metadata disagreement, fixed counts as acceptance criteria, or best-effort observability represented as guaranteed. Pilot should supply equivalent checks through its graph/work packet/return acceptance path with explicit version-bound evidence and actual caller integration; this report alone does not certify that those equivalents currently exist.
