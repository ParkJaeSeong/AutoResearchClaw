## 필요한 UI 수락 조건

- 하나의 작업에 단계 ID, 시도 ID, 부모/되돌림 연결, 입력 버전, 현재 대기 사유를 공통으로 표시한다.
- 요청 접수, 외부 응답 대기, 역할별 실행 시작/종료, 공개 가능한 발언, 검사 실패, 재작업, 복구, 채택/보류를 발생 순서로 기록하고 화면에서 재구성한다.
- 독립 의견 내용은 공개 장벽을 유지하되 각 역할의 시작/진행/완료는 즉시 표시한다. 비공개 추론을 기록하려는 요구가 아니다.
- 서버 연결, 워커 생존, 연구 진행을 구분한다. 영속 기록과 화면 갱신 기준을 통일하거나 별도 원장의 revision을 명시한다.
- 새로고침·재시작·프로젝트 전환 후 같은 순서/상태로 복원한다. 늦게 온 이전 프로젝트 응답이 현재 프로젝트를 바꾸지 않아야 한다.
- 작업 종료·결과 검토·연구 판단 채택·마일스톤 완료를 구분한다. 검사 미통과를 완료 배지로 감추지 않는다.
- 실제 브라우저에서 지연 응답·실패·반복·재개가 포함된 한 경로를 관찰한다. DOM 단위 테스트만으로 완료 선언하지 않는다.
