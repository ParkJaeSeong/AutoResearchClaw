# AutoResearchClaw Codex 개발 현황

기준일: **2026-09-08**

코드 기준: `b4d4be2` (이 문서를 추가하기 전 GitHub `main`)

이 문서는 현재 구현·검증·설치된 범위와 아직 결정하거나 개발해야 할 작업을 구분한 시점별 현황이다. 이후 변경은 Git 이력과 최신 검증 기록을 함께 확인한다.

## 1. 현재 위치

**연구 파이프라인은 23단계 중 15단계까지 지원하며, 16단계부터는 미구현이다.** 다만 단계별 지원 범위에는 아래 제한이 있다. 단계 수는 개발 공수나 연구 품질의 달성률이 아니다.

앞 단계의 다중 에이전트 보완은 별도 작업이다. 첫 단위 **A—공통 역할 정의와 읽기 전용 조회**를 구현·검증·설치했고, 사용자 테스트도 확인했다. 다음 **B—7~9단계 실제 협의 연결**은 7단계부터 설계 논의를 시작했지만 아직 구현하지 않았다.

| 구분 | 현재 상태 |
| --- | --- |
| 기존 연구 파이프라인 | 1~15단계 구현, 지원 범위 제한 있음 |
| 논문 작성 이후 | 16~23단계 미구현; 계약 이름의 존재는 실행 지원을 뜻하지 않음 |
| 공통 역할 안내 A | 구현·독립 리뷰·회귀 검사·메인 반영·설치 갱신 완료 |
| A 사용자 테스트 | 7단계 조회, 역할 안내 해석, 16단계 거부 확인 |
| 실제 협의 연결 B | 7단계 상세 설계 논의 중, 코드 변경 없음 |
| 연구 내용 품질 | 실제 연구에서의 타당성·유용성 입증은 별도 과제 |

## 2. 개발 원칙

- 연구 해석·판단·대안 선택은 현재 Codex의 에이전트가 수행한다.
- Python CLI는 형식, 근거 연결, 파일 해시, 진행 절차, 권한과 예산을 검사하고 상태를 보존한다.
- Codex-native 경로에는 외부 LLM API 키 요구나 별도 모델 실행 프로그램을 추가하지 않는다. 보존된 포크 원본 코드 전체가 제거·전환됐다는 뜻은 아니다.
- 중요한 연구 판단은 서로 독립된 관점을 거쳐야 한다. 역할 이름이나 생산자 문자열만으로 실제 독립 실행을 인증하지 않는다.
- 사용자 승인과 실행 확인은 에이전트 협의로 대체하지 않는다.
- 기존 완료 프로젝트·승인·불변 증거를 자동 수정하거나 새 규칙으로 재판정하지 않는다.
- 형식 검사 통과, 점수 개선, 에이전트 수를 과학적 타당성의 증명으로 취급하지 않는다.

| 6 | 구조화된 지식 추출 | 구현. 승인된 문헌의 주장·근거 추출과 출처·접근 수준 기록 |

| 23 | 인용·참고문헌 검증 | 미구현 |

### 지원 범위에서 주의할 점

1~11단계는 일반 단계 명령을 사용하지만, 12~15단계는 각 단계의 전용 실행 전달·등록 프로토콜을 사용한다. 모든 단계가 같은 명령이나 자동 실행 방식으로 동작하지 않는다.

10단계의 실행 가능한 v2 경로는 제한된 수치 회귀 패키지다. CSV 하나, 선언된 스칼라 특성과 목표값, 학습 데이터만으로 학습, 분리된 데이터 구획, 승인 단위의 MAE 등을 지원한다. 일반적인 임의 Python 실행 환경이나 모든 종류의 연구 실험을 지원하는 것은 아니다. 보존된 v1 경로는 정적 계획용이며 정책 근거형·실험실형의 10단계 패키지는 아직 지원하지 않는다.

13단계는 세 판단 역할의 기록과 응답을 거치고 최소 두 개의 일치 권고 규칙을 유지한다. 14단계는 방향 투표가 아니라 분석 종합이다. 15단계는 세 최종 권고가 모두 같아야 합의로 등록하며, 불일치는 미해결로 남긴다.

## 4. 이번에 완료한 A

다음 명령으로 프로젝트를 생성하거나 열지 않고 역할 안내를 조회한다.

```sh
researchclaw-codex roles describe --stage 7 --json
```

- 지원 범위: 1~15단계.
- 제공 내용: 역할 ID, 책임, 단계별 필수 질문, 판단 기준, 권한 제한.
- 출력 표식: `schema_version: 1`, `protocol_version: 1`, `activation: guidance_only`.
- 미지원 단계·잘못된 입력: 오류 메시지와 종료 코드 2로 거부.
- 조회 자체는 에이전트 실행·협의 기록 등록·프로젝트 상태 변경을 하지 않음.

| 적용 단계 | 안내하는 논리적 역할 구성 |
| --- | --- |
| 1·2·3·5·7·8·9·14·15 | 분야·방법론·비판 및 재현성의 세 판단 역할 + 비투표 조정자 |
| 4·6·11·12 | 작업자 + 독립 확인자 |
| 10·13 | 세 판단 역할 + 비투표 조정자 + 평가·승인과 분리된 구현 담당 |

전체 15개 프로필에 54개 논리적 역할과 108개 필수 질문이 있다. 이는 동시에 54개 에이전트를 실행한다는 뜻이 아니다.

**A만으로 앞 단계가 실제 다중 에이전트 협의 방식으로 전환되지는 않는다.** 특히 7단계의 `existing_protocol: single_author_validation`은 기존 지원 방식을 나타낸다. `mode: judgment_council`은 안내하는 역할 구성이며 해당 프로젝트의 독립 검토 완료 증거가 아니다.

## 6. 남은 에이전트 보완 작업

| 단위 | 범위 | 현재 상태 |
| --- | --- | --- |
| A | 공통 역할 정의·읽기 전용 조회 | 완료 |
| B | 7→8→9단계 실제 독립 검토·협의·등록 연결 | 7단계 설계 논의 시작, 구현 전 |
| C | 5·6·10단계 독립 검증 연결 | 미착수 |
| D | 1~4·11~12단계 보완 | 미착수 |
| E | 13~15단계 역할 지침·실행 출처 기록·사용자 요약 정비 | 미착수. 기존 협의 기능은 이미 구현돼 있음 |

### 바로 다음 개발 대상: B-1, 7단계

추천 방향은 기존 14단계의 독립 검토·응답·종합 방식을 참고하되, 7단계에 필요한 부분만 적용하는 것이다. 모든 단계를 한꺼번에 공통 엔진으로 바꾸지 않는다.

설계할 내용은 다음과 같다.

1. 독립 판단 → 전체 제출 후 공개 → 한 차례 응답 → 종합의 실제 기록 형식.
2. 검토 대상 초안·최종 문서와 기록을 묶는 해시, 수정 시 재검토 범위.
3. 검토 누락·미해결 이견·근거 부족일 때의 진행 조건과 사용자 보고.
4. 결론·근거·관점 차이·한계·다음 행동을 보여주는 읽기 쉬운 요약.
5. 이전 완료 프로젝트와 새 협의 프로토콜 프로젝트의 구분.
6. 실제 독립 Codex 역할로 수행하는 작은 성공·협의 불성립 수용 검사.

**아직 확정하지 않은 적용 정책:** 새 프로젝트에는 새 방식을 기본 적용하고, 기존 프로젝트는 유지하되 7단계 미완료 프로젝트만 명시적으로 전환하게 할지 사용자에게 제안한 상태다. 승인된 구현 요구사항으로 간주하지 않는다.

B-1의 기록 경로·버전·진행 조건 등 상세 설계와 구현 계획은 아직 작성·승인되지 않았다. 외부 LLM API 호출이나 자동 점수로 연구 결론을 결정하는 방향은 채택하지 않는다.

## 7. 미완료 품질 과제와 보존 항목

- 실제 연구 내용이 좋은지 사용자가 쉽게 확인할 수 있는 단계별 산출물·요약 표시를 보완해야 한다.
- 모순된 근거, 상관과 인과의 혼동, 반증 불가능한 가설, 데이터 누출 등의 사례에서 에이전트의 지적과 최종 수정이 타당한지 별도로 평가해야 한다.
- 합성 예제나 형식 검사 통과를 실제 분야 연구의 타당성·성능 입증으로 확대해서는 안 된다.
- 원본 포크 기능을 Codex-native 방식으로 계승하는 작업은 계속 남아 있다. 현재 지원 범위를 넘어선 자율 논문 완성 시스템으로 보고하지 않는다.
