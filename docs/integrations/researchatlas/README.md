# Pilot–ResearchAtlas M1 연결 검토

자료 수집의 새 설계 방향은 [직접 수집 흐름](direct-collection-flow-2026-09-13.md)을 참고한다. Zotero 제안은 철회되어 [아카이브](../../../archive/legacy/2026-09-13-design-reset/docs/integrations/researchatlas/zotero-collection-flow-2026-09-13.md)로 옮겼다. 아래 기존 계약·구현 기록은 그대로 유효하며 새 제안의 구현 여부와 구분한다.

검토일: 2026-09-13. 상태: **현재 코드 검토 및 인터페이스 제안**. API 구현·배포·실제 Pilot 통합 호출 시험을 완료했다는 문서가 아니다.

## 판단

현재 Atlas HTTP API와 MCP는 보유 지식 검색·조회, 기존 입력의 ingest, 질문 위임과 상태 조회를 제공한다. M1 전체 줄거리를 연결하려면 **자료 접수 → 지정 자료 분석 → 근거를 포함한 결과 반환**을 보완하고 Pilot의 협의 기록에 연결해야 한다.

사용자가 정정한 최신 역할 분담을 기준으로 한다.

- **Pilot:** 연구 질문과 자료 탐색·확보, 분석 의뢰, 결과의 연구 적합성 판단, 독립 검토·교차 검토, 가설·설계·실행 준비·인계.
- **Atlas:** 전달받은 자료의 원문 추출·분석·비교·위키 축적, 보유 지식 조회·질답, 미확인 범위와 추가로 필요한 자료 안내.
- Atlas 검색은 자료실 조회다. 외부 근거를 발견·확보하는 작업은 Pilot이 연결된 수집 도구로 수행한다. Atlas 분석을 받았다고 Pilot이 원문을 직접 읽었다고 기록하지 않는다.

## 공동 v1 최종화

[Pilot 최종 검토](pilot-review-v1.md)에서 R1–R6 해소와 v1 최종 수용을 기록했다. 정확한 경로·필드·오류는 [Atlas 규범 본문](/Users/jspark/orca/projects/ResearchAtlas/docs/integrations/researchpilot/api-mcp-v1.md)을 따른다. Atlas는 생산자 API·MCP 본문과 예제를, Pilot은 시나리오·소비자 계약을 소유한다. 최신 방향은 기존 jobs에 kind=analyze 확장, 별도 analysis ID/worker 없음, 자료실 고정 instance ID 제공이다. 일반 project=null은 유지하며 기본 프로젝트 요구는 Pilot M1 운영 규칙이다. 계약 본문 대조·구현·배포·공동 시험 완료는 별개다.

현재 사실과 제안을 분리했다. 신규 경로·도구·필드는 합의할 계약 초안이며 현재 호출할 수 있는 명령이 아니다. API와 MCP를 각각 별도 실행기로 만들지 않고 같은 도메인 서비스와 작업 ID·중복 방지 규칙을 공유한다.

## 개선안 반영

[Atlas의 검토·개선안](/Users/jspark/orca/projects/ResearchAtlas/docs/integrations/researchpilot/m1-api-mcp-review-2026-09-13.md)을 반영했다. 기존 job·QA·queue를 재사용하고 A1 원형·근거 반환부터 시작한다. 접수 후 source 참조는 선택적이며, 변환 연결 A2b를 추가했다. QA 원형/현재 처리 상태의 차이와 페이지의 YAML 포함 전체 파일 해시·본문 표현의 차이를 명시했다. 프로젝트 생성·ID 연결은 별도 설계 제안이며 Atlas가 승인하거나 구현했다는 뜻은 아니다.

이 역할 분담은 이번 연계 흐름에 적용한다. Atlas의 기존 wiki-discover 기능 제거를 요구하지 않는다.

## M1 줄거리와 책임

| 장면 | Pilot | Atlas | 연결 상태 |
| --- | --- | --- | --- |
| 1. 연구 접수·프로젝트 연결 | 기존 연구 재개 또는 생성, 목표·제약 정리, Atlas ID 연결 | 기존 지식 프로젝트 조회·재사용 또는 생성 | 목록/페이지 조회 가능; 생성·자료 연결 API 보완 |
| 2. 질문 선택 | 후보 질문 비교·선택 | 관련 지식 검색·질답 | 현재 조회 활용 가능 |
| 3. 근거 확보 | 외부 탐색·파일 확보·전달 | 접수·중복/버전 관리 | 서비스 자료 접수 공백 |
| 4. 자료 분석 | 목적·대상 지정, 결과의 사용 범위 판단 | 추출·조건 분석·자료 간 비교 | 목적과 자료를 함께 고정하는 계약 공백 |
| 5. 가설 초안 | 같은 근거 묶음으로 독립 검토 | 분석 결과·근거 제공 | 결과 회수와 입력 묶음 연결 보완 |
| 6. 반론·수정 | 공개 후 교차 검토, 추가 근거 탐색 | 후속 분석·미확인 안내 | 분석/QA/쟁점의 이전 기록 연결 보완 |
| 7. 실험 설계 | 변수·측정·분석·실패 처리 결정 | 관련 방법과 적용 전제 분석 | 지정 자료 분석 계약 재사용 |
| 8. 실행 준비 | 실제 장비·재료·자원·권한 증거 검증 | 전달된 설명서·방법 자료 분석 | 현장 준비 판단은 Pilot 책임 |
| 9. 예행 검토 | CSV·환경·실패/복구 경로 점검 | 추가 문헌 질문 지원 | Atlas 완료가 준비 완료를 대신하지 않음 |
| 10. M1 마감 | 최종 검토·M2 수신 의무와 인계 | 사용한 지식·분석 버전 보존 | Pilot 인계에 정확한 Atlas 참조 연결 |

## 반복의 종료와 재개

Atlas가 부족한 항목과 판단 영향을 반환하면 Pilot은 추가 탐색, 주장 범위 축소, 보류, 실험 질문 중 하나를 선택한다. 새 근거 없이 같은 요청을 반복하지 않는다. 자료 개수나 임의 실행 시간으로 연구 완료를 정하지 않는다.

검토 회차의 근거는 고정한다. 새 자료·새 분석은 다음 입력 묶음으로 편입하고, 영향받는 가설·설계만 재검토한다. 각 장면에서 결론·이유·남은 문제·다음 행동을 보여준다. 사람의 피드백은 관련 결론에 연결하되 매 회차의 필수 실행 승인이 되지는 않는다.

현재 실제 연구의 쟁점·준비 상태·예산·M1 완료 여부는 이 문서 작성으로 변경하지 않았다.
