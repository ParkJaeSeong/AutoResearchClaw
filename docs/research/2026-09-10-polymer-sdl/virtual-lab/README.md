# 가상 실험실과 CSV 전달 설계

장비 모델은 나중에 지정한다. 지금은 **사람이 압출기·사출기·전기전도도 측정기·UTM을 운전하고 CSV로 결과를 전달하는 흐름**을 설계한다. 실제 장비가 있다는 사용자 설명은 반영하되 모델·성능·자동 제어 가능성은 추정하지 않는다.

현재 후속 버전은 [CSV v2와 로컬 검증기](v2/README.md)다. 아래는 보존한 v1 양식과 당시 설계다.

이번 v1 산출물은 작업·데이터 전달 양식과 합성 예시다. 장비 시뮬레이터, 물성 예측 모델, CSV 자동 업로드·검증 기능을 구현한 것은 아니다. 실제 연구 기록에 합성 예시를 등록하지 않았다.

## 작업 흐름

계획 작성 → 작업자에게 지시 → 작업자 착수 확인 → 수동 제조·측정 → CSV 전달 → 파일·조건 확인 → 사용 가능한 결과 해석 → 다음 실험 제안.

Pilot은 계획과 실제 수행을 구분한다. 작업자가 조건을 바꾸면 계획값과 실제값을 함께 남긴다. 파일이 도착했다고 실험 성공이나 가설 검증 완료로 처리하지 않는다. 필요한 입력이 빠지면 해당 결과의 해석만 보류하고 작업 기록은 보존한다.

| 가상 장비 | 담당 작업 | 연결할 산출물 |
| --- | --- | --- |
| VIRTUAL-EXTRUDER | 배합 재료의 압출·혼련 | 투입 배합 → 혼련 배치, 계획·실제 공정 조건 |
| VIRTUAL-INJECTION | 사출·시편 제작 | 혼련 배치 → 제조 배치 → 시험별 시편 |
| VIRTUAL-CONDUCTIVITY | 전기전도도 측정 | 시편·방향·접촉 회차·측정법·결과 |
| VIRTUAL-UTM | 기계적 물성 시험 | 별도 시편·시험법·결과, 가능하면 원시 시험 곡선 |

전기전도도를 현재 가설 검토의 중심으로 유지하고 기계적 물성을 추가 평가 축으로 둔다. UTM의 시험 종류·규격·속도·형상은 미정이다. 전기시험과 기계시험은 같은 제조 배치의 별도 시편으로 연결한다. 같은 배치에서 나온 여러 시편은 독립 제조 반복이 아니다. Raman은 이번 가상 기본 구성에 포함하지 않으며 구조 기작의 직접 판정은 보류한다.

## CSV 네 종류

| 파일 | 한 행의 의미 | 빈 양식 | 합성 예시 |
| --- | --- | --- | --- |
| tasks.csv | 작업 하나와 현재 수행 상태 | [작업 양식](templates/tasks.csv) | [작업 예시](examples/tasks.csv) |
| specimens.csv | 제조 배치에서 나온 시편 하나 | [시편 양식](templates/specimens.csv) | [시편 예시](examples/specimens.csv) |
| conditions.csv | 작업의 조건 하나: 계획값과 실제값 | [조건 양식](templates/conditions.csv) | [조건 예시](examples/conditions.csv) |
| results.csv | 시편의 측정 시도에서 얻은 지표 하나 | [결과 양식](templates/results.csv) | [결과 예시](examples/results.csv) |

작업 지시서는 tasks의 계획·작업·시편 식별자와 conditions의 계획값을 묶어 제공한다. 작업자는 상태·담당자·실제값·결과를 채워 전달한다. 양식은 UTF-8 BOM, 쉼표 구분, 소수점 `.`을 사용한다. 숫자와 단위는 별도 열이며 미상은 빈칸으로 둔다. 빈값을 0으로 해석하지 않는다.

### 공통 식별자와 값

- `schema_version`: 현재 `1`. `data_origin`: `synthetic` 또는 `real`. 수신 시 필수이며 누락을 real로 보충하지 않는다.
- `plan_id`, `task_id`: 계획 버전과 작업. `equipment_id`는 현재 가상 장비 이름이며 실제 장비 지정 때 매핑한다. 작업 ID를 재사용해 이전 파일을 덮어쓰지 않는다.
- `input_batch_id`, `output_batch_id`: 투입·생성 배치. 최초 배합은 별도 배합 명세로 정의해야 하며 예시의 DEMO-MIX-01은 가상 시작 재료다.
- `specimen_id`, `manufacturing_batch_id`: 시편과 제조 배치. 시험 작업의 투입 배치와 시편의 제조 배치가 일치해야 한다.
- `status`: `planned`, `in_progress`, `completed`, `failed`, `cancelled`. completed는 작업자가 수행 종료를 보고한 상태이며 결과 사용 승인과 다르다.
- `operator_id`: 실제 수행 담당자. 계획 단계는 비울 수 있으나 실제 수행 기록에는 필요하다.
- `parameter`, `planned_value`, `actual_value`, `unit`: 조건명·계획·실제값·단위. `value_status`는 `provided`, `unknown`, `not_applicable`. 조건 종류별 필수 항목·단위는 장비·시험법 결정 후 명세화한다.
- `measurement_id`: 지표 행의 고유 ID. `attempt_id`: 측정 시도 ID. 한 시도의 여러 지표는 같은 attempt_id를 사용한다. 재시도는 새 attempt_id를 사용한다.
- `metric`, `value`, `unit`: 결과 지표·값·단위. 예시는 electrical_conductivity(S/cm)와 tensile_strength(MPa)이며, 인장시험 채택이나 단위 자동 환산을 의미하지 않는다.
- `quality_status`: `unverified`, `valid`, `below_limit`, `invalid`, `missing`. valid는 파일 제공자의 선언이며 Pilot의 검증을 대신하지 않는다. 한계 이하 값은 숫자로 대체하지 않고 해당 상태와 한계값·단위를 conditions에 기록한다.
- `method_id`, `direction`, `contact_cycle_id`: 방법 명세와 재료 방향·접촉 회차. UTM 등 해당하지 않는 열은 빈칸이며 이유는 notes에 기록한다. 실제 방법의 내용이 없으면 method_id만으로 정량 사용을 승인하지 않는다.
- `raw_file`: 제출 묶음 안의 상대 경로. 원시 CSV가 있다면 함께 전달한다. UTM의 원시 힘·변위·변형률 등 채널 정의는 나중에 확정하며 요약값만으로 곡선·파단 거동을 복원하지 않는다.
- `supersedes_measurement_id`: 오기 정정 시 대체 대상. 독립 재측정과 구분하며 원래 행·파일은 보존한다. `notes`에는 변경·실패·누락 이유를 남긴다.

## 수신 시 확인할 기준

1. 버전·필수 열·data_origin을 확인하고 실제값과 합성값을 분리한다. 혼합 파일을 자동으로 실제 연구 분석에 넣지 않는다.
2. 작업·시편·제조 배치·측정 참조를 확인한다. 중복 measurement_id의 내용이 다르면 충돌로 남기고 자동 덮어쓰기하지 않는다.
3. 수치 파싱·단위·방법·실제 조건·품질 상태를 확인한다. 누락을 임의 교정하지 않는다. 계획과 실제 조건이 다르면 영향받는 비교를 재판단한다.
4. 원시 파일이 지정됐다면 존재 여부를 확인하고 제출 묶음과 파일 해시를 보존한다. 경로가 제출 묶음 밖으로 벗어나면 읽지 않는다.
5. 제조 배치·시편·시도·접촉 회차의 반복 관계를 유지한다. 요약값만 있는 결과는 그 범위에서만 해석한다.

위 항목은 **구현할 수신 규칙**이며 자동 검사 기능의 완료 선언이 아니다. 비용·시간·안전 확인·사람 개입 이력 및 작업 상태 변경 이력은 이후 실행 기록 계약에 추가해야 한다. 이 네 CSV만으로 실제 착수 준비를 충족하지 않는다.

## 예시를 볼 때

예시의 장비·작업자·시편·결과는 모두 합성이다. 임의 전도도와 강도 값은 파일 연결을 확인하기 위한 값이며 물리 시뮬레이션 결과가 아니다. 예시의 completed는 가상의 종료 상태다. 미확인 조건이 남으므로 실측이었다 해도 그대로 가설 판정에 사용할 수 없다.

예시는 한 제조 배치의 두 시험 전달만 보여 준다. [실행 명세](../execution-spec.md)의 M0/M1·접촉·방향 대조 전체나 독립 반복을 충족하지 않으며, 다목적 최적화 성능도 평가하지 않는다.

다음 구현 단위는 **CSV 묶음을 읽어 연결·누락·합성 여부를 확인하고, 사용 가능 범위를 보여주는 가져오기 기능**이다. 그 뒤 작업자 상태 입력과 결과 화면을 연결한다. 6단계 정식 기록 연결은 [기존 남은 작업](../stage6-status.md)으로 유지한다.
