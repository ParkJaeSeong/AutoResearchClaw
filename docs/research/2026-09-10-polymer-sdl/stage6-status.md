# 6단계는 어디까지 끝났는가

**내용 검토와 후속 설계는 진행했지만, 6단계 정식 완료는 아직이다.** 이 사례의 6단계는 ‘근거 종합과 자료 사용 판단’이다. 실제 장비·예산·반복 수 확인까지 모두 6단계 완료 조건으로 늘리지 않는다. 그것들은 M1의 후속 실험 설계·착수 준비에 속한다.

| 구분 | 현재 상태 | 확인할 결과물 |
| --- | --- | --- |
| 현재 근거의 사용·보류 범위 | 여섯 항목 정리됨 | [근거 종합](stage6-synthesis.md) |
| 설명 후보·예측·약화 조건 | 세 역할의 실제 교차 검토 완료 | [가설 결론](hypothesis-review/decision.md), [대화](hypothesis-review/README.md) |
| 후속 실험 준비로의 연결 | 제조·측정 명세 v0.1 작성; 실행 준비 미완료 | [실행 명세](execution-spec.md) |
| 정식 입력과 단계 등록 | 이전 질문 참조와 수집·추출 등록 공백이 남음 | [현재 런타임 확인](stage6-status.json) |
| 6단계 완료 판단 | 미완료 | 등록·검토 연결 후 다시 평가 |

## 실제로 확인한 등록 공백

현재 등록된 노드는 scope·questions·search·screen이다. search와 screen의 questions 입력이 현재 질문 버전과 달라 `issue_reference_stale`가 발생한다. collect·extract·synthesize·hypothesize·review 노드는 등록되어 있지 않다. 원문 파일·검토 문서가 존재한다는 사실과 이 노드 등록은 별개다.

현재 `current_evidence` 조회는 오래된 참조에서 중단된다. 따라서 이것만 고치면 모든 완료 조건이 통과한다고 판단하지 않는다. 원본 상태를 수정하지 않고 확인했다.

## 6단계 완료에 직접 필요한 다음 작업

1. **검색·선정 입력 연결:** 기존 실제 검색 결과와 현재 사용 범위를 유지할지 검토하고, 최신 질문에 맞춘 검색·선정 개정안을 만든다. 단순히 이전 기록의 해시만 갈아 끼우지 않는다. 새 검색은 현재 결정을 바꿀 자료가 필요할 때만 한다.
2. **수집·추출 등록:** 승인된 사용 범위에 맞는 실제 원문·읽은 위치·주장·한계를 현재 기록에 연결하고 필요한 검증을 수행한다. 원문 발췌를 근거 추출 결과로 자동 간주하지 않는다.
3. **종합 등록과 완료 확인:** 여섯 판단을 정식 추출 근거에 연결하고 검토·미해결 처리·완료 조건을 평가한다. 사용자에 의한 ‘이번 5단계 마감’을 기존 시스템의 선정 승인으로 대신 기록하지 않는다.

공존 가능한 설명 후보를 구현의 ‘기각한 대안’ 필드에 억지로 넣지 않는다. 현재 가설 모델의 관계 표현과 대화 등록 연결은 별도로 검토해야 한다. 기존 22개 쟁점을 해결 처리하지 않는다.

이 순서는 **등록 수정의 작업 순서**이며 완료된 기록이나 실행 허가가 아니다. 실제로 필요한 승인 권한이나 추가 전제가 드러나면 해당 작업의 구체적 입력을 준비한 뒤 판단한다.

## 실험 준비에서 따로 남은 것

실행 환경, 원료·장비, 제조 설정값, 접촉·방향의 구현 가능성, Raman 감도·관측 범위, 의미 차이·반복 수·분석법, 비용·권한이 미정이다. H2의 참조 판정과 비교 선택법 명세도 별도다. 이 항목들을 6단계의 같은 자료 검토를 계속 반복해야 하는 이유로 쓰지 않는다.

이번 실행 명세는 조정자가 이전 에이전트 결론을 구체화한 것이며 새 에이전트 검토 완료로 표시하지 않는다. 실험은 수행하지 않았다.
