21개·16개·20개다. 검색어 연결 1건은 도구 기록과 일치하지 않아 미확인으로
남겼다. 상세 시점별 수치는 `.superpowers/research/2026-09-10-polymer-sdl/discovery-audit.json`에 기록했다.

## 이전 실행이 중간에 끝난 이유

`start_scope.py`, `review_questions.py`, `review_search.py`, `review_screen.py`는
각각 한 노드와 그 협의만 실행하고 종료한다. M1 전체 실행기가 아니다.
UI의 01–09는 내부 노드 번호이고, `ready`는 그 노드의 검토 조건 충족이다.
`complete`는 협의의 필수 제출 완료다. 어느 쪽도 전체 연구 완료가 아니다.
화면은 읽기 전용이므로 다음 에이전트를 자동으로 실행하지 않는다.

조정자가 매 노드마다 대화를 끝낸 것은 이 개별 실행 방식을 사용했기 때문이다.
실제 corpus 승인 같은 정책 조건과, 조정자의 임의 단계별 중단을 구분해야 한다.

## 변경한 실행 방식

`researchclaw.codex.literature_loop`는 다음을 한 번의 실행으로 이어간다.

1. 소재·방법론·SDL/반증 역할의 독립 웹 탐색.
2. 같은 이전 회차를 세 역할에 공개하고 출처·반례·누락을 교차 확인.
3. 근거가 부족하면 다음 회차에서 직접 재검색.
4. 후보 검토 상태 또는 예산 도달과 미해결 쟁점을 기록.

실시간 웹 검색을 설정하고 실제 CLI 웹 호출을 검사한다. 웹 호출 기록은 실행의
증거이며 논문별 해석을 독립 검증했다는 증거는 아니다. 읽은 범위는 역할의
선언으로 보존한다. 원문을 못 읽은 후보도 접근 실패와 함께 남긴다.
DOI 기준 중복을 합쳐도 역할별 읽은 범위·해석 차이는 삭제하지 않는다.
초기 입력에서 동료 의견은 제외한다. 격리는 여전히 instructions_only다.

첫 실행 예산: 최대 3회차, 역할별 회차당 600초. 논문 수 상한은 없다.
예산 종료는 충분성이나 M1 완료가 아니다. 상태/부분 로그를 보존하며, 같은 출력
디렉터리를 덮어쓰지 않는다. 후속 회차는 남은 검색 질문을 이어받아 실행한다.

## 실행과 확인

```sh
.venv/bin/python -m researchclaw.codex.literature_loop \
  --host /Users/jspark/.local/bin/codex \
  --output .superpowers/research/2026-09-10-polymer-sdl/discovery-runs/restart-01 \
  --topic '고분자 복합소재 물성 예측을 위한 가설 검증형 자율 연구 에이전트와 셀프 드라이빙 랩 설계'
```

출력: `status.json`, `reports.json`, `sources.json`, 역할·회차별 실제
`events.jsonl`, `report.json`. 검색엔진 전체 결과 건수는 추정하지 않는다.
검색어·수집 후보·중복 제거 수를 구분한다. 큰 실행 원문은 Git에서 제외한다.

기존 frozen-evidence council은 등록 자료의 협의용으로 유지한다. 탐색은 이 새
실행 경로가 담당하며, 결과를 후속 native 검색/선정 개정에 연결한다. 새 탐색
로그가 저장됐다는 이유로 과거 5편의 승인이나 원문 검증을 생성하지 않는다.
전체 M1의 수집·추출·가설·검증·인계 자동 실행은 이 탐색 실행기와 별개다.
따라서 기존 연구 UI의 native 검색/선정 목록에는 아직 첫5편이 남아 있다.
새 탐색 결과는 실행 폴더에서 확인하며, 대조·선정 후 새 native 개정으로 연결해야 한다.
