# PC/CNT 선정·가설 교차 검토

2026-09-10. 우선23개 후보와 H1–H3 초안을 연구 질문의 새 개정으로 등록했다.
세 역할이 독립 의견 → 공개 반박 → 최종 판단의9개 실제 제출을 완료했다. 실제 제출은 기존 UI의
연구 질문 → 공개 대화에서 확인한다. 기존14개 쟁점은 보존하며 자동 해소하지 않는다.

## 별도 조건 변수 감사

검토 입력을 동결한 뒤 조정자가 공개 가공 CSV의 PC/CNT137행·16문헌ID를 추가 집계했다.
아래 결과는 이번 협의 초기 입력에 포함되지 않았다. 에이전트가 확인했다고 소급하지 않는다.

| 조건 | 전체 부분집합의 값 | 같은 문헌 안에서 값이 달라지는 문헌 수 |
| --- | --- | ---: |
| temperature | 23:128행, 230:8행, 270:1행 | 0/16 |
| log10(thickness) | 서로 다른12개 값 | 2/16 |
| ac | 전부0 | 0/16 |
| dc·four-probe·two-probe·impedance | 각각0/1, 활성 행 수5·16·6·20 | 각각0/16 |
| vol% | 서로 다른36개 값 | 10/16 |

숫자와 열 이름은 가공 CSV 그대로다. 온도의 단위, 0의 의미, 측정법 누락의
인코딩과 가공 규칙은 아직 원문과 대조하지 않았다. 원자료의 온도 개입이나
측정법 효과가 관측됐다는 뜻이 아니다.

이 집계는 H1을 문헌 분리 예측 성능 비교로 제한해야 할 이유를 강화한다.
조건 입력이 문헌 차이를 대리할 가능성을 감사해야 하며, 조건 변수의 인과 효과를
추정하는 설계로 해석할 수 없다. PC/CNT의 조성·필러 고정 값도 예측 입력으로서
정보가 없을 수 있으므로 충전율 기준선과 조건 추가 비교를 명확히 해야 한다.

로컬 집계: `.superpowers/research/2026-09-10-polymer-sdl/selection-hypotheses-01/condition-audit.json`.

## 최종 결과와 결정 경로

세 역할 모두 `ready_with_limits`를 제출했다. 현재 정책은 열린 major 쟁점을
진행 제한으로 처리하므로 노드 상태는 `ready=false / blocking_issue_unresolved`다.
대화 완료와 연구 질문의 다음 단계 통과는 다르다. 기존14개와 새8개를 합쳐22개
쟁점을 열린 상태로 보존한다. 독립 초기 의견의 중복 제기가 포함되어 새 문제8종을 뜻하지 않는다.

실제 입장 변화: 방법론 역할은 문헌 내 조건 변이 부재와 문헌 간 예측 비교 불가능을
구분했다. 소재·SDL 역할은 반박 단계 이후 이 구분을 명시적으로 수용했다.
소재 역할은 H3를 처음의 ‘유지’에서 평가 명세 ‘수정’으로 명확히 변경했다.
새로운 실증 자료 없이 합의를 가설 입증으로 표현하지 않았다.

- H1: 조건 정보의 추가 예측 가치와 평가 가능성부터 점검한다. 조건의 인과 효과나
  에이전트 효과로 확장하지 않는다. 모집단 변경은 명시적 질문 개정으로 다룬다.
- H2: 단독·복합 기전, 모든 후보 불충분과 판별 유보를 포함한다. 성공 사례만의 비용을
  비교하지 않고 전체 캠페인의 오판·미판별·비용을 함께 평가한다.
- H3: 동일한 검사 전 전체 제안에서 부적합 통과와 유효 제안 오거절을 함께 평가한다.
  실제 장비가 없는 현재는 모의 제약 평가 설계로 한정한다.

UI 상단 수정안은 조정자의 후속 정리이며 재심을 통과한 문구가 아니다.
검토받은 입력과9개 원문 제출은 연구 질문2차 개정에 그대로 보존했다.
새 입력으로 바뀐 연구 질문 때문에 이전 검색·선정 기록은 ‘재검토 필요’로 표시된다.
197개 탐색 후보가 삭제되거나 검색 실행을 잃어버린 것이 아니다.

검증: 호스트9개 응답과 native9개 제출을 대조했고, 첫 의견0개/반박 시3개/최종 시
초기3개·반박3개 공개 조건을 확인했다. 총 native 제출45개다. 이번 검토는 제공 자료만
사용하여 역할별 도구 호출0회이며, 새 원문 검색·모델 학습·물리 실험·corpus 승인은 없다.
모델은 CLI 기본 설정이고 서로 다른 모델의 교차 검증 여부는 확인되지 않았다.
격리는 instructions_only다. 600초 제한이나 ephemeral 실행은 사용하지 않았다.
