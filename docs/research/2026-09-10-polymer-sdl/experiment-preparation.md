# 실험 착수 준비 초안

2026-09-11 조정자가 [질문 4차 교차 검토](preprocessing-review.md)를 실행 준비 항목으로 정리했다. 에이전트의 새 합의나 승인 기록은 아니다. 실제 학습·실험은 수행하지 않았다. M1은 이 설계와 자원·권한·실행 전 확인까지 끝나야 완료된다.

## 이번에 정한 준비 범위

| 연구 질문 | 지금 준비할 것 | 착수 전에 충족할 조건 |
| --- | --- | --- |
| H1: 조건 정보가 새 문헌의 전도도 예측에 도움이 되는가? | 자료 사용표, 계보를 보존하는 분할 명세, 대응 비교 계획 | 목표값 단위·시료 대응·자료 사용권·유효한 평가군 확인 |
| H2: 가설을 구별하는 실험 선택이 자원을 절약하는가? | 경쟁 설명별 다른 예측과 필요한 관측 목록 | 관측오차와 구별 가능성, 측정 장비·자원·권한 확인. 현재 자료를 기전 정답으로 쓰지 않음 |
| H3: 실행 전 검사가 부적합 제안을 줄이는가? | 명시적 가상 제약과 고정 제안 집합을 사용하는 평가 설계 | 판정 기준·정답 작성 절차·분모·자원 상한 확정. 실제 장비 검증과 구분 |

H1–H3는 별도로 평가한다. 하나가 보류됐다는 이유만으로 다른 설계 작업을 막지 않는다. 평가 결과를 본 뒤 유리한 질문이나 모집단을 골라 성공으로 보고하지 않는다.

## 자료 사용 초안

| 자료 | 확보한 범위와 준비에 쓸 용도 | 보류하는 용도와 재개 조건 |
| --- | --- | --- |
| 공개 EC 데이터·상세표 | 저장된 원본의 해시와 버전을 묶어 수집 기록 준비. 열·시료·문헌 대응을 확인하는 입력 | 단위·권리·계보 확인 전 가설 평가용 학습 보류 |
| Abbasi 2010 원문 | §2.2·§2.6·그림12의 기존 읽기 기록으로 측정 명세와 교란 요인 정리 | 공정과 형상·두께가 함께 변하므로 배향만의 인과 정답으로 사용하지 않음. 23°C·최종 두께·단위 대응 미해결 |
| Takeda 2011 대응 14행 | 기존 비파괴 보류 목록 유지; 원본에서 삭제하지 않음 | 그림4와 시료·주파수 대응 확인 전 목표값 비교 보류. 나머지 123행도 자동으로 사용 가능 판정을 받지 않음 |
| 공개 그룹 생성 코드 | 고정 커밋의 코드 읽기 결과로 분할 위험 정리 | expt를 독립 실험실·배치로 간주하지 않음. 저자 연결·데이터 재사용 경계 확인 후 분할 확정 |

자료 수집 묶음은 연구 작업 공간의 `m1-preparation-intake.json`에 파일 해시와 기존 읽기 기록으로 연결했다. 이후 R1의 `m1.source.capture`로 기존 파일 5개를 정식 수집 기록에 등록했다. 결과는 `native-source-capture-receipt.json`에 보존했다. 사용 적합성을 판단한 것은 아니며, 현재 질문·검색·선정의 진행 조건이 충족되지 않아 기존 collect/extract 단계는 아직 미시작이다.

## H1 비교 명세 초안

- **예측 대상:** 사용 적합성이 확인된 PC/CNT의 전기전도도. 로그 밑과 원래 단위를 명시하고 변환 규칙을 먼저 고정한다. 현재 전체 데이터 단위는 미확정이다.
- **비교군:** 충전율 중심 입력과 조건 정보를 추가한 입력을 같은 학습기·학습 예산·분할에서 비교한다. 미상·대체값을 실측값처럼 쓰지 않는다.
- **분할:** 같은 시료 및 확인된 자료 재사용 관계를 양쪽에 나누지 않는다. 문헌 단위 평가와 공저자 연결을 보존하는 평가의 대상·한계를 구분한다. 기존 expt만으로 독립성을 선언하지 않는다.
- **학습 전 처리:** 결측 처리·스케일 변환·특성 선택·튜닝은 학습 부분 안에서 수행한다. 외부 평가값으로 처리법을 고르지 않는다.
- **주 지표 후보:** 문헌별 MAE의 두 비교군 간 차이. 문헌 가중치, 최소 의미 개선폭, 불확실성 추정 단위는 방법론 검토에서 실행 전에 고정한다. 현재 숫자 기준이 없으므로 성공 판정이나 학습을 시작하지 않는다.
- **반증·유보:** 무작위 분할에서만 개선되면 새 문헌 일반화의 근거로 삼지 않는다. 평가군 부족이나 식별 불가능은 판단 불가로 남긴다. 계산 실패를 제외한 성공 실행만 비교하지 않는다.

## H2·H3 설계에서 지켜야 할 비교 조건

H2는 무작위 선택·일반 능동학습/BO와 목적, 초기 정보, 접근 가능한 관측 및 자원 상한을 맞춘다. 복합 설명과 미판별을 허용하고 오판·미도달·실패·재시도·시편 준비·사람의 해석과 복구를 포함한다. 단가를 모르면 재료량·장비시간·노동시간·개입 횟수를 따로 기록한다. 독립 판정자의 의견만으로 기전 정답을 만들지 않는다.

H3는 검사 유무에 같은 제안 집합을 제공한다. 부적합 통과, 유효 제안 오거절, 판단 불가를 구분하고 전체 제안 수와 판정 가능 제안 수를 모두 보고한다. 유효 탐색 손실·처리량·추적성·복구 시간도 기록한다. 사람의 수정 전후 결과를 분리한다. 테스트용 예제가 동작한 것은 시스템 점검이며, H3를 평가하는 본 실행은 M2다.

## 실행 준비 상태

| 항목 | 현재 상태 | 담당 책임과 다음 산출물 |
| --- | --- | --- |
| 자료·사용권·측정 조건 | 필수 미확정 사항 있음 | 문헌·소재 담당: 자료별 허용 용도와 확인 근거 |
| 비교·성공·중단 기준 | 초안, 수치 기준 미확정 | 방법론 담당: 결과를 보기 전에 고정한 평가 명세 |
| 코드·환경 | 연구용 실행 환경 점검 전 | 실행 담당: 의존성 고정, 입력 검증, 학습 없는 입출력 점검 기록 |
| 예산·일정·장비·재료·안전·권한 | 연구 실행 범위 미확정 | 실행 담당: 작업별 필요 자원과 허용 범위. 불필요한 항목도 이유 기록 |
| 결과·실패·재개 | 명세 필요 | 실행 담당: 입력/코드/설정 버전, 시료 ID, 원결과, 오류, 재개 지점을 연결한 실행 묶음 |
| 정식 기록·검토·인계 | 현재 게이트 미충족 | 조정자: 아래 재개 기록의 구현 차이를 해결한 뒤 실제 등록·검토 |

위 담당은 책임 구분이며, 새 에이전트를 배정하거나 실행했다는 뜻은 아니다. **착수 가능: 아니오.** 필수 미확정 사항과 정식 기록의 진행 조건이 남아 있다.

R1 수집 등록 뒤 다음 작업은 [재개 점검](resume-check.md)의 R2다. 기존 쟁점이 실제로 영향을 주는 자료·주장·작업을 구분하고 그 판단을 이력으로 남길 경로를 마련한다. 같은 미해결 사항만 재확인하는 협의는 다시 열지 않는다.
