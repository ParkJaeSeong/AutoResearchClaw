# 선정 수정본 검토 완료

**검색·선정 검토를 마쳤다.** 이번 선정 이유에서 발견한 지적 네 개를 수정본과 실제 재검토로 확인해 해결했다. 기존 연구 쟁점 22개는 바꾸지 않았다. 정식 선정 검토 조회가 ready이며, 사용자에 의한 자료 사용 결정은 아직 등록하지 않았다.

## 확인한 수정

- PC/CNT137행·Abbasi25행의 출처를 저자 저장소와 Abbasi 원문에 귀속하고 NanoMine·OOD 자료의 참고 역할과 분리했다.
- 후보별 원래 탐색 내용·읽은 범위·한계를 선정 사유에 연결했다.
- 같은 URL 별칭은 포함된 대표 기록으로 연결하고 보류 이유를 남겼다.
- 가설 중심 선택의 반론 후보는 H2 비교군·참조 판정을 확정하기 전에 적용 범위를 확인하도록 재검토 조건을 남겼다. 반론이 없거나 해결됐다는 판단은 아니다.

세 역할이 독립 의견→상호 질문 응답→최종 재판단을 수행했고 모두 ready_with_limits였다. [실제 대화](selection-correction-dialogue.md)와 [검증·해결 확인 기록](selection-correction-receipt.json)에 연결했다. 지적 네 개는 같은 수정본·검토 묶음을 사용한 관련 문제이며 독립 실증 성공 네 건으로 세지 않는다. 원문 전체 검증·실험 준비 완료와 구분한다.

## 다음에 사용할 자료 범위

[자료 목록](search-reconnect.md)의 24개 기록을 현재 근거 검토의 수집·추출 대상으로 사용하고, 나머지 174개 기록은 후속 후보로 보존하는 안이다. 총198개는 논문·저장소·버전 식별자가 섞인 수이며 독립 논문 수가 아니다. 이 결정은 자료 사용 범위에 한정하며 모델 학습·장비 운전·물리 실험 승인이 아니다.

[수집·추출 연결 준비표](collection-registration-inputs.json)에 선정본의 정확한 참조와 24개 자료를 묶었다. 현재 정식 파일 보존에 바로 연결되는 자료는 저자 저장소와 Abbasi 원문이며, 나머지는 먼저 기존 탐색 작업 공간의 보존 파일을 확인한다. 과거 접근 신고와 지금 원문 파일을 확보한 상태를 구분하고, 새 검색이 반드시 필요하다고 가정하지 않는다.

현재 구현의 `m1.corpus.decide`는 정확한 선정본에 대한 명시적인 사용자 결정을 요구한다. 이전의 5단계 회차 마감이나 검토자의 진행 의견을 이번 선정본의 사용자 승인으로 기록하지 않았다. 이 24개 범위의 사용 결정 후 기존 자료를 연결해 수집·추출을 등록하며, 근거 종합 등록과 M1 완료 판단은 그 뒤에 남는다.

## 필요한 기록 경로 보완

실제 검증 작업의 범위·자원 선언을 등록하는 `verification.budget.register` 경로를 추가했다. 테스트에서만 임시 객체로 제공되던 필수 참조를 실제 프로젝트에서도 만들 수 있게 한 변경이다. 자원 할당·비용 승인·실험 실행·쟁점 해결을 자동으로 수행하지 않는다. 관련150개 검사와 독립 코드 검토의33개 집중 검사가 통과했다.

이번 해결은 원래 해소 조건을 고정한 검증 준비→수정본·실제 최종 발언 대조→결과 등록→독립 검토자 판단을 근거로 한 이슈 상태 변경 순서로 수행했다. 원래 지적·초기 수정 요청·수정본·재검토·검증 결과를 보존했다. 브라우저 시각 검수는 이번에 하지 않았다.
