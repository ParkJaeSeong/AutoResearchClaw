# Atlas 검토 작업의 원장 연결 수정

2026-09-15 · D4 후속 개발·기록 점검 · 작업 회차 007

**정상으로 저장된 Atlas 근거 검토 2건을 원장 계산기가 처리하지 못한 오류를 수정했다.** 검토를 다시 수행하거나 과학적 결론을 바꾸는 작업은 아니다. 장비 결정 유예를 유지하며 진행 가능한 기록 점검부터 수행했다.

## 원인과 수정

기존 원장 계산기는 일반 M1 노드 검토와 `issue_scope`, `source_analysis`를 지원했으나, 이후 추가된 `atlas-evidence-review`를 일반 노드 검토로 처리했다. 해당 검토는 Atlas QA와 연구 질문에 대한 용도 선언을 입력으로 사용하므로 대응하는 M1 노드 자료가 없다. `work_accounting._source`의 노드 자료 개수 검사에서 `work_source_invalid`가 발생했다.

Atlas 유형에 대한 명시적 경로를 추가했다. 당시 용도 선언의 정식 등록·바이트·식별자와 작성자를 확인하고, 그 등록 직전의 기록으로 QA 원형·버전·질문 참조를 다시 검증한다. 대화 준비와 발언도 각각의 당시 입력에서 검증해 담당자 구분·공개 순서·입력 고정을 확인한다. 이후 QA가 갱신됐다고 과거 검토를 지우거나 최신 내용으로 바꾸지 않는다.

허용 근거는 용도 선언에 연결된 QA와 질문의 정확한 참조여야 한다. 질문 누락·다른 참조 대입·원형 변조·등록 이벤트 변조는 거부한다. 미완료 토론을 완료 작업으로 세지 않으며, 보류와 수정 의견을 준비 완료 의견으로 바꾸지 않는다.

## 실제 기록 반영

- 기존 작업 기록 20건을 보존하고 확인한 Atlas 검토 2건만 `m1.work.record`로 추가했다.
- `work_ledger.refresh`로 22건을 연결했다. 중복 작업·가짜 노드·새로운 발언·물성 결과를 만들지 않았다.
- 되돌림 7회/기존 한도 3회, 검증 시작 4회/한도 10회를 유지했다. 실제 비용은 미확인으로 남겼다.
- UI 회차의 개발 진행 보고와 정식 검토 작업 원장은 구분한다. 파일을 작성하거나 개발 검토자가 코드를 읽은 사실만으로 새로운 과학적 검증 횟수를 더하지 않는다.

실제 명령의 입력 HEAD·명령 ID·접수 기록과 변경 상태 비교는 연구 폴더 `accounting-repair-20260915/`에 보존한다. 최종 원장 판단은 해당 폴더의 `verification.json`, 운영 화면 확인은 `ui-verification.json`에 기록한다.

## 검증

수정 전 동일한 오류를 재현하는 새 테스트 5개가 실패했다. 수정 후 새 Atlas 테스트 12개와 기존 비노드 검토 테스트 23개가 통과했다. 별도로 실제 Atlas 실행 경로와 같은 서로 다른 QA/질문 참조, 질문 누락·대체 거부 테스트 1개를 추가해 통과했다. 기존 인계·원장 회귀 5개, Atlas 협의 실행 회귀 5개도 통과했다.

별도 코드 검토자는 차단 문제 없이 수용했다. 검토 권고에 따라 서로 다른 질문 참조에 대한 영구 회귀 테스트를 보완했다. 그 검토는 코드 검증이며 연구 에이전트의 과학적 토론으로 표시하지 않는다.

## 남은 조건

원장 출처 오류와 별개로 `returns_exhausted`가 남는다. 과거 되돌림 7회를 줄이거나 기존 한도 3회를 몰래 올리지 않는다. 다음은 이 정책과 사용자가 요청한 자율 연구 범위를 대조해 조정안을 정리하는 일이다.

실제 장비·재료·측정 적합성·수치·반복·자원/권한은 [D4 입력표](d4-start-inputs-20260915.md)에 남아 있다. 이번 원장 수정으로 D4·M1 완료나 M2 실험 권한이 생기지 않는다. 장비를 결정하면 첫 입력 묶음부터 확인한다.
