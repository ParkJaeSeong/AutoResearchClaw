2026-09-15 원장 후속: [Atlas 검토 유형 누락 수정](accounting-repair-20260915.md)으로 `work_source_invalid`를 해소하고 실제 검토 2건을 연결했다. 되돌림 7회/한도 3회 정책은 바꾸지 않았다. 아래의 실제 준비 조건도 유지한다.

2026-09-15 입력표 작성: [D4 착수 준비표](d4-start-inputs-20260915.md)에 배치 v2·CSV 연결·14개 확인 항목을 반영했다. [입력 CSV](d4-start-inputs-20260915.csv)는 장비 결정 후 채울 작업표다. 아래 내용은 준비 범위 설명이며 실제 입력·검증 완료로 바뀐 것은 아니다.

현재는 **가상 실험 설계와 파일 전달 경로를 준비하는 단계**다. 6단계와 D1은 완료했으며 D2 구조 검토를 마쳤다. 실제 장비를 나중에 정하겠다는 기존 요청에 따라 아래 값을 추정해 채우지 않는다. [과거 시점의 코드·기록 감사](readiness-audit.md)와 이번 작업의 변경은 구분한다.

위 정보는 새로운 연구를 시작하기 위한 질문 목록이 아니라 이미 정한 설계를 실행값으로 채우는 입력표다. 실험 장비 자동화나 API는 필수 전제가 아니다. 수동 운전과 CSV 전달로 진행하되 사람이 확인·전사할 수 없는 시간 해상도의 계측을 수행한 것으로 쓰지 않는다.

UTM은 후속 보조 평가이므로 현재 전도도 사례에 UTM 수치 확정을 추가 차단으로 넣지 않는다. 배향 직접 관측도 현재 설정 비교의 필수 장비로 추가하지 않는다.

## 준비 기능과 남은 작업

1. **외부 근거 최종 인계(B5) 기능 구현**: 실제 자료를 보존하고 다른 담당자가 항목별로 확인하는 기능, Atlas 근거·설계·준비 검증을 묶는 인계 명세, 수신자 지정·수락을 연결했다. 자료 갱신·검증 기각·미해결 필수 문제·자원 조건은 인계를 막는다. [준비 증거·인계 사용 기준](../../guides/m1-preparation-handoff.md). 현재 사례에는 실제 준비 자료가 없으므로 확인 기록과 인계를 생성하지 않았다.
2. **현재 최종 검토**: 남은 쟁점을 각각 보존·확인·실험 질문으로 처리하는 실제 최종 판단이 필요하다. 이전 H1/H2/H3 문제를 현재 전도도 비교로 해결했다고 바꾸지 않는다. 적용 범위를 좁히려면 그 범위 변경을 명시적으로 검토해야 한다.
3. **작업 기록과 진행 정책**: Atlas 검토까지 실제 작업 22건을 원장에 연결했다. [재검토 정책 변경](return-policy-20260915.md)에 따라 횟수 대신 부족한 근거와 다음 행동으로 판단한다. 과거 되돌림 7회와 당시 한도 3회는 보존한다. 비용·자원 선언은 실제 지출이나 권한을 대신하지 않으며, 검증 자원·비용과 실제 준비 조건은 별도로 유지한다.

## M1 완료 판정

가상 예시가 파일 검사를 통과해도 실제 실험 준비는 완료가 아니다. 이 사례의 M1을 닫으려면 위 실제 입력으로 명세를 확정하고, 필요한 미해결 문제를 검토하며, 정식 준비·인계 정책이 통과해야 한다. 지금은 해당 조건을 만족하지 않으므로 M1 완료와 M2 실험 착수를 기록하지 않는다.

착수 입력표의 구조와 확인 기준은 2026-09-15 정리했다. 다음 재개 지점은 **장비 결정 후 첫 입력 묶음(D4-01·02·04·05)을 받아 제조·측정 설계 적용 가능성을 확인하는 것**이다. 준비 증거·인계 기능은 실제 자료와 판단이 들어오면 적용한다. 현재 최종 검토의 쟁점 처리와 원장·정책 점검도 최종 인계 전에 남아 있다.
