## 정식 gate에서 정확히 부족한 것

최종 검토의 25개 미해결 항목은 major 8개(methodology 4, logic 2, empirical 2), optional 17개다. 기존 해결 4개를 다시 미해결로 바꾸지 않는다. 이전 질문의 미해결과 현재 제조 비교의 필수 전제를 구별해야 하지만, 현재 `prepare_hypothesis_review`는 이전 M1의 미해결 major를 모두 검사한다. 따라서 영향 범위를 기록했다는 이유만으로 이 함수가 ready가 되지 않는다. 기존 쟁점을 가짜로 해결하거나 단지 시간이 걸린다는 이유로 M2로 옮기지 않는다.

현재 search/screen 조회는 `issue_reference_stale`, collect/extract는 `m1_node_missing`이다. 이는 외부 근거 사용을 위해 자체 수집을 다시 할 이유가 아니다. 현행 native handoff가 이 아홉 노드와 corpus 승인에 고정돼 있다는 구현 차이다. 종합·가설의 ready는 그 차이나 실제 준비를 통과시킨 상태가 아니다.

## 장비 정보 전에 자율적으로 끝낼 순서

1. D2의 측정·배정·분석 구조를 완성하고, 각 미정 수치에 확정 근거·담당·적용 시점을 붙인다. 수치가 필요한 실행 명세를 빈칸인 채 확정본으로 부르지 않는다.
2. D3의 CSV 연결과 상태·재시도·정정·원자료 계약을 구현하고 합성 정상/누락/오연결/재시도 묶음으로 검사한다. 이 결과의 완료 범위는 소프트웨어 기록 흐름이다.
3. D1–D3 산출물을 실제 검토 입력으로 묶고 기존 쟁점의 현재 영향·처리 초안을 작성한다. 정식 review는 정확한 입력에 실제 검토를 수행하며 대리 제출하지 않는다.
4. B5를 아래 최소 범위로 구현·검증하고 작업량 정책 오류를 진단한다. 모든 준비 상태가 unknown이면 인계를 차단하는 결과도 정상적인 구현 완료다.
5. 실제 장비/측정기와 금형·가용 배합/로트, 현장 담당·자원 정보를 한 번에 받을 입력표를 완성한다. 정보가 도착하면 수치·측정 적합성·반복 수·자원/권한을 확인하고 최종 실제 준비 검토와 수신자의 인계를 수행한다.

## B5의 최소 구현 범위

- **경로별 인계 계약:** 기존 native 자료 형식·과거 인계를 보존하면서 외부 계약은 현재 질문, 근거 묶음/QA/사용 판단, 종합·가설·review의 정확한 참조를 사용한다. 가짜 corpus·collect·extract를 만들지 않는다.
- **준비 증거 계약:** 설계/분석/CSV 버전, 장비·재료·측정 적합성, 수치·반복, 작업자·예산·일정·안전·권한, 실패/복구·기록 방식의 증거·담당·확인 시점과 충족/미확인/미충족/이유 있는 미적용을 저장한다. 등록 가능, 과학 검토 완료, 실행 준비, 인계 가능을 별도로 산출한다.
- **쟁점 범위 정책:** 현재 사례와 이전 세 질문에 대한 영향·처리 방침을 검증한다. 적용 범위 축소를 명시적·추적 가능한 정책으로 다루되 쟁점 상태를 자동 해결하지 않는다. empirical 이전만 검증 계획·담당·자원 및 실제 수신 수락에 연결한다.
- **무효화·수신·표시:** 근거/설계/준비 증거 변경 시 재확인 필요를 산출하고, 실제 수신 담당·수락·검증 의무를 보존한다. 공통 화면에 빠진 항목과 다음 담당 행동을 표시한다.
- **검사:** 필수 준비 누락, 합성 자료만 존재, 오래된 근거·설계 참조, 미해결 필수 쟁점, 수락 누락 시 차단; 기존 native/과거 인계 호환. 실제 데이터를 요구하는 확인은 합성 fixture의 테스트 통과로 충족시키지 않는다.

따라서 현재 사용자에게 필요한 정보는 실제 가용 장비·금형·측정기와 재료/로트 및 현장 실행 여건이다. 그 정보 전에도 위 1–4는 진행 가능하다. 물리 실험을 수행해야만 M1이 끝나는 것은 아니지만, 수행 가능한 명세와 실제 착수 전 필수 확인은 M1 안에서 끝내야 한다.
