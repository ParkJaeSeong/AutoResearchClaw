# 재검토 진행 기준 변경 — 2026-09-15

사용자가 “횟수보다는 저게 맞지.”라고 수용한 방향에 따라, 되돌림 횟수로 막던 정책을 부족한 근거와 다음 행동을 판단하는 정책으로 변경했다.

- 자료 부족: 필요한 자료와 확인 질문을 정해 다시 탐색한다.
- 가설의 문제: 문제가 있는 주장과 수정 방향을 연결한다.
- 같은 논의의 반복: 새 근거나 달라진 접근을 확인하고 같은 작업의 재실행을 피한다.
- 확인할 수 없음: 해당 용도 보류, 범위 축소, 입력 대기를 정하고 독립 작업은 계속한다.

되돌림 7회와 기존 한도 3회, 실제 작업 22건은 이력으로 보존한다. 새 정책에서 과거 한도는 진행 차단 기준으로 사용하지 않는다. 검증 자원·비용과 실험 준비·권한 조건은 유지한다. 정책 변경은 과학적 승인이나 실험 실행 권한이 아니다.

## 구현과 검증

정책 변경 명령, 다음 작업 평가 명령, 원장의 횟수 조건 분리, UI의 현재 정책 표시를 연결했다. [사용 기준과 입력 계약](../../guides/return-policy.md)에 필수 계획과 적용 범위를 정리했다.

자동 검증은 정책·기존 예산·CLI 43개, 기존 인계 조건 4개, UI 22개를 통과했다. 별도 코드 검토에서도 이 범위의 차단 문제는 없었다. 기존 설계 및 D4 입력·출력 10개 원본의 해시는 보존했다.

평가기의 계획 검사는 필수 내용과 참조의 존재·현재 버전, 같은 입력·질문·작업·완료 기준의 반복을 확인한다. 의미가 같은 다른 표현, 과학적 타당성, 영향받는 자료의 적절성은 조정자가 검토한다. 모든 노드·협의 실행에 자동 연결된 기능은 아니므로 재검토 전에 조정자가 평가를 호출하고 계획·결과를 회차에 연결한다.

## 다음 작업

현재 가설·실험 계획·CSV 명세를 함께 검토하고 남은 쟁점의 처리를 정한다. 가상 설계에서 검토 가능한 부분과 실제 실행 전에 채울 부분을 구분한다. 장비 결정 유예는 유지하며, 실제 장비·재료·측정 적합성·수치·반복·자원과 권한 확인 전에는 M1 완료나 M2 인계를 만들지 않는다.

작업 회차는 `008 · 재검토 진행 기준`이다. 명령·접수·검증 및 운영 화면 기록은 `.superpowers/research/2026-09-10-polymer-sdl/return-policy-20260915/`에 보관한다.

운영 UI 8771에서 008 종료·개발 검토 대기, 정책 문구와 재검토 7회, 최신 HEAD 일치를 확인했다. 브라우저 오류와 검수 중 쓰기는 0건이다. 원장의 진행 조건은 충족됐으나 M1 완료 조건과는 별개다. 연구 상태 변경은 정책과 회차·후속 기록에만 한정됐다.
