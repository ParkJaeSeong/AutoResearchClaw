# 에이전트 작업·근거·품질 표준 절차

2026-09-17 · 적용 대상: Pilot의 연구 작업과 위임받은 전문가. M1-1/2/3의 공통 운영 규범이며 이후 마일스톤에도 같은 원칙을 적용한다. 실행 엔진의 자동 차단은 후속 구현이다. 현재 조정자는 아래 절차를 직접 준수하고 확인 결과를 지원되는 작업 기록에 남긴다.

목표는 매번 같은 결론이 아니라 **목적에 맞는 답변, 추적 가능한 사실, 명시적인 한계, 재현 가능한 검토 수준**을 유지하는 것이다. 모델의 환각 부재나 과학적 정확성을 프롬프트·형식 검사만으로 보증하지 않는다.

## 적용 강도: 진행을 위한 검사

이 절은 아래 상세 항목의 적용 시점과 범위를 정한다. 모든 작업을 최종 심사처럼 처리하지 않는다.

- **탐색·정리·초안:** 담당자가 진행하고 누락·가정을 표시한다. 별도 검토자 호출이나 모든 주장 카드 작성을 요구하지 않는다.
- **중요 판단 채택:** 가설·설계·핵심 해석·권고처럼 다음 결정을 좌우하는 주장만 근거와 반례를 대조한다.
- **마일스톤 완료·실제 인계:** 목적별 필수 조건을 확인한다. 유효한 기존 검토는 재사용하고 빠진 부분만 검사한다.

목적·페르소나·이전 자료는 고정된 프로젝트 설정을 참조하고 변경분만 전달한다. 같은 내용을 매번 다시 작성하지 않는다. 입력·결론 변경이나 새 반례가 없으면 같은 검사를 반복하지 않는다. 추가 확인은 다음 결정을 바꿀 가능성이 있을 때 배정한다.

| 검사 결과 | 처리 |
| --- | --- |
| 진행 가능 | 확인한 범위에서 다음 작업 진행. 전체 연구 검증 완료를 뜻하지 않음 |
| 보완하며 진행 | 누락·영향·다음 조치를 남기고 독립적인 작업 계속 |
| 해당 판단 보류 | 결론이 성립하지 않는 핵심 결함 또는 권한 부족에 한정. 의존 작업만 보류 |

미확인은 기본적으로 후속 작업이다. 필수 원문이 없으면 서지 정리는 계속하지만 읽지 않은 본문 주장은 채택하지 않는다. 초안·부분 결과·실패 기록 저장은 항상 허용한다. 검사에는 문제·영향받는 판단·보완 방법을 남기며 실제 담당·실행 기록 없이 ‘에이전트 보완 중’ 또는 ‘사용자 확인 대기’로 표시하지 않는다.

자동 확인은 시작 전 목적·필수 입력 접근, 저장 시 형식·참조·버전·실행 상태를 다룬다. 의미 검토는 중요한 판단 채택 시에만 수행한다. 자동 검사기는 후속 구현이며 현재는 조정자가 이 기준을 적용한다.

## 1. 목적의 계층

| 계층 | 반드시 전달할 내용 | 변경 권한 |
| --- | --- | --- |
| 프로젝트 | 누구의 어떤 결정을 위해 무엇을 달성하는가, 범위·제약 | 사용자 의도와 대조. 핵심 목적 변경은 확인 필요 |
| 마일스톤 | 이번 이정표의 목적·완료 기준·수신자 | 조정자가 합의된 목적에서 도출. 실험 승인 등 별도 권한 유지 |
| 경로 | M1-1 연구 설계 / M1-2 조사·평가 / M1-3 계획 수립과 선택 이유 | 주 목적 변경은 결정 이력과 영향 검토 필요 |
| 단계 | 이번에 답할 질문·해소할 공백·완료 기준·돌아갈 조건 | 근거에 따라 조정하되 영향 기록 |
| 작업 | 담당·입력 버전·도구·허용 행동·출력 계약 | 배정 범위 내 수행. 범위 밖 행동은 의뢰로 반환 |

마일스톤 목적은 M1: 근거와 방향·실행/작성 준비, M2: 실제 결과에 의한 검증·해석, M3: 논문 완성, M4: 보고서·계획서 완성이다. 보고서·계획서에 실험 단계 통과를 강제하지 않는다. 단계와 수행 회차는 다른 식별자로 관리한다.

검색어·자료 우선순위는 허용 범위 내 자율 조정한다. 핵심 대상·질문·성공 기준·비용/실행 권한은 임의 변경하지 않는다. 목적이 모호하면 후보 해석과 영향부터 제시하고 핵심 확인을 받는다. 확인 대기와 무관한 작업은 진행할 수 있다.

## 2. 표준 수행 절차

| 순서 | 책임 | 필수 행동 | 통과 기준 |
| --- | --- | --- | --- |
| 1. 맥락 확정 | 조정자 | 목적·단계·현재 상태·남은 문제·검토 기준 확정 | 목적 계층과 질문이 연결됨 |
| 2. 역할 배정 | 조정자 | 필요한 도메인·검토 책임·반론 관점 선정 | 결과물별 작성·검토 책임이 있음 |
| 3. 입력 구성 | 조정자 | 이전 결정·자료·원형 참조·실패·변경 사항 묶음 고정 | 필수 자료 접근 가능, 독립 검토 공개 범위 적합 |
| 4. 수신 확인 | 수행자 | 목적·읽은 입력·누락·권한·수행 가능성 확인 | 필수 입력을 실제 확인; 불가 시 보완 요청 |
| 5. 수행 | 수행자/도구 | 검색·분석·초기 의견을 목적별로 작성 | 실제 실행과 관측·추론·가정 구분 |
| 6. 검토 | 검토자 | 근거 대조·반론·방법·목적 적합성 확인 | 핵심 주장 검증, 차이와 미해결 사항 기록 |
| 7. 결정 | 조정자 | 채택·제한·수정·보류와 다음 작업 판단 | 미해결 필수 문제를 우회하지 않음 |
| 8. 인계·보존 | 조정자/수신자 | 버전 고정 결과와 사용 조건 전달, 수신 상태 확인 | 접수/보완/수행 불가 구분, 추적 가능 |

단순 자료 조회는 별도 토론을 강제하지 않는다. 그러나 가설 채택·평가 기준 확정·계획 선택·최종 인계처럼 후속 판단을 좌우하는 결과는 작성자와 구분된 검토를 거친다. 별도 검토자가 없으면 독립 검토 완료라고 쓰지 않고 해당 결정을 검토 대기로 둔다. 모든 의견이 모이기 전 동료 초기 의견을 공개하지 않는다.

## 3. 페르소나의 최소 계약

모든 전문가에게 [common.md](common.md)의 카드에 다음을 추가해 전달한다.

- 역할 ID·버전과 실제 담당 에이전트/모델 정보(확인 가능한 범위).
- 전문 분야, 이번 목적에서 필요한 이유, 직접 책임질 판단.
- 적용할 이론·방법과 성립 조건. 모르는 이론의 근거를 창작하지 않음.
- 자신의 관점이 놓치기 쉬운 편향, 가장 강한 경쟁 설명.
- 필요한 자료·확인 수준, 판단을 바꾸는 증거.
- 담당 밖의 판단·실행 권한, 필요한 다른 전문가.
- 제출 형식, 검토자와 공개 규칙.

분야 전문가에게 사업성을 단독 확정하게 하거나, 사업 전문가에게 실증 성능을 단정하게 하지 않는다. ‘찬성 역할’이므로 찬성 결론을 유지하도록 강요하지 않는다. 모델 다양성은 사실 검증을 대체하지 않는다.

## 4. 이전 자료 제공 기준

| 이전 맥락 | 전달 방식 | 금지 사항 |
| --- | --- | --- |
| 사용자 목적·제약·피드백 | 원래 지시 참조와 현재 적용 버전, 바뀐 이유 | 오래된 목표로 새 지시를 덮어쓰기 |
| 이전 결정 | 결정 내용·이유·근거·허용/보류 범위 | 이전 결정을 새 실증 증거로 취급 |
| 미해결 문제 | 영향·담당·확인 방법·미확인 시 처리 | 같은 문제를 새 ID로 반복 생성 |
| 문헌·원자료·Atlas 분석 | 자료 ID·버전·해시(확보 시)·위치·확인 범위 | 요약만 전달하고 원문을 읽었다고 표시 |
| 검색·실험·도구 기록 | 조건·요청/실행 ID·결과·실패·재개 위치 | 성공만 남기거나 실패를 새 실험으로 은폐 |
| 직전 회차 이후 변경 | 추가·수정·폐기 후보와 영향 | 과거 결과를 조용히 덮어쓰기 |
| 동료 의견 | 교차 검토 때만 공개, 초기 의견과 구분 | 독립 검토 입력에 미공개 의견 혼입 |

이전 자료는 전부 복사하지 않는다. 목적·필수 원문/발췌·핵심 반론·미해결 문제는 입력에 포함하고, 나머지는 고정 버전 참조로 제공한다. 생략 목록과 이유를 남긴다. 요약만으로 판단할 수 없는 핵심 항목은 원형 접근을 요구한다. 모델 문맥이 부족하면 작업을 나누며 근거·반론을 임의로 삭제하지 않는다.

작성자는 입력 목록에 대해 실제 읽은 항목·부분 확인·접근 불가를 반환한다. 이 자기보고만으로 원문 확인을 자동 인증하지 않으며 검토자가 핵심 근거를 대조한다. 재시작 시 목적·입력·결과 버전을 확인하고, 변경이 없으면 이미 끝난 도구 작업을 반복하지 않는다.

## 5. 사실 기반 결과의 규칙

핵심 주장은 다음 유형을 표시한다: 직접 관측 / 문헌의 보고 / 도구 계산 / Atlas·타인의 해석 / 본인 추론 / 가정 / 제안. ‘사실’이라는 단일 라벨로 섞지 않는다.

주장별로 출처 참조·버전·페이지/표/행·확인 범위·조건·단위·지지/반박/불충분 관계를 연결한다. 같은 원천의 재인용은 독립 증거가 아니다. 해시 일치는 파일 동일성의 증거이며 내용의 진실성 보증이 아니다. URL이 존재하는 것만으로 해당 주장을 지지한다고 판단하지 않는다.

핵심 주장(가설 선택, 순위·권고, 핵심 비용/성과, 실행·인계 결정에 영향을 주는 주장)은 모두 근거와 실제 지지 관계를 대조한다. 나머지 주장은 영향·불확실성에 따라 추가 검토하며 핵심 주장으로 승격하면 대조한다. 확인되지 않은 주장은 삭제보다 미확인·가정으로 정정하고 사용 범위를 제한한다.

### 자료 유형별 최소 확인

| 유형 | 필수 기록·검토 |
| --- | --- |
| 검색 결과 | 실제 검색어·도구/사이트·시각·반환 후보·접근 범위·중복 관계. 엔진 전체 hit 수 추정 금지 |
| 문헌 | 식별자·서지·버전·확보 범위·방법/조건·주장 위치·반론. 검색 요약을 본문 근거로 승격 금지 |
| 실험 | 실제/합성/가상 구분, 시료·조건·장비/방법·단위·반복·원자료·실패·사람 개입·변경 이력 |
| 계산·학습 | 데이터/코드/설정 버전, 분할·전처리·지표·실행 기록·오류·재현 정보. 예측과 실제 관측 분리 |
| 통계·시장·비용 | 출처·기준일·지역·기간·모집단·분모·통화/단위·산식·가정·민감도 |
| 이론·해석 | 이론의 출처·성립 조건·경쟁 설명·관측에서 결론으로 가는 논리·추론 한계 |

M1에서는 실제 실험 결과를 새로 만든 것처럼 쓰지 않는다. 기존 실험 자료가 없으면 실행 설계 또는 확보 필요로 기록한다. 수집·분석 도구의 지원 범위를 먼저 확인하고 없는 API/MCP 호출 기록을 만들지 않는다.

## 6. 검수·채택 기준

공통 평가 축은 목적 적합성, 근거 추적성, 해석 타당성, 반론 처리, 실행 가능성이다. 합산 점수로 필수 결함을 상쇄하지 않는다.

| 확인 지점 | 필수 기준 | 실패 시 |
| --- | --- | --- |
| 입력 | 목적·페르소나·단계 질문·필수 자료·출력 계약 존재 | 해당 작업 배정 보완 |
| 원형·버전 | 참조가 존재하고 대상 프로젝트/버전·해시와 일치 | 영향받는 결과 채택 중지, 원형 재확인 |
| 근거·해석 | 핵심 주장에 실제 지지가 있고 범위·한계를 넘지 않음 | 주장 정정·제한·보류, 필요 시 추가 조사 |
| 독립성 | 초기 입력 공개 규칙과 실제 검토자가 확인됨 | 독립 검토 주장을 철회하고 재검토 |
| 경로별 완결성 | 연구/평가/계획의 필수 산출물과 종료 기준 충족 | 빠진 항목만 보완 또는 조건부 의뢰 |
| 인계 | 결과·근거·미해결·허용 행동·수신 요구가 연결됨 | 작성 초안과 실제 실행 준비를 구분해 반환 |

초안·실패·부분 결과는 항상 저장할 수 있다. 검사 실패가 기록 보존을 막아서는 안 된다. 다만 실패한 내용이 검증된 근거·채택된 결정·완료된 인계로 승격되면 안 된다. 관련 없는 작업까지 전부 중단하지 않는다.

상태별 의미: 초안은 미검토, 수정 필요는 명시한 결함 존재, 검토 통과는 확인 범위 내 적합, 조건부 사용은 특정 용도만 허용, 보류는 필요한 판단 불가다. 이는 제안한 운영 분류이며 기존 저장 스키마 상태값을 임의로 추가하지 않는다.

## 7. 보완과 종료

추가 확인에는 반드시 ‘공백 → 영향을 받는 결정 → 새로 확인할 증거 → 끝낼 조건 → 미확인 시 제한/보류’를 붙인다. 새 증거나 방법이 없는 반복은 조정자가 재설계한다. 임의의 논문 수·토론 횟수·10분 제한으로 자료를 폐기하거나 완료하지 않는다. 명시된 예산·기한·권한에 도달하면 결과와 재개 지점을 보존한다.

연구 경로에서는 실제 실행 필수 조건을 미확인 상태로 통과시키지 않는다. 보고서·계획서에서는 불확실성을 정직하게 표시한 작성 의뢰가 가능하나, 그 불확실성에 의존하는 확정 주장이나 자원 집행을 허용하지 않는다.

목적·입력 자료가 바뀌면 영향받는 결정과 후속 산출물을 재검토 대상으로 표시한다. 과거 검토 결과는 당시 버전에 귀속한다. 수신자는 접수·보완 요청·수행 불가를 반환하며 도구 완료와 Pilot의 채택을 분리한다.

## 8. 실제 강제의 수준과 구현 순서

- **현재 운영 규범:** 조정자가 작업 패킷을 구성·전달하고 수신 확인·검토·결정 사유를 기록한다. 하위 에이전트가 AGENTS.md를 자동으로 읽는다고 가정하지 않는다.
- **기존 구현 활용:** 불변 연구 기록·버전 참조·원형 해시·명령 충돌 검사와 기존 교차 검토/승인 조건을 유지한다. 새 절차 전체를 이미 자동 검증한다고 주장하지 않는다.
- **후속 자동화 1:** 목적/페르소나/입력 패킷 스키마, 참조·버전·자료 접근 검사. 누락의 영향에 따라 보완 안내 또는 해당 의존 작업만 보류.
- **후속 자동화 2:** 주장–근거 연결 검사와 검토 기록, 채택·인계 전에 필수 확인을 요구하는 서비스/CLI 경계. UI만의 경고로 대체하지 않음.
- **후속 자동화 3:** 목적별 검수 사례 실행, 실패 결과의 승격 차단, 재시작·우회 경로 회귀 검사.

내용의 지지 여부와 방법론 타당성은 의미 검토가 필요하다. 구조·해시 검사와 분리해 검토 책임자·이유를 남긴다. 자동화 전에는 위반을 코드가 막는다고 표현하지 않는다. 품질 기준과 절차는 강제할 수 있지만 사실 정확성을 무조건 보장할 수는 없다.
