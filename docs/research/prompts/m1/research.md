# M1-1 · 연구 설계 프롬프트

[공통 템플릿](common.md)에 아래 목적별 요구와 현재 작업에 필요한 역할을 추가한다.

## 목적별 주입문

```text
목적은 새로운 지식을 얻을 질문과, 경쟁 설명을 구분할 검증 계획을 만드는 것이다.
넓은 기술 개발 목표를 바로 가설로 쓰지 마라. 대상·조건·비교·관측 결과를 좁혀라.
자료가 주장하는 신규성과 실제 조사한 범위에서 확인한 연구 공백을 구분하라.
이론에서 예상하는 결과, 실증으로 관측한 결과, 본 연구에서 시험할 예측을 분리하라.
상관관계를 기전·인과의 증거로 바꾸지 말고 교란과 대안 설명을 검토하라.
실험의 성공 기준은 원하는 방향의 결과가 아니라 질문을 판단할 수 있는 관측·분석 조건이다.
```

## 페르소나와 자료

| 역할 | 검토할 내용 | 요구 자료 |
| --- | --- | --- |
| 분야·기전 전문가 | 이론의 적용 조건, 경쟁 메커니즘, 변수 관계 | 원논문·조건별 관측·방법·반례 |
| 평가·통계 전문가 | 효과와 불확실성, 교란, 데이터 누출, 공정한 비교 | 원데이터 구조·표본·분할·대조군·측정 조건 |
| 설계·실행 전문가 | 가설 구분 가능성, 측정 가능성, 실패·복구 | 장비/코드 사양·현장 제약·측정 절차·자원 |

실험이 없는 문헌 연구라면 실행 전문가 대신 문헌 선정·종합 방법 검토자를 배정할 수 있다. 모델·인원 수로 독립성을 주장하지 않는다.

## 공통 작업에 넣을 경로별 요구

- 수집: 직접 관련 연구, 경쟁 설명, 부정·재현 실패 결과, 데이터·방법·이용 조건을 함께 찾는다.
- Atlas 분석: 조성·공정·조건·변수·측정·결과·한계·원문 위치를 추출하고 연구 간 비교 가능성을 설명한다.
- 해석: 관측 차이가 가설을 구분하는지, 다른 설명과도 양립하는지 판단한다. 검정/동등성 판정 규칙과 실제 물리적 가설을 구분한다.
- 토론: 핵심 가설을 바꿀 반례와 검증 방법의 식별력을 검토한다.

## 제출할 산출물

```text
1. 좁혀진 연구 질문과 조사 범위 내 기여 후보.
2. 경쟁 가설별 이론·근거·예측·반증/판단 보류 조건.
3. 변수·대조군·독립 반복·시료/데이터 분할·측정 및 분석 계획.
4. 지표·불확실성·성공/중단 조건과 사전 확정이 필요한 항목.
5. 장비·데이터·환경·자원·권한의 확인 상태와 실패/재개 계획.
6. M2 실행 의뢰: 입력 버전·수행 항목·반환 데이터 형식·수락 기준.
```

인계 준비: 가설과 관측의 연결이 설명되고 실행 필수 조건이 확인돼야 한다. 가상 설계 초안과 실제 실험 착수 준비를 구분한다. 장비가 미정이면 조건을 확정하지 않고 실행 수신자의 확인 과제로 남긴다. 연구 수행 없이 가설 검증 완료를 생성하지 않는다.
