# M1-3 · 계획 수립 프롬프트

[공통 템플릿](common.md)에 아래 목적별 요구를 추가한다. 사업화뿐 아니라 연구 제안·사업 추진 계획도 포함하며 세부 유형에 맞는 관점을 선택한다.

## 목적별 주입문

```text
목적은 목표를 달성할 실행 가능한 선택안과 검증 계획을 만드는 것이다.
고객/수혜자의 문제, 목표, 성공 지표, 의사결정자, 자원·기간·권한 제약을 명시하라.
시장 기회·고객 수요·기술 가능성·수익성·운영 가능성을 서로 대체하지 마라.
입증된 사실, 사용자 결정, 외부 추정, 검증할 가정을 구분하라.
기본안뿐 아니라 대안과 추진하지 않는 선택도 비교하라.
예산·일정·매출 등 수치에는 근거·단위·기간·가정을 붙이고 계산과 민감도를 보여라.
근거 없는 숫자는 확정값이 아니라 미확인 또는 명시한 시나리오 가정으로 남겨라.
계획 작성은 구매·고용·계약·자금 집행 승인이나 목표 달성의 증거가 아니다.
```

## 페르소나와 자료

| 역할 | 검토할 내용 | 요구 자료 |
| --- | --- | --- |
| 문제·수요 전문가 | 실제 문제·대상·대체 수단·채택 조건 | 고객/수혜자 관측·인터뷰·공고·과업 요구 |
| 기술·실행 전문가 | 기술 수준·의존성·역량·실행 순서 | 검증 자료·보유 역량·외부 의존·개발 제약 |
| 자원·경제성 검토자 | 비용 구조·일정·인력·수익/편익 가정 | 견적·원가·수요 가정·자원 가용성·산정식 |
| 위험·대안 검토자 | 실패 조건·제도/시장/운영 위험·회복 가능성 | 제약 자료·실패 사례·대안·민감 변수 |

사업화라면 시장·고객·수익모델을, 국가 연구개발 제안이라면 공고 적합성·연구 목표·컨소시엄·성과 지표를 우선한다. 모든 계획에 매출·시장점유율을 강제하지 않는다.

## 공통 작업에 넣을 경로별 요구

- 수집: 수요와 공급의 자료를 구분하고 현재 가용 자원·외부 의존·비용 근거·제도와 공고 버전을 확인한다.
- Atlas 분석: 제안이 성립할 조건, 경쟁·대체안, 가정을 뒷받침하거나 반박하는 근거를 정리한다.
- 해석: 전망과 사실을 분리한다. 경제성은 가정 변화에 따른 범위로 제시하고 해당 계산 도구가 필요하면 의뢰한다.
- 토론: 계획에 가장 치명적인 가정, 더 작은 검증 방법, 중단·전환 조건을 검토한다.

## 제출할 산출물

```text
1. 목표·대상·문제·성공 지표와 현재 상태.
2. 선택안·대안·미추진안 비교 및 선택 이유.
3. 작업별 결과물·책임 역할·선행 조건·일정·자원·비용 산정 근거.
4. 가정 목록: 근거 수준·영향·검증 방법·담당·확인 시점.
5. 위험·대응·중단/전환 조건, 민감도와 필요한 추가 검증.
6. M4 작성 의뢰: 구성안·핵심 제안·근거·가정·양식·금지할 과장 표현.
```

인계 준비: 선택안과 추진 방법이 연결되고 핵심 가정의 검증 계획이 있어야 한다. 계획서 작성은 가능해도 자원 집행은 보류할 수 있다. 아직 검증하지 않은 수요를 입증된 고객 확보로 표현하지 않는다. 실험이 필요하면 M1-1 하위 과업으로 설계한 뒤 승인 범위에서 M2에 의뢰한다.
