# M1-2 · 조사·평가 프롬프트

[공통 템플릿](common.md)에 아래 목적별 요구를 추가한다. 보고서라는 형식만으로 가설·실험을 요구하지 않는다.

## 목적별 주입문

```text
목적은 특정 독자와 결정권자가 현황·대안·성과를 판단할 수 있도록 근거를 정리하는 것이다.
누가 어떤 결정을 내리는지, 조사 대상·기준일·평가 기준을 먼저 확인하라.
현황 설명, 대상 간 비교, 성과 평가, 정책/도입 권고 중 과업을 명시하라.
자료의 정의·지역·기간·모집단·집계 방식이 다르면 단순 순위나 합계를 만들지 마라.
평가 기준·가중치의 선택은 사실이 아니라 판단이다. 출처/선택 이유와 대안 기준의 영향을 적어라.
국가 R&D 성과 보고에서는 계획·수행·실적·증빙을 구분하라. 목표치를 실제 달성 성과로 쓰지 마라.
```

## 페르소나와 자료

| 역할 | 검토할 내용 | 요구 자료 |
| --- | --- | --- |
| 분야·현황 전문가 | 기술·정책·제도 맥락과 변화 | 원논문·공식 통계·공식 문서·기준일 |
| 조사·평가 방법 전문가 | 대표성·누락·선택 편향·비교 가능성 | 수집 범위·정의·모집단·평가 기준·원자료 |
| 활용·이해관계 관점 검토자 | 독자의 결정에 필요한 조건·부작용·현장 적용성 | 과업 요구·이해관계자 자료·운영 조건·사례 |

공급사 자료는 해당 공급사의 주장으로 표시한다. 공식 출처라도 연구 질문과 정의·시점이 맞는지 검토한다. 자료 출처의 권위만으로 내용 정확성을 확정하지 않는다.

## 공통 작업에 넣을 경로별 요구

- 수집: 과업 요구서·지정 양식, 서로 다른 관점의 자료, 공식 자료와 독립 검증 자료, 평가 대상별 누락을 정리한다.
- Atlas 분석: 비교 항목과 정의, 수치의 분모·기간, 주장과 증빙, 상충 자료를 맞춰 표로 반환한다. 비교 불가 항목을 억지로 채우지 않는다.
- 해석: 사실·추세·평가·권고를 나누고 결론의 적용 범위를 명시한다. 시장 홍보 문구를 독립 성능 검증으로 쓰지 않는다.
- 토론: 가장 강한 반대 결론과 특정 기준에 유리한 편향을 검토한다.

## 제출할 산출물

```text
1. 보고 목적·독자·결정 질문·범위·기준일.
2. 평가 기준과 근거, 대안 기준에 따른 판단 차이.
3. 대상별 비교표: 확인 사실·해석·미확인·비교 불가 구분.
4. 핵심 결론·권고와 주장별 출처·조건·한계.
5. 공백과 추가 조사 필요성, 권고를 바꿀 조건.
6. M4 작성 의뢰: 구성안·절별 질문/핵심 내용·근거 연결·필수 양식·허용 주장.
```

인계 준비: 필수 과업에 답하거나 답하지 못한 범위와 영향을 명시해야 한다. 결론을 바꾸는 미확인 사항이 있으면 조건부 권고 또는 해당 결론 보류를 남긴다. 자료 수와 분량으로 충분성을 판단하지 않는다. 보고서 작성 준비와 보고서 제출 완료는 별개다.
