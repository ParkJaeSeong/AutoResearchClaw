# M1 목적별 프롬프트 설계

2026-09-17 · 사용자 합의를 구체화한 설계 템플릿. 실행 엔진·UI에 자동 적용되지 않는다. 아래 필드는 프롬프트 입력 설계이며 기존 저장 API의 신규 필드가 아니다.

M1-1 연구 설계, M1-2 조사·평가, M1-3 계획 수립은 순차 단계가 아니라 목적별 경로다. 공통 절차를 재사용하되 자료·페르소나·해석·종료 기준은 경로별로 주입한다. 자료 수집은 Pilot 내부 책임으로 유지한다.

## 필수 운영 절차

모든 연구 작업은 [표준 절차](protocol.md)를 따른다. 배정에는 [작업 패킷](task-packet.md)을 사용하고 결과 채택 전 [검수 기준](quality-checks.md)을 적용한다. 현재 조정자가 준수할 운영 규범과 후속 자동 차단 구현을 구분한다. 프롬프트만으로 항상 정확한 결과를 보장하지 않는다.

## 항목별 상세 명세

[8개 항목의 상세 명세](spec/README.md)에서 목적 카드·단계 목적·페르소나 배정·이전 자료·근거 카드·토론·종료·인계의 필수 값과 실패 처리를 확인한다. 원칙은 표준 절차, 실제 배정은 작업 패킷, 상세 판정은 이 명세를 함께 사용한다. 현재 문서 설계이며 자동 강제 구현은 별도다.

## 읽는 순서

1. [공통 입력·페르소나·작업 템플릿](common.md)
2. 필요한 경로 하나: [M1-1 연구 설계](research.md), [M1-2 조사·평가](assessment.md), [M1-3 계획 수립](planning.md)
3. [적용 예시와 검수 사례](examples.md)

한 작업에 세 경로 문서와 모든 전문가 지침을 전부 넣지 않는다. 조정자가 주 경로·세부 과업·입력 버전을 정하고 필요한 부분만 조합한다.

## 프롬프트 조합

공통 규칙 + 프로젝트 목적 카드 + 목적별 작업 요구 + 도메인 페르소나 카드 + 현재 작업 지시 + 허용된 근거 묶음 + 산출물 계약.

| 공통 작업 | M1-1 연구 설계 | M1-2 조사·평가 | M1-3 계획 수립 |
| --- | --- | --- | --- |
| 목적 구체화 | 검증 질문·기여·예측 대상 | 독자·의사결정·비교 대상·기준일 | 목표·수혜자/고객·성공 조건·결정권자 |
| 자료 수집 | 직접 관측·방법·반례·공개 데이터 | 비교 가능한 통계·정책·기술·성과 증빙 | 수요·대안·비용·역량·일정·제약 증거 |
| Atlas 분석 의뢰 | 조건·기전·교란·재현 가능성 | 정의·기간·모집단·비교 기준 차이 | 사실·가정·추정의 구분과 성립 조건 |
| 전문가 검토 | 경쟁 설명과 구분 가능한 검증 | 편향·대표성·평가 기준의 타당성 | 실행 가능성·대안·민감도·실패 조건 |
| 종합 판단 | 가설·반증·실험·분석 계획 | 조건별 결론·권고·한계 | 선택안·추진 순서·자원·위험·검증 계획 |
| 인계 | M2 실행 명세 | M4 보고서 작성 지시 | M4 계획서 작성 지시 |

## 혼합 과업

프로젝트에는 주 경로와 목적 버전을 둔다. 예: 사업 계획(M1-3)의 기술 비교를 M1-2에, 성능 검증 설계를 M1-1에 하위 과업으로 배정한다. 하위 과업은 질문·범위·부모 결정·출력 계약을 받고 결과를 부모에게 반환한다. 프로젝트나 자료를 복제하지 않는다. 경로 전환 시 이유·영향받는 판단·재사용 가능한 근거를 명시한다.

## 실행과 종료

일반 수집·서지 정리는 진행 에이전트가 맡는다. 중요한 가설 선택·평가 기준 변경·계획 채택에는 담당 전문가와 다른 관점의 검토자를 배정한다. 공개 전 첫 의견은 같은 입력 버전으로 작성한다. 역할 수·토론 횟수·자기 확신 점수를 품질 지표로 사용하지 않는다.

자료 부족과 실제 의견 차이를 구분한다. 추가 작업은 바뀔 수 있는 판단, 확인할 근거, 성공·미확인 시 처리 방침이 있을 때 제안한다. 목적별 필수 조건을 충족하면 미해결 사항을 명시해 인계한다. 미확인 실행 필수 조건을 문장만으로 완료 처리하지 않는다. 사람의 검토가 필요한 프로젝트에서는 그 정책을 따르고, 무응답을 승인하지 않는다.

이 설계의 검수는 프롬프트 내용 대조까지다. 실제 에이전트 출력과 자동 분기 품질은 [검수 사례](examples.md)로 별도 실행 평가해야 한다.
