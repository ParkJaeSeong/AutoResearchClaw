# M1 표준 절차 상세 명세 v0.1

적용 강도는 [진행을 위한 검사](../protocol.md#적용-강도-진행을-위한-검사)를 우선한다. 탐색·초안은 가볍게 진행하고 중요한 판단 채택 시 검토한다. 목적·역할·입력은 기존 버전을 참조하고 변경분만 작성한다.

2026-09-17. [표준 절차](../protocol.md)를 실제 배정·검토 단위로 구체화한다. 설계상 필수 요건이며 새 API·자동 검증기가 구현됐다는 뜻은 아니다. 실제 연구 실행 없이 명세를 작성했다.

| 항목 | 담당·결과물 | 상세 |
| --- | --- | --- |
| 1. 목적·경로 확정 | 조정자 → 목적 카드 | [목적과 역할](purpose-roles.md) |
| 2. 마일스톤·단계 정의 | 조정자 → 질문·종료·복귀 조건 | [목적과 역할](purpose-roles.md) |
| 3. 페르소나·검토자 배정 | 조정자 → 책임별 역할 카드 | [목적과 역할](purpose-roles.md) |

| 5. 수집·분석·주장 기록 | 수행자 → 검색/자료/주장 목록 | [입력과 근거](inputs-evidence.md) |

## 명세 해석 규칙

- 필수는 배정/채택/인계 중 어느 시점에 필요한지 구분한다. 모든 값을 연구 시작 전에 요구하지 않는다.
- 필드 값은 확인 사실·사용자 결정·가정·미확인·해당 없음으로 구분한다. 해당 없음에는 이유와 판단자를 붙인다. 0·빈 문자열·성공으로 누락을 메우지 않는다.
- 내부 결과 식별자는 프로젝트·목적 버전·작업·입력 묶음·결과 버전으로 연결한다. 기존 ID를 다시 발급하거나 저장 스키마를 임의 변경하지 않는다.
- 양식 충족은 내용 타당성의 대용이 아니다. 자동 확인 후보와 의미 검토를 구분한다.
- 문헌 수·의견 수·고정 점수로 종료하지 않는다. 범위와 필수 질문에 답했는지 평가한다.
- 한 핵심 주장에 문제가 있으면 해당 주장과 의존 작업을 보류한다. 원기록 저장과 독립 작업까지 막지 않는다.

## 이후 구현의 작은 단위

1. 목적·역할·입력 목록의 읽기 전용 형식 검사: 누락·참조 오류를 반환하며 연구 상태는 바꾸지 않는다.
2. 작업 배정과 수신 확인 연결: 필수 입력을 못 읽은 작업은 보완 요청으로 반환한다.
3. 주장–근거–검토 연결과 기존 채택 명령 통합: 모든 쓰기 진입점에 동일 조건을 적용한다.
4. 목적별 종료·인계와 재개: 입력 변경·응답 유실·거부·보완 경로를 검증한다.

각 단위는 기존 명령·저장 계약과 대조해 구현 계획을 세운 뒤 적용한다. 현재 단계는 이 명세의 문서 검수이며 자동화 시험 통과가 아니다.
