# 6–8. 토론·채택·종료·인계 구체화

[공통 해석 규칙](README.md)을 적용한다. 아래 판정명은 운영 의미이며 현행 저장 상태를 임의 변경하지 않는다.

## 6. 검토 라운드

| 과정 | 입력 | 출력 | 조건 |
| --- | --- | --- | --- |
| 독립 초기 의견 | 목적·페르소나·고정 근거, 동료 의견 없음 | 판단·근거·경쟁 설명·공백·다음 작업 | 전원 제출 전 초기 의견 비공개 |
| 교차 검토 | 공개된 초기 의견·동일 근거 | 주장별 동의/반박·입장 수정 이유·남은 이견 | 실제 읽은 의견만 언급 |
| 종합 | 의견 원문·반론·검토 기록·새 근거 변경표 | 채택안·비채택 이유·미해결 영향·후속 의뢰 | 조정자 해설을 전문가 원발언으로 기록하지 않음 |

독립·교차 검토는 중요한 판단의 기본 절차다. 단순 조회·형식 정리에는 억지 토론을 붙이지 않는다. 추가 라운드는 새 근거·방법·결정에 중요한 이견이 있을 때 수행하고, 고정 횟수나 합의율로 종료하지 않는다.

### 검토자 체크 항목과 실패 대응

| 질문 | 확인 근거 | 실패 시 |
| --- | --- | --- |
| 원래 목적에 답하는가 | 목적 카드와 결과의 질문 대응 | 목적 범위에 맞게 재작성 |
| 핵심 주장이 실제 자료로 지지되는가 | 원형의 해당 위치·조건과 주장 대조 | 주장 정정·가정 표시·보류 |
| 단위·버전·대상·기간이 맞는가 | 자료·계산·방법 기록 | 비교/계산 재검토 |
| 대안 설명과 불리한 근거를 다뤘는가 | 반례·교차 의견·원천 관계 | 빠진 반론 검토 |
| 독립성과 실제 실행 표현이 맞는가 | 입력 공개 이력·도구/실행 기록 | 표현 철회·필요 시 재검토 |
| 목적별 필수 산출물이 있는가 | 경로별 요구와 결과 대응 | 부족한 항목만 보완 |
| 다음 작업이 가능한가 | 입력·지원 기능·권한·수신 조건 | 의뢰 수정 또는 제한된 초안 전달 |

검토 결과는 확인 범위·핵심 주장별 판정·결함·영향·수정 요구·통과 조건을 포함한다. 원문 위치가 없는 핵심 근거를 검토자가 추정해 채우지 않는다.

## 7. 채택과 종료

| 판정 | 허용되는 다음 행동 | 허용하지 않는 것 |
| --- | --- | --- |
| 채택 | 명시한 질문·조건 범위에서 사용 | 다른 목적의 자동 사용 |
| 조건부 사용 | 허용 용도·조건을 표시해 사용 | 보류 조건에 의존한 확정 결론 |
| 수정 필요 | 초안 보존과 특정 보완 | 수정 전 결과의 완료 인계 |
| 보류 | 독립 작업, 필요한 확인 또는 범위 재설계 | 해당 주장에 의존한 실행 |
| 해당 용도에서 제외 | 이유·원형 보존, 다른 용도 검토 가능 | 반대 결과라는 이유의 삭제 |

조정자는 결과 버전·검토 참조·남은 문제·판정 이유·허용/금지 행동을 기록한다. 자기 확신 점수·다수결·잘 쓴 문장으로 근거 결함을 상쇄하지 않는다.

### 경로별 종료 기준

| 경로 | 필수 결과 | 종료를 막는 문제 | 남겨도 되는 불확실성 |
| --- | --- | --- | --- |
| M1-1 | 질문·경쟁 가설·관측/반증·설계·분석·실행 준비 | 단위/측정/데이터/권한 등 실험 성립 조건 미확인 | 실험으로 검증할 과학적 질문 |
| M1-2 | 독자·과업·비교 기준·근거·결론/권고·한계·구성 | 핵심 결론을 지지하지 않는 자료 또는 필수 과업 누락 | 권고를 조건부로 제한해 정직하게 설명 가능한 공백 |
| M1-3 | 목표·대안·선택 이유·일정/자원·가정·위험·검증 계획 | 핵심 추진 방법 없음, 사실과 가정 혼동, 산정 근거 없음 | 검증 담당·방법·시점·전환 조건이 정해진 가정 |

가상 설계만 요청받은 M1-1은 설계 초안 완료를 기록할 수 있지만 실제 M2 착수 준비 완료와 구분한다. M1-2/3의 작성 입력이 준비돼도 문서 작성 완료·구매/자원 집행 승인은 별개다. 새 실험 없는 문헌 연구 논문은 질문·선정·종합 방법과 근거 검토 후 별도 M3 작성 의뢰로 판단한다.

### 반복을 계속할지 정하는 카드

```text
현재 모르는 것:
답이 바꾸는 결정과 영향:
새로 확인할 근거 또는 다른 접근:
확인되면 할 일 / 확인되지 않으면 할 일:
이번 작업 완료 기준과 허용 자원:
기존 문제·작업과의 관계:
```

새 접근이 없다면 같은 검색/토론을 반복하지 않는다. 조건부 사용·범위 조정·보류를 판단한다. 사용자에게 질문이 필요하면 선택지와 영향, 확인 전 가능한 독립 작업을 함께 제시한다.

## 8. 전문 도구·다음 마일스톤에 인계

| 인계 항목 | 필수 내용 |
| --- | --- |
| 목적 | 수신자가 어떤 작업을 끝내야 하는가 |
| 정체성 | 프로젝트·목적 버전·작업 ID·요청 ID·부모 결정 |
| 입력 | 자료/결정/코드/조건의 고정 참조와 버전, 접근 가능성 |
| 수행 범위 | 허용 행동·비용/권한·하지 않을 일 |
| 기대 출력 | 파일/구조·단위·근거·한계·반환 결과 버전 |
| 수락 기준 | 무엇을 확인하면 완료인지, 부분 성공 처리 |
| 실패·재개 | 같은 요청 조회/재시도, 미지원·접근 실패·취소 처리 |
| 열린 문제 | 어떤 작업을 막는지, 해결/보류 책임 |
| 수신 상태 | 접수 / 보완 요청 / 수행 불가와 이유 |

전송 계약은 상대 프로젝트가 실제 지원하는 API/MCP 필드로 변환한다. 이 명세에 적힌 필드가 새 endpoint를 뜻하지 않는다. Atlas의 기존 instance·receipt·해시·오류·재개 계약을 보존한다. 프로토콜 응답 유실이면 원요청을 확인하고 새 작업을 임의 생성하지 않는다.

수신자의 접수는 수행 완료가 아니다. 수행 완료도 Pilot의 채택이 아니다. 입력이 바뀌면 기존 검토가 새 버전에 유효한지 영향 확인 후 새 의뢰 여부를 결정한다. 기존 요청 내용을 덮어쓰지 않는다.

### 인계 예시

- M1-1 → 실행 계층: 검증 질문, 고정 설계·측정·분석 명세, 준비 조건, 원자료 반환 형식. 장비 조건 미확인이면 실행 대신 수행 가능성 검토만 의뢰.
- M1-2 → 작성 프로젝트: 독자·기준일·구성안·절별 결론·주장–근거·비교 불가·금지할 과장 표현.
- M1-3 → 작성 프로젝트: 목표·선택안·추진 작업·자원 산정·가정·위험·검증 계획. 계획을 이미 달성한 성과로 쓰지 못하게 명시.

원문·원자료의 관리자는 전문 도구로 유지한다. Pilot은 채택 판단과 입력/결과 참조를 보존하고, 원문을 읽을 수 없는 경우 그 범위를 알린다. 별도 실행·작성 프로젝트 연결이 아직 없으면 전달 준비 상태로 남기며 접수됐다고 기록하지 않는다.
