# Atlas 파일 연계 검증 · 2026-09-12

[설계](../../superpowers/specs/2026-09-12-atlas-file-evidence-design.md)와 [사용법](atlas-file-evidence.md)에 따라 QA 입력·원본 보존·사용 판단·결정·후속 질문·UI를 확인했다.

## 확인한 흐름

- 실제 HTTP/CLI: 미리보기 무변경, 정확한 원본 해시, 같은 명령 재시도, HEAD 충돌, 허용된 요청 출처·형식, 과대·중첩 입력 거절.
- 핵심 기록: 버전 이력, 다른 QA의 중복 가능성 표시, 정확한 연구/기록 참조, 사용·보류 조건, 실제 공개 최종 제출만 협의 결정에 연결.
- 브라우저: 파일 가져오기 → 사용 판단 → 결정 → 질문 초안 저장. 잘못된 입력을 수정한 재시도, 통신 오류 시 고정 요청의 명시적 재확인, 과거 기록 저장 잠금.
- 화면: 1440/768/390 폭의 밝은/어두운 화면에서 열린 양식까지 확인. 페이지 오류와 가로 넘침 없음.
- 실제 연구: QA 1건 및 판단·결정·질문 각 1건이 서버와 화면에 표시됨. 이전 상태 필드 전체가 동일함을 확인. [등록 기록](../2026-09-10-polymer-sdl/atlas-review/registration.md)

브라우저 기능 시험에는 별도 synthetic 프로젝트를 사용했다. 실제 연구에서는 저장된 QA와 기존 조정자 결론만 등록했다. 이전 협업 원응답을 새 런타임 발언으로 만들지 않았으며 Atlas 질문은 보내지 않았다.

## 검증 범위의 경계

외부 근거를 M1의 종합·가설·완료 조건으로 전환하는 정책과 자동 CSV 수신기는 이번 범위가 아니다. 기존 화면의 기록 시점 선택과 API 조회는 동작하지만, 과거 시점 URL을 직접 새로 여는 문서 경로는 기존 서버의 query 제한이 남아 있다.
