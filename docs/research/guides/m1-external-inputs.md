# Atlas 근거로 종합·가설 초안 작성 · B2

B1에서 등록한 질문별 근거 묶음을 기존 M1 종합·가설·검토 노드의 입력으로 사용할 수 있다. 같은 연구 질문과 근거 묶음을 명시해서 연결한다.

## 입력 계약

기존 `research apply --operation m1.node.register` 명령을 사용한다. 공통 artifact 필드와 각 단계의 content 형식은 유지하고, 외부 경로에서는 input_refs를 아래처럼 구성한다. 각 값에는 조회 결과의 정확한 ref 객체 전체를 넣는다.

| 단계 | input_refs 키 |
| --- | --- |
| synthesize · 근거 종합 | questions, evidence_basis |
| hypothesize · 가설 | questions, evidence_basis, synthesize |
| review · 가설 검토 | questions, evidence_basis, synthesize, hypothesize |

`evidence_basis`를 넣으면 외부 경로를 명시한 것이다. 이때 screen·collect·extract를 섞어 넣지 않는다. 기존 자체 수집 경로의 입력 형식도 계속 지원하며 저장된 기록을 변환하지 않는다.

- questions: 묶음에 연결된 현재 Pilot 질문 개정.
- evidence_basis: 현재 입력을 사용하고 후속 개정으로 대체되지 않은 묶음.
- synthesize/hypothesize: 같은 질문·같은 묶음으로 작성한 현재 단계 개정.
- content의 evidence_refs/counterevidence_refs: 해당 묶음의 claims[].ref. QA 전체나 다른 묶음의 주장으로 대체할 수 없다.

주장의 의미와 허용 용도의 적합성은 에이전트 검토 대상이다. 구조 검사를 통과했다고 과학적 주장이 검증된 것은 아니다. 묶음·주장·사용 판단의 한계와 보류 용도는 가설 검토의 한계 목록으로 이어진다.

## 등록과 검토 완료

연구 질문의 검토가 끝나야 종합 초안을 등록할 수 있다. 종합·가설·검토 초안은 등록 후 각 단계에 실제 분야·방법·비판 역할의 협의를 연결한다. 독립 초기 의견 → 전원 공개 → 교차 검토 → 최종 판단이라는 기존 규칙을 유지한다. council 없이 등록만 한 노드는 검토 완료되지 않는다.

새 QA, 근거 묶음의 후속 버전 또는 질문 개정이 생기면 영향받는 현재 노드를 다시 검토해야 한다. 이전 답변·묶음·노드·대화는 보존되며, 변경 이유를 적은 새 노드 개정으로 이어간다.

## 이번 범위

B2는 입력 연결과 공통 검토 조건까지다. 실제 연구 에이전트 실행(B3), UI 작성 흐름(B4), 외부 경로의 실험 준비·인계 조건(B5), 현재 복합재 사례의 질문 추가와 적용(B6)은 별도다.

가설 검토가 완료돼도 전체 M1이나 실험 착수 준비가 완료된 것은 아니다. 기존 자체 수집의 corpus 승인, 수집·추출 완료 또는 M2 인계 기록은 생성하지 않는다. B2 구현 시점에는 현재 연구의 질문·쟁점·승인을 수정하지 않았다. 이후 실제 사례에서 질문·근거 묶음과 종합·비교 가설 초안을 등록하고 실제 협의까지 수행했다. 최종 review와 외부 인계 준비는 남아 있다. [최신 적용](../2026-09-10-polymer-sdl/atlas-review/synthesis-hypotheses.md). [현재 사례](../2026-09-10-polymer-sdl/atlas-review/case-application.md).

기존 자체 수집 자료가 모두 준비된 프로젝트에서도 외부 근거 경로를 기존 인계에 합치지 않는다. B5b에서 외부 근거용 명세와 실제 준비 증거 검증을 추가했다. 현재 준비 기록·독립 검증·최종 검토·자원·수신 조건을 충족해야 인계할 수 있다. [준비 증거와 M2 인계](m1-preparation-handoff.md)를 따른다.

## 검증 결과 · 2026-09-12

관련 Python 검사 65개와 기존 UI 검사 49개가 통과했다. 별도 시험 프로젝트에서 종합→가설→검토와 3단계 협의를 재현했다. 자체 수집 경로의 정상 동작, 외부 경로의 잘못된 인계 거절, 이전 기록 보존을 확인했다. 사용자 서버를 갱신했고 실제 연구 HEAD는 그대로다.
