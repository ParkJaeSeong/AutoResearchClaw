# 근거와 다음 행동으로 판단하는 재검토

사용자 합의(2026-09-15): 돌아간 횟수보다 무엇이 부족하며 다음에 무엇을 확인할지가 중요하다. 되돌림은 연구의 정상 흐름이고, 횟수 자체를 연구 중단이나 M1 인계 차단 사유로 사용하지 않는다.

## 조정자의 판단 순서

1. 부족한 내용을 구체적으로 적는다. 자료 부족, 가설의 문제, 같은 논의의 반복을 구분한다.
2. 영향을 받는 자료·판단과 이전 작업을 연결한다. 결과가 어떤 결정을 바꾸는지 적는다.
3. 다음 작업과 완료 기준을 정한다. 필요한 자료 탐색, 가설 수정, 설계 보완 중 해당 작업만 수행한다.
4. 확인되지 않았을 때의 처리를 정한다. 해당 용도 보류, 범위 축소, 추가 입력 대기를 구분하고 독립 작업은 계속한다.

같은 내용이라면 말만 바꿔 다시 요청하지 않는다. 새 근거 또는 달라진 접근이 무엇인지 먼저 판단한다. 입력이 바뀌었다는 사실만으로 과학적 가치가 있다고 단정하지 않는다. 비용·권한·실험 준비 조건은 별도로 확인한다.

## 현재 제공하는 기능

- `work.return_policy.set`: 현재 프로젝트의 정책을 명시적으로 변경하고 근거를 이력에 보존한다. 이전 한도와 실제 사용 횟수, 작업·승인·결론은 수정하지 않는다.
- `research assess-work`: 저장한 다음 작업 계획을 읽고 진행 조건을 평가한다. 작업을 실행하거나 승인·완료 기록을 만들지 않는다.
- 원장 평가: 새 정책에서 되돌림 횟수만으로 최종 인계를 차단하지 않는다. 실제 인계의 근거·준비·권한 조건은 계속 검사한다.
- UI: 준비와 인계에서 재검토 횟수와 현재 정책을 보여준다.

변경하지 않은 프로젝트와 과거 스냅샷은 기존 정책을 유지한다. 새 프로젝트도 현재 생성 명령 뒤에 아래 정책 명령을 명시적으로 적용한다. 기존 `max_returns` 숫자를 크게 올리거나 사용 기록을 지우는 방식은 쓰지 않는다.

## 정책 변경

`research apply`의 `--operation work.return_policy.set`에 다음 JSON 파일을 전달한다. 현재 HEAD와 재시도에 사용할 고정 command ID가 필요하다.

```json
{
  "mode": "evidence_driven",
  "rationale": "횟수 대신 부족한 근거와 다음 행동으로 판단한다.",
  "authorization_basis": "이 프로젝트에 대한 사용자의 실제 지시를 기록한다."
}
```

`authorization_basis`는 지시의 출처를 적은 선언이다. 실행 승인 영수증이나 과학적 검토로 사용하지 않는다.

## 다음 작업의 재검토 계획

기존 [다음 작업 입력 계약](../../superpowers/specs/research-governance/budget-inputs.md)의 필드에 `return_plan`을 추가한다. 새 정책에서 `resource_request.returns > 0`이면 필수다. `work.question`, `work.work`, `work.acceptance_rule`에 확인 질문·다음 행동·완료 기준을 적는다.

| 필드 | 내용 |
| --- | --- |
| `previous_work_ref` | 원장에 등록된 이전 작업의 정확한 참조 |
| `trigger` | `missing_evidence`, `hypothesis_problem`, `repeated_discussion` 중 하나 |
| `gap` | 무엇이 부족하거나 잘못됐는가 |
| `affected_refs` | 영향을 받는 현재 자료·판단 참조 목록. 중복 금지 |
| `decision_impact` | 확인 결과가 바꾸는 결정 |
| `evidence_needed` | 확인할 자료·관측·반론 |
| `if_unavailable` | 확인되지 않았을 때 보류할 용도, 줄일 범위 또는 기다릴 입력 |

```sh
.venv/bin/python -m researchclaw.codex.cli research assess-work PROJECT \
  --payload next-work.json --json
```

반환된 `ready`는 이 계획 평가의 결과다. 연구 단계 완료나 실제 실험 허가는 아니다. 평가와 사용한 계획 파일을 작업 회차에 연결하고, `reason_codes`가 있으면 그 항목의 다음 행동을 정한다.

## 검증 범위와 한계

자동 검사는 필수 내용, 현재 자료 참조, 이전 원장 작업, 동일 입력·질문·작업·완료 기준의 반복을 확인한다. 의미가 같은 다른 표현을 자동 판별하거나 적힌 계획의 과학적 타당성을 인증하지 않는다. 의미 중복 여부가 불확실하면 `semantic_status=uncertain`으로 평가하고 조정자가 대안을 검토한다.

현재 모든 노드 등록·협의 실행이 이 평가기에 자동 연결된 것은 아니다. 조정자가 재검토 전에 평가 명령을 호출하고 결과를 기록한다. 이 경계를 전체 자율 실행 엔진의 구현 완료로 설명하지 않는다. 기존 동일 작업의 정정·승인 계약, 검증 실행 자원, 비용, 실제 실험 권한은 유지한다.
