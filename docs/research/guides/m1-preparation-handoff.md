# 실험 준비 증거와 M2 인계

Pilot은 **준비 자료 확보 → 다른 담당자의 검증 → 준비 상태 갱신 → 최종 검토·자원 확인 → M2 인계·수신 확인** 순서로 실험 착수 조건을 확인한다. 자료를 저장한 사실과 그 자료를 검증한 판단은 각각 남긴다.

이 기능은 장비를 제어하거나 실제 실험을 시작하지 않는다. 수동 장비와 CSV 전달도 같은 절차를 사용한다. ResearchAtlas의 자료 수집·추출을 다시 수행하거나 자체 수집 승인으로 바꾸지 않는다.

## 1. 준비 자료 확보

`m1.preparation.evidence.capture`는 현재 최종 검토와 설계·데이터 이력 결정에 준비 자료를 연결한다. 담당자는 자료의 위치·버전·원문 바이트·SHA-256과 용도를 함께 제출한다. 현재 지원 범위는 UTF-8 문서·장비 확인 기록·데이터 명세·코드 환경 확인·권한 기록이다. 장비 API나 파일 자동 판독은 포함하지 않는다.

| 항목 | 확인할 내용 |
| --- | --- |
| 설계·분석 | 변수와 대조 조건, 분석법, 성공·중단 기준 |
| 데이터 이력 | 원자료 버전, 가공 과정, 시료·결과 추적 |
| 재료 | 재료 식별, 가용량, 사용 조건 |
| 제조 | 제조 과정, 장비, 작업자 |
| 측정 | 측정법·단위, 교정, 기록 방법 |
| 반복 | 반복 수, 독립성, 분석 방법 |
| 인력·자원·권한 | 필요한 권한, 작업자, 예산, 일정, 안전 |

실제 값이 없는 설계 초안이나 테스트용 가상 자료로 실제 준비를 확인했다고 기록하지 않는다. 적용하지 않는 항목도 단순 체크 해제가 아니라 해당 연구 범위에서 필요하지 않은 근거가 있어야 한다.

## 2. 다른 담당자의 검증

`m1.preparation.evidence.verify`는 자료를 제출한 담당자와 다른 활성 M1 검증 담당자가 수행한다. 검증자는 위 항목별 점검 결과, 원문에서 확인한 구절, 판단 이유와 확인·기각 결과를 제출한다. 확인 결과에는 모든 필수 점검의 통과가 필요하다. 미적용 판단에는 연구 범위상 제외 근거가 필요하다.

이는 등록된 역할과 발언을 연결하는 절차다. 로그인한 실제 사람의 신원이나 문서의 외부 진위를 자동 인증하는 기능은 아니다. 원문 해시도 바이트 변경 여부를 확인하며 문서 내용 자체의 진실성을 보장하지 않는다.

## 3. 준비 상태 갱신

기존 `m1.preparation.register`에서 일곱 항목의 상태와 검증 기록 참조를 제출한다. `verified`라는 문구만으로는 통과하지 않는다. 검증 기록이 정확한 항목·담당자·현재 검토·현재 결정·자료 버전에 연결돼 있어야 한다. 미확인 항목은 이유와 담당자를 남긴다.

화면은 준비 증거 확인과 설계 검토 상태를 따로 보여 준다. 이전 기록은 보존한다. 자료·결정·가설 검토가 바뀌면 현재 조건으로 다시 확인해야 한다. 가상 자료로 구성한 테스트 프로젝트는 실제 준비 완료를 얻지 않는다.

## 4. M2 인계와 수신 확인

`m1.handoff.issue`는 현재 연구 질문, Atlas 근거 묶음, 종합·가설·최종 검토, 준비 자료와 검증 기록을 하나의 변경 불가능한 인계 명세로 묶는다. 다섯 작업의 실제 검토 회차가 완료돼야 하며, 미해결 필수 문제와 자원 조건을 함께 평가한다.

실험으로 답할 수 있는 질문만 기존 의무·예산을 연결해 M2에 넘긴다. 측정 단위나 실행 권한처럼 실험 전에 알아야 할 문제를 실험 질문으로 바꾸지 않는다. 남은 이견도 명세에 보존한다.

이후 `m1.handoff.receiver.assign`으로 별도 M2 담당자를 지정하고 `m1.handoff.accept`로 수신 의무를 확인한다. 이관 쟁점은 기존의 검증 계획과 담당 변경 절차까지 완료해야 한다. 발행만으로 수신 완료나 실험 시작이 되지는 않는다. 인계 이후 전제가 바뀌면 현재 인계 조건은 다시 미충족이 될 수 있고, 당시의 인계 기록은 남는다.

기존 자체 수집 경로의 인계 기록은 그대로 읽는다. Atlas 경로에는 자체 수집 corpus나 그 승인을 대신 만들어 넣지 않는다.
