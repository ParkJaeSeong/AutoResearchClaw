# 15단계: 에이전트 협의를 통한 연구 방향 결정

> 아카이브: 이전 단계 구조 또는 철회한 제안의 개발 이력이다. 새 개발의 작업 지시로 사용하지 않는다. [현재 설계 정리](../../../../../../docs/superpowers/specs/2026-09-13-pilot-autonomous-research-design.md).

## 승인된 목적과 범위

14단계의 결과 해석을 다시 수행하지 않고, 등록된 분석과 남은 쟁점을
바탕으로 다음 행동을 결정한다. 연구적 판단은 Codex 에이전트들이
협의하며, 로컬 CLI는 근거 연결·등록 순서·기록 무결성과 상태를 관리한다.
외부 LLM API나 별도 모델 프로세스는 추가하지 않는다.

이번 구현은 결정과 후속 요청의 등록까지다. 실제 연구에서의 분석 품질
입증은 후속 평가 과제로 남긴다. 그러나 개발용 사례라는 이유로 근거가
부족한 결정을 자동 승인하거나 합성 결과를 실제 연구 성과로 바꾸지 않는다.

## 원본 계승과 의도적인 차이

확인한 포크 내 원본 구현은 pipeline/stage_impls/_analysis.py의
_execute_research_decision과 pipeline/stages.py의 DECISION_ROLLBACK이다.
PROCEED, REFINE, PIVOT이라는 판단 종류와 근거 기반 방향 결정은 계승한다.
일반 경로에서 REFINE은 13단계, PIVOT은 8단계 가설 생성으로 돌아간다.

원본의 LLM 미사용 시 기본 PROCEED, 반복 결과 정체에 따른 진행 유도,
횟수·점수에 의한 강제 진행, 자동 롤백·실험 재실행은 계승하지 않는다.
Codex판의 기존 승인, 실행 예산, 불변 증거를 다시 여는 작업은 별도 범위다.

대안은 결정과 실제 롤백을 함께 구현하는 것이다. 이는 기존 단계의 승인과
유효성 무효화, 새 실행 세션 및 이력 연결까지 필요하므로 이번에는 선택하지
않는다. 기존 협의·등록 패턴을 재사용하는 전용 모듈을 우선하며 범용 협의
프레임워크나 13단계 전체 구조 개편은 하지 않는다.

## 입력과 준비

- 시작 조건은 14단계 완료 및 현재 15단계다.
- 등록된 analysis/results.json, analysis/report.md, 세 검토와 상호 응답,
  14단계 evidence_packet 및 그 입력 근거를 검증하고 해시로 연결한다.
- 의사결정 패킷에는 다음 행동 판단에 필요한 등록 경로, 원래 가설·설계,
  선택 결과, 한계와 이견, 허용 출력 및 실행 금지 경계를 명시한다.
- 기존 분석의 완료 검증을 재사용한다. 작업용 결과 파일이나 보고서의
  비등록 사본을 정식 근거로 대체하지 않는다.
- 14단계의 패킷·보고서·검토·결과는 수정하거나 다시 등록하지 않는다.
  합성 출처, 미검증 사항과 당시의 제한된 결론을 유지한다.

## 짧은 협의 절차

1. domain, methodology, critical_reproducibility의 세 역할이 독립적으로
   진행·보완·방향 변경 중 권고를 작성한다. 14단계 자료는 공통 입력이지만
   이번 15단계 동료 초안은 세 권고가 모두 등록되기 전 공개하지 않는다.
2. 권고에는 선택 이유, 관련 근거, 허용 가능한 주장 범위, 반드시 필요한
   보완과 선택적 보완, 다른 선택을 하지 않는 이유를 적는다. 과거 분석을
   장문으로 반복하거나 새 수치·통계·문헌을 만들어 넣지 않는다.
3. 세 권고를 등록한 뒤 한 차례만 실제 상호 응답을 받는다. 각 역할은
   동료의 반론을 검토하고 최종 입장을 직접 밝힌다. 최초 기록은 보존한다.
4. 투표하지 않는 조정자가 협의 결과를 종합한다. 역할의 응답을 대신
   작성하거나 조정자 단독 판단을 공동 합의로 표시할 수 없다.
5. 코드가 다수결, 점수 임계값, 반복 횟수로 방향을 선택하지 않는다.
   협의된 방향과 남은 이견은 에이전트 작성 기록으로 명시한다. 방향 자체의
   합의가 없으면 결정 미완료를 기록하고 추가 지시를 기다린다. 이유에 대한
   차이는 같은 방향에 합의했더라도 삭제하지 않는다.

역할 분리와 독립 작성은 스킬의 오케스트레이션 의무다. 생산자 이름과
해시만으로 실제 독립성이나 과학적 타당성을 증명했다고 주장하지 않는다.

## 산출물과 명령 경계

전용 decision 명령 그룹으로 prepare, status, register-review,
register-rebuttals, register-result를 제공한다. 일반 stage validate가
이 절차를 우회해 15단계를 완료할 수 없어야 한다.

정식 작업 기록은 analysis/research-decision/ 아래의 evidence_packet.json,
reviews/{role}.json, rebuttals.json으로 구분하여 14단계 출력과 충돌하지 않는다.
입력용 초안은 같은 디렉터리의 submissions/ 아래로 명시적으로 허용한다.
정식 결정은 기존 단계 계약의 analysis/decision.json과 사람이 읽을
analysis/decision.md에 등록한다. 보고서는 검증된 구조화 기록에서
결정적으로 생성하며, 권고·실제 응답·남은 이견·후속 요청을 보존한다.

결정 기록은 프로젝트·패킷·검토·응답 해시, 협의 결과, 이유와 근거,
주장 가능한 범위, 필수/선택 후속 작업, 보류 사항과 이견을 포함한다.
연구 결정 값은 proceed/refine/pivot이며 협의 미완료는 decision=null과
disposition=unresolved로 표현한다. null을 proceed로 해석하지 않는다.
이 버전에서 정식 종합은 한 번만 등록하며 자동 재논의·기록 교체는 없다.

## 상태와 실행 권한

- PROCEED: 허용된 주장과 남은 한계를 보존해 15단계를 완료하고 16단계
  대기 상태로 이동한다. 16단계는 아직 미구현이며 논문 개요를 생성하지 않는다.
- REFINE: 필요한 보완과 권고 대상 13단계를 기록한다. decision 등록 상태는
  follow_up_required이며 current_stage는 15, 완료 단계는 14까지 유지한다.
- PIVOT: 방향 변경 이유와 권고 대상 8단계를 기록한다. REFINE과 마찬가지로
  15단계 follow_up_required에서 정지한다.
- 합의 미완료: 결정·이견 보고서를 등록하되 current_stage는 15이고
  needs_direction을 반환한다. 15단계 완료로 집계하지 않는다.
- 후속 요청은 실행 승인, 예산 증액, 기존 승인 재사용 또는 롤백 명령이 아니다.
  이번 버전은 REFINE/PIVOT/미합의 기록 이후의 재개·재논의 실행을 제공하지
  않는다. status/resume은 그 경계를 명시하고 동일 등록의 정확한 재시도만 허용한다.

현재 analysis status의 14단계 완료 기록은 계속 조회할 수 있게 한다.
15단계 이후에도 이전 분석의 무결성을 검증할 수 있도록 현재 단계 검사와
과거 완료 자료 검증을 구분한다. 사용자-facing status/resume은 현재 단계의
권위 있는 next_action을 안내하며, 과거 패킷에 적힌 대기 문구로 되돌리지 않는다.

## 오류·복구·검증

기존 트랜잭션과 안전한 경로·용량 제한·해시 검증을 재사용한다. 출력 경로는
쓰기 전에 검증하여 심볼릭 링크나 프로젝트 밖 쓰기를 거부한다.
등록 순서, 생산자 식별, 허용 근거와 해시를 검증하며 잘못된 입력은
기존 증거를 덮어쓰거나 다음 단계로 이동시키지 않는다.
동일 요청의 재시도는 멱등적이다. 파일 게시 후 상태 저장이 중단된 경우에도
유효한 동일 요청으로 복구하고, 충돌하는 바이트는 보존하며 거부한다.
결정 보고서와 구조화 결과가 모두 검증되기 전에 상태를 전진시키지 않는다.

## 인수 기준

- PROCEED, REFINE, PIVOT, 합의 미완료 각각의 등록과 정지 위치를 검증한다.
- 단계 우회, 조기 종합, 바뀐 근거, 허위 생산자 연결, 충돌 재등록,
  상태 저장 중단 복구, 경로 이탈, 기존 분석 훼손을 검증한다.
- 세 역할의 권고·실제 응답·남은 이견과 필수/선택 보완이 보고서에 남는다.
- 14단계 이후의 상태 안내와 과거 분석 조회에 회귀가 없어야 한다.
- 실제 에이전트 인수시험은 기존 14단계 완료 프로젝트의 새 복사본에서
  진행한다. 원본·실험·예산을 변경하지 않고 예상 결정을 미리 강요하지 않는다.
- 출처가 합성인 이번 시험은 흐름과 경계 검증이다. 실제 연구에서의 판단
  품질, 다양한 자료의 반증·보완 사례와 사용자 이해도 평가는 후속 과제다.
- 테스트 수정 후에는 변경 파일 전체와 관련 통합 검사를 실행한다.
  배포 전 전체 검사는 병렬 실행하고 통과·건너뜀·경고를 구분하여 기록한다.

## 이번에 제외하는 작업

실제 롤백, 새 실험·자료 수집, 외부 LLM API, 연구 예산 자동 증액,
16단계 논문 개요 구현, 보고서 전용 UI, 범용 다중 에이전트 프레임워크,
현재 사용자 프로젝트의 자동 진행은 포함하지 않는다.
