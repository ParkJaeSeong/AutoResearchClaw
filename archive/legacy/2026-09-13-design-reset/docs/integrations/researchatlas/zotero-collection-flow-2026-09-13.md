# Zotero 수집 흐름 — Atlas 공유

> 아카이브: 이전 단계 구조 또는 철회한 제안의 개발 이력이다. 새 개발의 작업 지시로 사용하지 않는다. [현재 설계 정리](../../../../../../docs/superpowers/specs/2026-09-13-pilot-autonomous-research-design.md).

상태: 이전 제안 — 사용자 결정으로 Zotero 경로 제외. 현행 방향은 [직접 수집 흐름](../../../../../../docs/integrations/researchatlas/direct-collection-flow-2026-09-13.md)을 따른다. 아래는 당시 공유 기록이다.

Pilot 담당입니다. 사용자 요청 “Zotero를 설치하는 동안 이 내용을 Atlas와 공유해줘”에 따라 현재 브레인스토밍 합의와 연계 검토사항을 전달합니다. 현재 진행 중인 업무를 중단하거나 즉시 구현/배포/연구 상태를 변경하라는 요청은 아닙니다.

목적: Pilot은 실험 계획을 잘 세우는 M1 자율 연구에 집중합니다. 자료 탐색·선정은 Pilot, 서지·원문 수집은 Zotero 활용, 문서 변환은 Documents, 지식 축적·분석·내용 검색은 Atlas로 나눕니다. 사용자는 Zotero를 설치 중이며 설치/연결 완료는 아직 확인하지 않았습니다.

사용자가 제안하고 수용한 기본 흐름:
1. Pilot이 연구 질문에 필요한 논문 검색·선정.
2. 논문 페이지를 브라우저로 열고 원문 접근 확인.
3. Zotero Connector로 로컬 Zotero에 서지와 확보 가능한 PDF 저장.
4. PDF와 서지를 읽기 쉬운 파일명으로 로컬 전달용 폴더에 내보내기.
5. PDF를 Documents에 전달해 Markdown으로 변환.
6. Markdown과 원문·서지를 연결해 Atlas 지식 구축.
7. Pilot이 Atlas에서 내용을 검색·질의하고 근거를 실험 계획에 활용.
외부 검색 전 Atlas/Zotero의 기존 자료를 확인해 중복 다운로드·변환을 줄입니다.

책임 분담 제안: 5–6의 Documents 호출은 Atlas가 조정합니다. Pilot이 Atlas에 원문+서지 전달 → Atlas가 Documents에 변환 요청 → Atlas가 변환 산출물 수신·축적. 사용자에게는 이 하위 도구 처리도 추적 가능해야 합니다. 기존 API/MCP 계약을 즉시 바꾸거나 이미 구현되었다고 간주하지 않습니다.

보존·연결 원칙: Zotero 내부 파일을 직접 이동/재명명하지 않고 별도 전달 사본을 내보내는 안입니다. 예: 연도_저자_짧은제목_항목키/ 아래 paper.pdf, bibliography.json, source.json (이 이름/스키마는 예시이며 미확정). 파일명은 표시용이고 library 식별자+item/attachment key+버전 및 파일 SHA-256으로 식별해야 합니다. 서지/원문 출처, Documents 변환 ID·버전, 표·이미지·원문 위치, 변환 누락·한계, Atlas source/extraction/result 참조의 연결이 필요합니다. 서지만 저장/원문 확보/변환 완료/분석 완료를 구분하고 실패 시 확보한 자료와 재개 지점을 보존합니다.

Pilot UI/기록 설계 맥락: 프로젝트 아래 실제 작업 회차 순서로 기록을 저장하되 연구 단계는 별도 필드로 관리합니다. 재탐색은 이전 판단과 이유를 연결한 새 작업입니다. UI는 최신 작업이 위에 쌓이는 카드 방식이며 요약→대화와 도구 호출을 실제 순서로 연결한 진행 과정→산출물을 보여줍니다. 구조화 기준 기록과 읽기용 Markdown을 함께 보관합니다. 따라서 Pilot 작업 ID와 Atlas job, Documents 하위 호출의 부모/자식 관계·목적·상태·결과·오류를 연결할 수 있어야 합니다. 정확한 필드 계약은 아직 설계 전입니다.

검증 전 경계: Connector 설치만으로 에이전트가 자동 저장할 수 있는 것은 아닙니다. 확장 프로그램 조작과 실제 PDF 확보를 작은 사례로 검증해야 합니다. 웹 API 서지 등록이 자동 PDF 탐색을 뜻하지 않습니다. 온라인 첨부 저장 300MB 제한을 피하기 위해 로컬 Zotero를 우선 검토하며 클라우드 PDF 동기화는 필수 전제가 아닙니다.

Atlas 관점에서 기존 Zotero/파일 입력 및 Documents 연계로 어느 범위까지 가능한지, 부족한 인터페이스·중복 방지·변환 재개·출처 연결 요구를 검토해 주세요. 당장은 공유 및 설계 의견 요청이며 구현 착수 승인이 아닙니다. 준비될 때 Atlas 문서 또는 담당 터미널 답변으로 알려주시면 Pilot 설계에 반영하겠습니다.
