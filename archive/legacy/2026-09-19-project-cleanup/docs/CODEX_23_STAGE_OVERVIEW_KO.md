# ResearchClaw-Codex 23단계 기능 개요

## 전체 단계

| 단계 | 기능 | 주요 작업 및 결과물 |
|---:|---|---|
| 1 | 연구 주제 초기화 | 사용자의 연구 목적과 범위를 정리하고 프로젝트를 생성한다. |
| 2 | 문제 분해 | 연구 주제를 세부 질문, 제약조건, 성공 기준으로 분해한다. |
| 3 | 검색 전략 수립 | 검색어, 데이터베이스, 수집 범위와 제외 기준을 설계한다. |
| 4 | 문헌 수집 | 관련 논문과 기술자료를 검색·수집하고 출처 정보를 기록한다. |
| 5 | 문헌 선별 | 관련성·품질·중복 여부를 평가해 사용할 문헌을 확정한다. |
| 6 | 지식 추출 | 문헌에서 주장, 방법, 데이터, 결과, 한계와 인용 근거를 추출한다. |
| 7 | 지식 종합 | 추출된 근거를 주제별로 통합하고 합의·충돌·연구 공백을 분석한다. |
| 8 | 가설 생성 | 검증 가능한 연구 가설과 후보 연구 방향을 도출한다. |
| 9 | 실험 설계 | 비교 대상, 데이터 분할, 지표, 성공·실패 기준과 재현성 계획을 설계한다. |
| 10 | 코드 생성 | 승인된 설계를 실행 가능한 실험 코드, 설정, 자체 테스트와 패키지 계약으로 구현하고 정적으로 검증한다. |
| 11 | 자원 계획 | 필요한 데이터, CPU·GPU, 메모리, 저장공간, 실행시간과 비용을 산정한다. |
| 12 | 실험 실행 | 자체 테스트와 사용자 승인을 거쳐 실험을 실행하고 결과를 불변 근거로 등록한다. |
| 13 | 반복 개선 | 결과를 바탕으로 실험 코드·설정·조건을 수정하고 재실행해 성능을 개선한다. |
| 14 | 결과 분석 | 지표, 통계적 검정, 비교 결과, 실패 사례와 불확실성을 분석한다. |
| 15 | 연구 의사결정 | 근거를 바탕으로 `PROCEED`, `REFINE`, `PIVOT` 중 다음 연구 방향을 결정한다. |
| 16 | 논문 개요 작성 | 논문의 논리 구조와 절·항별 주장, 근거, 표·그림 배치를 설계한다. |
| 17 | 논문 초안 작성 | 제목, 초록, 서론, 방법, 결과, 논의, 결론과 참고문헌 초안을 작성한다. |
| 18 | 동료 심사 | 복수의 심사 관점에서 타당성, 독창성, 근거성, 재현성과 표현을 검토한다. |
| 19 | 논문 수정 | 심사 의견을 반영해 논문을 수정하고 의견별 대응 내역을 작성한다. |
| 20 | 품질 게이트 | 연구·논문·인용·재현성 품질이 정해진 기준을 충족하는지 최종 판정한다. |
| 21 | 지식 보관 | 연구 과정, 결정 기록, 근거, 코드, 결과와 재현 패키지를 보관한다. |
| 22 | 최종 내보내기 | 최종 논문, 코드, 데이터 설명서와 부속 자료를 제출 형식으로 패키징한다. |
| 23 | 인용 검증 | 모든 인용과 참고문헌의 실재성·서지정보·본문 연결을 확인하고 의심 항목을 표시한다. |

## 단계 그룹

- 1~2단계: 연구 범위 설정
- 3~6단계: 문헌 탐색과 근거 추출
- 7~8단계: 지식 종합과 가설 생성
- 9~11단계: 실험 설계, 코드 생성과 자원 계획
- 12~13단계: 실험 실행과 반복 개선
- 14~15단계: 결과 분석과 연구 의사결정
- 16~19단계: 논문 작성, 심사와 수정
- 20~23단계: 품질검사, 보관, 최종 산출물과 인용 검증

## 현재 Codex 포크의 구현 상태

- 구현·검증 완료: 1~12단계와 제한된 Stage 13 개선 오케스트레이션
- 현재 워크플로 상태: 유효한 연구 결과를 등록하면 Stage 13으로 진입하며, 사용자가 명시적으로 개선을 요청한 경우에만 3인 평가단 절차를 시작한다.
- 향후 구현 대상: 14~23단계
- 설치 안정화 완료: `uv tool` 환경에서 설치형 CLI, 자체 테스트와 실행 계약이 동일한 환경 지문을 사용한다.

단계 수 기준 진척도는 `13/23`, 약 57%다. Stage 13에서는 조정자(투표권 없음), 독립 평가자 3명, 구현 담당자(투표권 없음)를 사용한다. 세 평가가 모두 등록되기 전에는 서로의 의견을 공개하지 않고, 한 번의 이의제기·수정 라운드 뒤에만 2:1 결정을 등록한다. 모든 실행·자체 테스트·결과 등록·최종화는 CLI가 반환한 인자와 사용자의 명시적 확인을 따른다. 기준선은 바이트 단위로 보존하고, 후보 근거는 전용 refinement manifest 이름공간에만 기록한다. 외부 LLM 제공자 설정, API 키, API 호출과 네트워크 호출은 허용하지 않는다.

## 10단계 코드 생성의 권장 에이전트 구조

10단계는 설명문이나 의사코드가 아니라 실제로 실행 가능한 실험 코드를 만드는 단계다. 프로젝트별 코드 구현에는 별도의 코딩 에이전트를 사용하는 구조가 적합하다.

1. 메인 ResearchClaw 에이전트가 승인된 9단계 설계를 해석하고 작업 지시서를 만든다.
2. 코드 생성 에이전트가 격리된 작업공간에서 자체 테스트를 먼저 작성하고 실험 코드와 설정을 구현한다.
3. 검증 에이전트가 설계 준수, 데이터 누출, 지표 계산, 재현성과 실행 안전성을 검토한다.
4. 메인 에이전트가 검토 결과와 산출물을 정리해 사용자에게 제시한다.

권한 경계는 다음과 같이 유지한다.

- 10단계: 코드 작성, 정적 검증과 제한된 자체 테스트
- 11단계: 실행 자원과 시간 검토
- 12단계: 사용자의 명시적 승인 후 본 실험 실행
