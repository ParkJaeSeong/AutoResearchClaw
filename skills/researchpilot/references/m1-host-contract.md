# M1 호스트 배정 기록 계약

M1 엔진은 호스트가 생성한 작업을 기록한다. Python CLI가 LLM 또는 에이전트 프로세스를 새로 실행하지 않는다. 조정자와 작성자는 판단 역할의 자기 승인을 대신하지 못한다.

| 상태 | 의미 |
|---|---|
| `host_observed` | 조정자가 호스트 배정 도구에서 해당 작업 식별자와 결과를 직접 관측했다. |
| `declared_only` | 호출자가 배정·실행 정보를 선언했지만 현재 호스트 관측과 연결하지 못했다. |
| `unavailable` | 식별자 또는 필요한 배정 정보를 얻을 수 없다. |

호스트 관측은 과학적 독립성 인증, 모델 다양성 인증, 서명된 감사 로그를 의미하지 않는다. 선언된 ID만으로 `host_observed`로 승격하지 않는다. 역할명과 작업 식별자는 별도 필드다.

## 최초 제출과 응답

1. 작성자와 별개로 domain, methodology, critical_reproducibility 작업을 배정한다.
2. 각 최초 입력에 동일한 자료 버전과 가설 버전, 역할별 질문을 넣는다. 타인의 최초 제출은 넣지 않는다. 입력 목록을 보존한다.
3. 세 최초 제출이 모두 도착한 뒤 하나의 동결된 라운드 문맥을 만든다. 원문 또는 조정자 요약 중 무엇을 전달했는지 기록한다.
4. 모두에게 동일한 문맥을 전달한다. 먼저 도착한 후속 응답을 같은 라운드의 다른 판단자에게 섞지 않는다.
5. 재개 가능 여부를 실제 결과로 기록한다. 새 작업으로 대체하면 이전 작업, 새 작업, 전달 문맥과 대체 이유를 함께 남긴다.
6. 슬롯 제한 때문에 순차 배정해도 독립 최초 입력의 조건은 유지한다.

## 보존 필드

`schema_version`, `host_support`(task_id, separate_initial_inputs, resume_assignment), `verification_scope`, `observed_assignments`, `limitations`를 보존한다. 배정에는 `host_task_id`, `role`, `provenance_status`, 최초/응답 입력 참조, 실제 제출·응답을 넣는다. 실제 제공되지 않은 UUID, 타임스탬프, 서명은 만들지 않는다.

`content_origin: synthetic`는 자료의 출처이며 호스트 실행 관측 여부와 독립적이다. 합성 자료로 실제 에이전트를 실행할 수 있지만 실제 연구나 M1 완료로 표시하지 않는다. 개별 판단자의 ready는 엔진의 쟁점 해소·사용자 승인·handoff 검사를 대체하지 않는다.

2026-09-08 검증에서는 세 별도 작업과 동일 작업 재개를 관측했다. 새 엔진 등록은 아직 구현되지 않아 `engine_registered: false`로 기록했다.
