# 질문 중심 수집·자료 보완

목표는 모든 PDF 확보가 아니라 가설·실험 계획의 선택을 설명할 근거 확보다. 어떤 질문을 위해 자료가 필요하고 답이 달라지면 어떤 판단이 바뀌는지 먼저 정한다.

사용자의 탐색 요청과 프로젝트의 도구·네트워크·비용 범위를 먼저 확인한다. 로컬 자료만 사용하도록 한 연구는 외부 검색으로 확장하지 않는다. 단순히 스킬을 호출했다는 이유로 별도 계정·유료 접근·무관한 프로젝트 자료 사용 권한이 생기는 것은 아니다.

1. Atlas 보유 자료와 정확한 버전을 확인하고, 부족한 근거를 외부에서 검색·선정한다.
2. 서지·출처를 먼저 기록하고 접근 가능한 PDF·웹 본문·보충자료를 확보한다. Zotero·Connector는 Pilot 필수/기본 도구 구성에서 제외돼 있다. 사용자 기기의 앱과 자료를 삭제하라는 의미는 아니다.
3. 자료 ID와 제목·저자·연도·DOI 등 확인한 서지, 원문 주소·확보 시각·버전·파일 해시를 연결한다. DOI가 없는 자료는 확인 가능한 다른 식별자를 사용하고 DOI를 만들지 않는다. 파일명은 표시용이며 중복·버전 판별의 유일한 기준으로 사용하지 않는다.
4. 미확보 자료는 공개 원문·저자 저장소·대체 문헌을 확인한다. 같은 경로를 새 이유 없이 반복하지 않는다. 실패 경로와 확보한 부분을 보존하고, 핵심 공백만 사용자 보완 또는 대체 설계 검토로 넘긴다.
5. 확보한 자료와 질문을 Atlas에 전달해 분석을 요청한다. Atlas가 Documents 변환을 조정하는 방향이지만 실제 지원 여부를 확인한다. 없는 하위 호출 기록을 만들지 않는다. 변환 파일·원문 위치·누락·한계와 Atlas 결과를 연결한다.
6. 분야·방법 검토자가 특정 용도에 사용할 수 있는지 판단한다. 탐색 담당은 확보·공백을 보고하고 조정자는 후속 작업과 이유를 정한다. 다운로드 성공이나 논문 개수만으로 연구 단계를 완료하지 않는다.

서로 다른 세 상태를 기록한다: **확보 상태 / 실제 읽고 분석한 범위 / 용도별 사용 판단**. PDF 없이 웹 본문을 읽을 수도 있고 PDF가 있어도 분석 전일 수 있다. 변환 실패는 원문에 해당 내용이 없다는 뜻이 아니다.

## 사람이 제공한 파일·주소

기존 미확보 자료의 보완인지 새 후보인지 구분하고, 서지·버전·파일 중복을 확인한다. 대상이 불명확하면 사용자에게 연결 대상을 확인한다. 사용자 제공 사실과 입력 버전을 보존한다. 주소 입력은 본문 확보 완료가 아니다.

기존 질문과 자료에 연결해 지원되는 접수·변환·분석부터 재개한다. 이전 실패·판단 기록은 보존한다. 새 자료가 바꾸는 판단만 재검토하며, 의존하지 않는 작업은 허용 범위에서 계속한다. 사용자가 파일을 제공한 일을 에이전트의 자율 수집 성공으로 표시하지 않는다. UI 업로드 기능이 없으면 제공된 로컬 파일과 지원되는 CLI/API 경로를 사용하고, 새 UI가 있다고 안내하지 않는다.
